# 원본 발췌·청취 검증 Extension 개선 보고

- 목적: 승인된 E2·E3 실행 절차 개선, 실제 검증, Core 문서화와 남은 영상 검수를 보고한다.
- 읽는 시점: 다음 편집에서 개선된 절차를 적용하거나 이번 session-close의 범위·커밋·한계를 확인할 때.
- 책임: Creator 유지보수 에이전트가 공통 절차를 유지하고, 각 job 담당자가 실제 원본·결과물·사용자 검수를 수행한다.
- 상태: 2026-10-22 KST 승인된 Extension 절차 개선·검증·정리 완료. 보고 문서는 프로젝트 내부에 보존한다.
- 관련 권위: 최신 사용자 지시와 session-close, Creator 정책, Core 작업·단계·문서·버전 관리·파일 정리·규칙 거버넌스 및 기존 영상 workflow 계약.

## 승인 범위와 소유권

대상은 Creator main이다. 사용자는 Core 작업을 제외한 Extension 개선을 진행하고 Core 개선 내용은 문서로 보고하라고 지시했다. 이는 E2·E3 실행 절차 보강과 로컬 단계 커밋·전용 임시 설계 정리·내부 보고의 범위로 적용했다. Core 수정·gitlink 갱신·설치·push·온라인 게시·실제 영상 재편집은 실행하지 않았다.

E1의 공통 저장 원칙은 Core 개선 후보로 정정했다. 구체적인 하위 경로는 Consumer·Extension의 책임이다. 제안은 [Core 산출물 저장 원칙 제안서](CORE_ARTIFACT_STORAGE_PROPOSAL_2026-10-22.md)에 보존했다. Maintainer 구현·일반화 검증·독립 반례 감사는 하지 않았다.

## 개선 전후

### E2 원본 발췌 요청의 실행 순서

기존 규칙은 exact 원본·최신 지시·anchor·누적 피드백 보존을 이미 요구했지만, 이번 대화에서는 원본 멘트를 요청한 사용자 교정을 새 멘트 작성으로 잘못 처리했다. 기존 기능이 없는 것이 아니라 적용 순서가 실행에서 빠진 문제다.

[입력·지시 규칙](../../rules/video-editing-intake-and-instructions.md)의 R02와 [영상 workflow 계약](../domain/youtube/VIDEO_EDITING_WORKFLOW_CONTRACT.md)의 시작 계약에 다음 순서를 연결했다.

1. 새 대사 작성과 원본 발췌를 구분하고 전체 원본·현재 편집본 중 최신 지정 범위를 적용한다.
2. 제안 전에 실제 대사·source 좌표·확인 방법을 찾고 불확실한 부분을 만들어 채우지 않는다.
3. 선택 대사를 기존 scene anchor의 observation·audio/both 범위로 연결한다.
4. 교정은 기존 record-feedback과 resolution으로 이어받고 옛 review를 재사용하지 않는다.
5. 전달 전 결과의 필수 대사·영상 보존을 원본 근거와 대조한다.

신규 대사 작성 요청에는 원본 발췌를 강제하지 않는다. 새 schema·별도 발췌 정본·validator를 추가하지 않았다. 기존 anchor·feedback 기능을 실제 요청 처리에 연결하는 절차 보강이다.

### E3 자동 사전검수와 직접 청취·완료 보고

기존 규칙과 review-preflight-v2는 자동 관찰을 의미 검수 passed로 승격시키지 않는다. 이번 아웃트로도 direct_listening=not_run으로 기록됐다. 그러나 발화 품질을 요구한 사용자에게 최종적으로 무엇이 남았는지 전달 과정에서 더 명확히 대조할 필요가 있었다.

[검증·전달 규칙](../../rules/video-editing-validation-and-delivery.md)의 R18과 같은 workflow의 완료 정의에 실행·보고 표를 보강했다.

- 디코딩·길이·프레임 통과는 기술 결과로 보고한다.
- ASR·RMS·source 연결 확인은 자동 사전검수 결과로 보고한다.
- 정지 frame 관찰과 실제 연속 재생을 구분한다.
- 발화 품질 요청에 직접 청취가 없으면 ‘직접 청취: not_run / 최종 발화 품질: 미검증’을 명시한다.
- MP4 후보 전달도 최종 품질 확인이나 사용자 승인으로 간주하지 않는다. XML은 기존 후보·검수 완료 writer 경계를 유지한다.
- 기술 검사만 요청받은 경우 관련 없는 전체 편집 검수를 추가하지 않는다.

새 자동 승인·청취 판정기·schema 변경은 없다. 절차 보강으로 앞으로 누락을 줄이는 것이 목적이며, 실제 에이전트 행동의 재발률이나 영상 품질 개선 효과를 실측한 것은 아니다.

## 실제 검증

| 검사 | 결과와 범위 |
|---|---|
| test_video_editing_editorial_state.py | 기존 회귀 19개 pass. anchor 누락·부분 삭제·역전, 피드백 누락·stale review, 원본 mismatch, 미확정 source 등록 등을 검사 |
| test_video_editing_review_delivery.py | 기존 회귀 7개 pass. 후보 상태 보존, 완료 경로 차단, 필수 preflight, source drift·기존 결과물 보존 등을 검사 |
| ASR 관찰 상태 대조 | 메모리상의 합성 입력에서 speech recorded 후보는 허용, speech passed 승격은 거부, semantic not_run은 보존됨을 확인 |
| E2 수동 문맥 대조 | 전체 원본으로 교정·새 대사 작성·source 시간 미확정·필수 피드백 해소 누락 네 경우를 변경 절차와 대조 |
| E3 수동 문맥 대조 | ASR-only 후보·실제 검수 근거가 있는 경우·기술 검사만 요청한 경우를 허용 보고 수준과 대조 |
| 문서·Git 검사 | diff 공백, 새 보고서 링크·필수 설명, 단계별 snapshot 경로·내용, Core 무변경과 최종 예상 상태 확인 |

회귀는 Python -B, PYTHONPATH=extension/src;extension/tests 조건으로 실행했다. 기본 샌드박스 임시 위치의 권한 및 원자 파일 생성이 차단된 뒤, 프로젝트 내부의 작업 전용 test temp와 승인된 권한 실행으로 같은 기존 회귀를 통과했다. 제품 코드를 환경 제약에 맞춰 완화하지 않았다. 합성 source 파일은 테스트 전용이며 실제 미디어 검증으로 주장하지 않는다.

수동 문맥 대조는 이 에이전트의 검토다. 독립 Agent 재현이나 새 세션 행동 검증이 아니다. route는 바꾸지 않아 새 route 의미 재현은 비해당이며, 실제 원본·완성 영상의 직접 청취·연속 재생, Premiere 재생, 사용자 승인, 성과 측정은 not_run이다.

최종 보고·Core 제안·유지보수 상태는 이 문서를 추가하는 별도 보고 커밋이 소유한다. 자기 커밋 식별자를 문서에 자기복제하지 않고 Git 이력으로 조회한다. push·이력 squash/reset은 하지 않았다.

임시 설계는 Git 이력으로 보존되며 최종 활성 트리에서 제거했다. 작업 전용 테스트 디렉터리는 빈 상태를 확인한 뒤 비재귀 방식으로 제거했다. 기존 설계·사용자 미디어·다른 작업 자료는 정리하지 않았다.

## 보고서 위치와 남은 영상 작업

이번 Core 제안서와 공통 개선 보고서는 Creator 내부 extension/docs/reports에 저장한다. 기존 영상별 재검토 자료는 해당 job의 work/reports에 유지하고 최신 결정·공통 보고서를 가리키게 한다. Git 제외 job 근거는 same-workspace이고 독립 clone에서 복원된다고 주장하지 않는다.

앞선 검색에서는 비보호 텍스트 253개에서 외부 보고서 참조 두 건을 확인했다. 두 외부 파일은 현재 없었고 기존 보고서의 내부 본문 해시는 복원 기록과 일치했다. 이번에 외부 자료를 추가 이동·삭제할 필요는 없었다. 검색 제외 영역과 PC 전체까지 외부 보고서 부재를 보장하지 않는다.

실제 TRYALLGAME 아웃트로의 직접 청취는 여전히 남아 있다. 사용자가 요청한 이번 작업은 Extension 개선과 Core 문서 보고이므로, 이 보고서 작성이나 회귀 통과를 영상 청취 완료로 바꾸지 않는다. 그 영상의 품질 확인은 해당 job에서 실제 검수 범위를 확정하고 수행해야 한다.

## 최종 처분

E2·E3는 승인된 범위에서 기존 실행 절차를 보강하고 검증했다. E1은 사용자 요청대로 Core 개선 제안서만 만들었으며 구현은 제외했다. 이번 작업의 임시 설계 정리와 내부 보고를 마쳤고, Core 및 Git 원격 변경은 없다. 실제 영상 직접 청취·Core Maintainer 구현은 이번 개선 완료에 포함하지 않는다.
