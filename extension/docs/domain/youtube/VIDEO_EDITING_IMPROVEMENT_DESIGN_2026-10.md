## 1. 꼭 필요한 개선

### N1. VM 전달 경로와 R04의 충돌 해소 (규칙 + 도구) — v2 그대로

- 사실: R04는 원본을 mandatory lock으로 잠그지 못하는 platform에서 **fail closed**를 요구하고, `delivery.py`의 잠금은 Windows 전용이다. 그런데 백룸과 도깨비 두 영상 모두 Cowork VM(Linux)에서 작업했고, XML·렌더를 작업별 우회 스크립트(전후 전체 hash·size·mtime + O_EXCL)로 만들었다. 즉 현재 모든 VM 산출물이 활성 규칙을 어긴 상태이고, 우회 스크립트는 회귀 테스트가 없다.
- 왜 필요: 독립 영상 2건에서 반복(승격 gate 1 충족), 다음 영상도 VM에서 하면 그대로 반복된다. 규칙과 실제가 어긋난 상태는 다음 세션이 "안 된다"고 잘못 판단하는 원인이 됐다(도깨비 세션에서 실제 발생). r8~r18에서도 18개 revision 모두 같은 우회(xml_split.py pre/gen/post)로 만들었다.
- 변경:
  1. R04 행동·검증에 "mandatory lock이 없는 platform은 생성 전 전체 sha256·size·mtime 기록 → gate 실행·O_EXCL 쓰기 → 생성 후 전체 재해시로 대체할 수 있고, 불일치면 출력 사용 금지·결함으로 보고"를 예외로 추가.
  2. `video_editing` writer/CLI에 이 모드를 공식 구현하고 호출 시간 제한(180초) 때문에 `pre / gen / post` 단계로 나눠 실행할 수 있게 한다. 기존 Windows 경로는 그대로.
  3. 회귀: 단계 사이 원본 변경, 출력 이미 존재, gate 실패, 스냅샷 파일 위조 각각에서 XML·임시 파일 0개 또는 post 단계 실패 보고.
- 승인 필요: R04 문안, extension 코드 변경.

### N2. 말 실수 검사를 자동 전사만으로 통과시키지 않기 (규칙 최소 보강) — v2, 사례 번호만 수정

- 사실: 전체 r2를 "말 실수 다듬음"으로 넘겼지만 '거의 바람의낸… 바람의 나라'가 남았다. 긴 구간 자동 전사가 거짓 시작을 지워 버려(전사에 '바람의낸'이 없음) 텍스트 대조로는 찾을 수 없었다. 사용자가 직접 찾아야 했다.
- 기존 규칙: R08은 "더듬기·고쳐 말하기는 가장 완결된 표현 하나만"과 "정상 속도로 듣고 확인"을 요구하지만, 에이전트는 청취를 못 하고 R18은 그 대체 확인을 정하지 않는다. → 기존 owner(R08)의 검증과 재현 사례만 최소 보강.
- 변경:
  1. R08 검증에 한 문장: "청취를 하지 않은 사전검수는 긴 구간 자동 전사의 무결함을 근거로 쓰지 않고, 남긴 발화를 클립 단위로 다시 받아써 인접 반복·접두(거짓 시작)·단어 안 숨은 무음·추임새 후보를 확인하며, 다듬은 컷은 앞뒤를 이어 다시 받아써 확인하고 제거 목록을 사용자에게 보고한다."
  2. 재현 사례 **TC34**: "자동 전사에 거짓 시작이 보이지 않음 → 전사 무결을 통과 근거로 쓰지 않고 후보 검사·컷 후 재전사로 확인한다."
- 도구화는 하지 않는다(§2 CAND14). body/reasr.py·detect.py·verify_cuts.py는 참고 구현.
- 승인 필요: R08 문안.

### N3. 무음 판정과 "무음이 적다"는 진단은 실제 소리로 한다 (규칙 최소 보강)

- 사실: r9(gaps_r9.py·edges_r9.py)와 r10(gaps_r10.py)은 large-v3-turbo 단어 시각 사이 간격으로 무음을 찾았다. 단어 시각이 앞뒤 무음을 흡수해서 단어 "안"에 묻힌 무음과 클립 앞 여백을 놓쳤고, 상태 문서에 "무음은 생각보다 적다, 지루함의 주원인은 말 속도 → 배속이 해결책"이라고 기록했다. 사용자가 "무음이 다 살아 있다"고 지적한 뒤 RMS(음성 대역 250~3500Hz, 10ms)로 다시 찾자 r12에서 270곳·약 133초가 빠졌다(r11 63,529 → r12 55,389프레임). 잘못된 진단이 배속 시도(N4)와 사용자 불만 2회로 이어졌다.
- 기존 규칙: R08은 ASR을 시간 탐색 보조로만 쓰라고 하지만 무음 판정 근거는 정하지 않는다. R09는 남긴 무발화의 기능을 묻지만 무발화를 어떻게 찾는지는 정하지 않는다. CAND01(영상별 luma·RMS calibration)은 기준값 문제만 다룬다. → 기존 owner(R09)에 최소 보강.
- 변경:
  1. R09 검증에 한 문장: "무발화·말 사이 간격의 검출과 '줄일 무음이 적다'는 판단은 ASR 단어 시각이 아니라 음성 대역 에너지(RMS 등) 같은 실제 소리 측정으로 하고, 사용한 기준값과 검출 건수·총 길이를 사전검수 요약에 남긴다. ASR 단어 시각은 무음을 포함할 수 있어 무음이 없다는 근거로 쓰지 않는다."
  2. 재현 사례 **TC35**: "단어 시각 간격으로 무음을 찾았더니 줄일 곳이 거의 없음 → 실제 소리로 다시 측정하기 전에는 '말 속도가 원인'이라고 결론 내리지 않는다."
  3. CAND01에 이번 기준값을 근거로 기록: 임계값 = min(하위10%+10dB, 상위10%−14dB), 말 사이 ≥0.3초 → 0.16초, 클립 앞 ≥0.25초 → 첫소리 0.12초 전, 클립 끝 ≥0.3초 → 끝소리 0.15초 뒤, 0.25초 미만 조각이 남는 컷은 건너뜀. 다른 영상에서 같은 값이 통하는지 확인되기 전까지 전역 기본값으로 쓰지 않는다.
- 승인 필요: R09 문안.

### N4. 편집 앱이 읽는 것만 산출물에 넣는다 (규칙 최소 보강 + CAND08 근거)

- 사실: r10에서 XML에 Time Remap 배속을 넣은 x115 파일을 만들었으나 Premiere CS6가 모든 클립에서 "Time Remap 효과가 변환되지 않았습니다"로 무시했다. 중첩 시퀀스 115% + 오디오 피치 유지는 목소리가 이상해 사용자가 거부했다. 반대로 확대(Basic Motion)는 사용자가 CS6에서 내보낸 XML의 구조를 그대로 따라 한 번에 적용됐다(r16, zoom_xml.py).
- 기존 규칙: R03은 산출물 형식을 계약하지만 그 형식 안에서 어떤 효과가 실제로 전달되는지는 정하지 않는다. CAND08(Premiere 버전별 호환 profile)은 "실제 import 근거 없음"으로 보류 중이었다 → 이제 실제 근거 2건이 생겼다.
- 변경:
  1. R03(또는 전달 규칙) 행동에 한 문장: "대상 편집 앱에서 import가 확인되지 않은 효과·속성(속도, 마스크, 키프레임 등)은 산출물에 넣기 전에 사용자 앱이 내보낸 같은 효과의 XML로 구조를 확인하거나 짧은 샘플로 import를 확인하고, 확인 전에는 해결책으로 제안하지 않는다."
  2. 재현 사례 **TC36**: "XML에 배속을 넣으면 해결될 것 같음 → CS6 Time Remap은 import되지 않는다. 확인된 효과 목록 밖이면 샘플 import부터."
  3. CAND08을 근거와 함께 갱신하고, `extension/docs/domain/youtube/`에 **CS6 XML 효과 호환표**를 둔다: Time Remap ✗(2026-10-10 실제 import), Basic Motion scale·center ✓(사용자 export 구조, 2026-10-11 적용), 음성 배속 + 피치 유지는 앱 기능은 되지만 음질 거부(사용자 판단, 말소리에는 배속을 쓰지 않음).
  4. 확대를 writer 기능으로 넣을지는 후편집에서 두 번째로 쓰일 때 판단(지금은 zoom_xml.py 후처리를 참고 구현으로 둔다).
- 승인 필요: R03 문안, 호환표 신설.

## 2. 규칙은 있지만 도구가 없어 반복된 것 (도구 보강)

### N5. 무음 일괄 컷에 첫소리·끝소리 검사를 묶는다 (도구)

- 사실: r12 무음 컷(클립 앞 115곳 포함) 뒤 '유도하려는'의 '유'가 잘렸다(사용자 발견). 같은 검사(onset_r16.py)를 돌리자 '아 세 줄', '아 거의 다'도 같은 문제였고, 애매한 4곳(4464.82·4727.82·9738.45·12152.27)은 판단 보류로 남았다. r11 제우스 예시 컷이 '편했거든요'의 '요'를 먹은 것도 사용자가 찾았다. r9 때도 클립 앞 여백 압축이 '기본적으로·게임안에' 첫소리를 잘라 그 방식을 버렸다.
- 기존 규칙: R08(약한 말끝 판정, 첫 음절 handle), R17(일괄 연산 전후 발화 경계 대조), TC20·TC22가 이미 요구 → 규칙 변경 없음.
- 변경(도구): 무음 컷 스크립트가 컷을 확정하기 전에 각 컷의 양 끝에서
  1. 컷 직후 0.15초 안에 약한 음성 에너지(강한 발화 기준보다 낮은 별도 기준)가 시작되는지 → 첫소리 의심,
  2. 컷 직전 0.15초 안에 약한 에너지가 남아 있는지 → 말끝 의심
  을 검사하고, 의심 컷은 경계를 다음 무음 쪽으로 물리거나 "청취 필요 목록"으로 보고서에 따로 낸다. 구현은 silcuts·onset_r16의 통합이며, `video_editing` 패키지가 아니라 작업 도구(CAND14와 같은 층)로 둔다.
- 검증: 이번 도깨비 사례 3건('유', '요', '아 세 줄')을 fixture로 넣어 모두 의심으로 잡히는지.
- 승인 필요: 없음(작업 도구). 패키지에 넣으려면 CAND14와 함께 승격 gate.

### N6. 바뀐 경계의 화면 상태를 에이전트가 직접 본다 (도구)
