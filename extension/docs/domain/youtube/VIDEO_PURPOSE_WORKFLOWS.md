# 목적별 영상 제작 경로

목적: 반복 제작의 자료 선택·구성·검수 차이를 연결한다. 제작을 시작하거나 목적이 바뀔 때 해당 경로만 읽는다. 책임은 제작 Agent이며 창작 방향과 보호 자료의 사용 범위는 사용자가 정한다. 상태: active. 공통 보장은 기존 영상 편집 규칙, 스타일 기본값은 VIDEO_EDITING_PROFILES.md가 소유한다.

## 목적과 실제 입력으로 선택

| 목적 | 진행 순서와 판단 | 연결할 기존 기능 |
|---|---|---|
| 게임 개발기 | 만들려던 경험 → 실제 시도·실패 → 내린 판단 → 확인된 변화. 당시 자료와 현재 결과, 구현과 계획을 구분한다 | 대본은 write-video-script. 녹화 발췌는 edit-gameplay-video. 별도 음성에 여러 자료를 맞추는 작업은 아래 합성 경로 |
| 플레이 경험 중심 리뷰 | 원본 플레이의 목표·행동·반응·결과를 확인하고 맥락을 보존하며 압축한다. 진행 없는 반복부터 줄인다 | 기존 edit-gameplay-video의 분석·컷·검수. 별도 해설이 필요한 부분만 대본 기능 연결 |
| 평가 중심 게임 리뷰 | 평가 질문·조건 → 직접 관찰한 플레이 근거 → 장단점·판단을 연결한다. 버전·플레이 조건, 사실·경험·의견을 구분한다 | write-video-script + 근거 플레이 발췌 + 필요한 합성. 검색·추가 녹화는 자료가 부족한 범위에서 선택 |

명칭보다 실제 입력을 따른다. 같은 개발기도 촬영된 원본만 자를 수 있고, 플레이 리뷰도 별도 나레이션과 비교 화면을 합성할 수 있다. 혼합 영상은 필요한 블록에 각각의 방식을 적용한다. 부분 자막·국소 수정은 해당 단계로 바로 들어가며 TTS·XML·업로드를 자동 추가하지 않는다.

## 대본·음성과 여러 자료를 조합할 때

1. 기존 job의 최신 대본·음성·장면 계획·자료 목록과 보존 범위를 재사용한다. 자료 목록 확인, 정지 이미지 관찰, 동작 재생 확인을 구분한다. 부족한 내용이나 충돌하는 버전을 집중 조사하며 지정된 범위 밖을 자동 수집하지 않는다.
2. 장면 계획 하나에서 발화 구간, 실제 자료와 당시 단계(초기/실패/수정/확정), 보여줄 기능, 선택한 연출, 변경·보존 범위를 연결한다. 기존 계획에 필요한 항목만 보강하고 같은 정보를 별도 표·문서로 복제하지 않는다. 메타데이터의 이름만으로 내용이 맞다고 판단하지 않는다.
3. 설명과 자료의 대상·시기·상태를 실제로 대조한다. 초기 자료가 없으면 미확인으로 남기거나 출처가 구분되는 대체 설명을 선택한다. 결과 예고는 예고임을 알 수 있게 하며 최종 그림을 최초 실패처럼 소개하지 않는다. 관절 규칙·코드 작성과 모델 가중치 학습을 혼동하지 않는다.
4. 도구의 지원 범위를 먼저 확인한다. 기존 컷 렌더러는 단일 CFR 원본 중심이다. 다중 PNG/GIF/영상·별도 음성 합성을 지원한다고 간주하지 않는다. 필요한 합성 adapter와 실제 검증 범위를 선택한다. 작업용 생성기의 고정 job 경로·과거 상태 문구를 다음 영상의 실행 정본으로 복사하지 않는다.
5. 새 배치·효과가 불확실하면 핵심 위험이 보이는 짧은 샘플에서 등장 중·정착 후·읽는 동안을 확인한다. 효과·빈도·컷 길이는 목적에 맞게 판단한다. 검증된 스타일과 유효한 기존 근거는 재사용하며 이미 위임된 선택을 장면별 승인으로 바꾸지 않는다. 읽어야 할 내용과 원본 동작을 효과가 방해하지 않는지 확인한다.
6. 변경 영향에 맞춰 검사한다. 화면만 바꾸고 음성·자막이 잠겨 있으면 동일성 검사로 보존을 확인하고 TTS·ASR을 반복하지 않는다. 자료·타이밍·연출을 바꾸면 해당 연결과 같은 원인의 영향 범위를 대조한다. 최종 정상속도 시청·청취를 자동 검사로 대체하지 않으며 미실행은 그대로 보고한다.

## 재개와 공용 도구

입력·설정·렌더 구현이 같은 구간만 재사용한다. `extension/src/video_scene_cache.py`의 `render_cached_scene`은 자료·overlay·렌더 코드의 해시와 설정을 묶고, cache의 무결성과 입력 변경을 확인하는 공용 실행 부품이다. 합성기 자체나 장면 의미 판정기는 아니다. 호출자는 승인된 exact 입력과 실제 renderer 의존 파일, frame/timebase·효과 설정, 실제 출력 검증 함수를 전달하고 기존 job runner 잠금 아래 실행한다.

기존 원본을 수정하지 않고 새 revision으로 결과를 만든다. 현재 상태는 최신 결과·잠긴 항목·검수 수준·다음 행동의 단일 안내로 유지하고 과거 과정은 기존 검증 자료를 참조한다. 과거 중간물에 의존하면 이를 입력으로 명시하며 누락 시 실행 전에 알린다.

## 적용 확인

- 같은 목적에 서로 다른 입력(촬영 원본/별도 해설)을 주어 필요한 경로로 분기되는지 본다.
- 초기 설명에 최종 자료를 연결한 장면을 내용 검수에서 찾아내고, 의도된 결과 예고는 허용하는지 본다.
- 한 장면의 자료·효과만 바꾸면 해당 cache가 갱신되고 다른 구간과 잠긴 음성·자막은 유지되는지 본다.
- 출처 목록 확인을 동작 관찰로 보고하거나 기술 검사 통과를 전체 시청·사용자 승인으로 올리지 않는지 본다.

문서에 항목이 존재하는지 검사하는 것과 실제 제작 행동 평가, 합성 fixture와 실제 영상 검증은 구분한다. 이 안내는 모든 영상의 고정 길이·효과 수·글자 크기·새 승인 단계를 만들지 않는다.
