# 영상 편집 스토리·컷 설계 규칙

- 목적: 사건 후보를 완성 컷으로 오인하지 않고 인과·상태·공간 기능을 보존한 실제 2차 편집을 만든다.
- 읽는 시점: 사건 후보를 선택하고, 구성 순서를 정하거나 후보 내부를 분할·압축할 때.
- 책임: 영상 편집 작업 에이전트가 구성·컷 판정과 근거를 유지하고 사용자가 창작 방향을 승인한다.
- 상태: 활성 소비 도메인 규칙.
- 관련 권위: `extension/docs/domain/youtube/VIDEO_EDITING_WORKFLOW_CONTRACT.md`가 작업 층과 완료 gate를 소유한다.

### R05 — 분석·구성·2차 편집 분리

- 조건: 사건 후보나 이야기 블록의 범위가 정해졌다.
- 행동: 후보를 바로 최종 clip으로 확정하지 않고, 방향을 고정하지 않은 1차 내용 지도와 방향 확정 뒤의 2차 상세 분석을 분리한다. 2차 분석은 각 후보에 source anchor, 기능, 유지·축소·제외 이유, 예상 위험을 붙인 뒤 1차 구성 편집과 정보·행동·반응·화면 상태·발화 절 단위의 2차 편집을 수행한다. 사용자에게 승인된 편집 문법의 exact evidence owner·artifact ID·editorial fingerprint·source manifest·승인 결정이 없거나 직전 교정이 문법을 무효화했으면 `calibration.required=true`로 두고 전체 분량으로 확장하지 않으며, 서로 다른 핵심 위험을 포함하는 가장 작은 연속 calibration에서 그 문법을 먼저 증명한다. 이 exact reference가 모두 유효할 때만 calibration을 `not_required`로 둘 수 있다. 화면·원본 오디오·자막·보조 음성 인식의 근거를 구분하고, 보조 인식만으로 정확한 대사나 고유명사를 확정하지 않는다.
- 예외: 후보 전체가 하나의 사건 타격점이나 끊을 수 없는 연속 체험이면 유지 이유를 기록하고 한 clip으로 둘 수 있다.
- 검증: 각 후보가 `미검수 / 2차 편집 완료` 중 하나로 명시되고, retained clip마다 정확히 하나의 microbeat 결정과 source anchor·기능·유지 이유가 실제 화면·오디오 변화에 대응하는지 확인한다. 전체 확장 전에는 actual calibration의 기술 통과와 사용자 방향 승인이 분리돼 있으며, `required=true`인데 승인 reference가 없거나 `not_required`인데 exact 승인 reference가 없는 확장은 0건인지 확인한다. 불확실한 화면 사건·대사·오디오 원인은 사실로 승격하지 않는다.

### R06 — 스파인·인과·상태·공간 연결

- 조건: 압축이나 삭제가 원인, 목표, 시도, 결과, 공간 이동, 감정 상태 변화를 건드린다.
- 행동: 스파인에 한 문장 메시지, 도입 질문·약속, 결말의 답, 보조 메시지, 말하지 않을 주장, 장·블록의 기능을 먼저 고정한다. 각 사건은 `상황 / 원인·발견 / 행동·시도 / 결과 / 다음 상태`의 의존 관계와 반드시 남길 anchor를 source 기준으로 가진다. retained clip은 정확히 하나의 microbeat와 하나의 event가 소유하며, 한 split edit의 연결된 video/audio clip도 각 clip ID와 source 범위를 그 동일한 사건·microbeat의 exact clip set에 기록한다. event dependency는 최종 timeline에서 실제 선행 event를 가리키며 제거된 microbeat는 retained clip을 소유할 수 없다. 반응·도주·규칙 이해·대사 결과는 그 원인 anchor 없이 단독으로 남기지 않고, 공간 전환은 찾기·접근·진입·도착 중 이해에 필요한 최소 연결을 유지한다. 본편은 원본의 원인·시도·결과 순서를 보존하며, 무발화 화면·침묵·환경음도 공간·상태·긴장 기능이 있으면 기능으로 판정한다. 원본에 없는 적·추격·감정을 만들기 위해 음악·효과음·화면 효과를 추가하지 않는다. 남긴 발화가 지시어·대답·호응·정정처럼 앞 발화나 화면을 전제하면 그 전제 대상을 최종 timeline에서 먼저 남기거나 그 발화를 제외하며, 영상과 각 장의 첫 발화는 앞 맥락 없이 이해돼야 한다. 장소·단계·주제가 바뀌는 지점은 편집 전에 원본 전체에서 목록화하고, 최종 timeline에서 각 전환을 시청자가 알아챌 수 있도록 출발·도착 중 최소 연결과 변화 표지를 남긴다.
- 예외: 같은 기능이 인접 컷에서 이미 명확하거나 생략 자체가 의도된 연출이면 줄일 수 있다. 사용자가 별도 창작 효과를 명시적으로 승인한 경우에도 원본 사실과 추가 처리를 구분해 기록한다. 도입부에서 뒤 장면을 미리 보여주는 경우는 원본 순서의 명시적 예외로 기록하고 같은 source 범위의 재사용을 허용하되, 본편에서 그 장면은 원인 맥락과 함께 다시 나오고 미리보기는 결말을 누설하지 않는다. 뒤에서 회수할 의도된 궁금증은 회수 위치를 기록할 때만 전제 대상 없이 남기며, 스파인이 의도적으로 생략한 전환은 생략 이유를 기록한다.
- 검증: v2 event와 microbeat가 실제 video/audio clip ID, source 범위, 최종 timeline 순서와 선행 event를 가리키는지 양방향 대조해 retained clip의 미소유·중복 소유·제거 microbeat 소유가 각각 0개인지 확인한다. 그 뒤 완성 타임라인만 순차 재생해 모든 반응과 결과에 선행 원인 anchor가 있으며 `왜 / 어디서 / 무엇이 바뀌었는가`에 답할 수 있는지 확인한다. timeline 좌표가 revision마다 달라져도 회귀할 수 있도록 결함은 source anchor나 사건 ID에 연결하고, 추가 처리가 원본 사실을 과장하거나 오인시키지 않는지 확인한다. 최종 timeline 전사만 순서대로 읽어 모든 발화의 지시 대상을 찾을 수 있는지, 원본 전환 목록의 각 항목이 최종 timeline에 연결됐거나 생략 이유를 갖는지 표로 대조한다.

### R07 — microbeat 분할과 긴 컷

- 조건: 설명·설정·UI·탐색·반복 행동이 하나의 긴 후보 범위에 들어 있다.
- 행동: 새 정보, 행동 한 박자, 반응, 화면 상태 변화, 자연스러운 발화 절에서 분할하고 중복·대기를 제거한다. 분석 단계의 시간 범위는 후보 anchor로만 사용하며, 후보 전체를 rough block으로 배치한 상태를 2차 편집 완료로 간주하지 않는다. 최종 인·아웃은 실제 60fps 화면·발화·숨·게임음 꼬리를 함께 들으며 정한다. 고정 컷 길이나 단일 영상의 사용 비율을 전역 기준으로 만들지 않는다. 촬영·제작 환경, 장비, 진행 준비, 주변 사정처럼 영상 주제·사건·인물과 무관한 발화는 웃음·인물 성격·정보·뒤 사건의 원인 중 하나의 기능이 없으면 제외한다.
- 예외: 사건·감정 누적·공간 체험·타격점은 필요한 만큼 길게 유지할 수 있지만, `끊을 수 없는 기능`과 내부 microbeat 감사 결과를 기록한다. 단지 인과를 잃을까 우려된다는 이유만으로 긴 source block 전체를 유지하지 않고 anchor 사이를 다시 편집한다. 고정 컷 길이를 강제하지 않는다. 그 사정이 뒤 사건의 원인이거나 영상 형식 자체가 제작 과정을 보여주면 곁가지 발화를 유지할 수 있다.
- 검증: 모든 긴 clip에 분할 감사와 구체적인 유지 이유가 있고, 분할 이유 또는 유지 이유가 화면·오디오의 실제 변화와 대응하는지 확인한다. `인과 보존`만을 이유로 내부 감사 없이 유지된 rough block은 0개다. 제외한 곁가지 발화가 뒤 장면 이해에 필요하지 않았는지 확인한다.

### R09 — 반복 압축과 첫 맥락 보존

- 조건: 같은 감정·도주·사망·탐색·설명이 반복된다.
- 행동: 이미 전달된 반응과 진행 없는 반복부터 줄이고, 새 상황의 첫 반응·새 실패·새 학습·회수는 유지한다. 사용자 피드백은 `positive lock / defect / untouched`로 나누고, 다음 revision은 exact protected baseline owner와 editorial fingerprint를 참조해 positive lock과 untouched 범위를 보존하면서 defect만 delta로 바꾼다. self-reported preserved 표지나 fingerprint 문자열만으로 기준본을 대신하지 않는다. 발화·화면 정보 변화·의미 있는 행동이 모두 없는 구간은 기본 제거 후보로 두고, 유지할 때는 공간 파악·등장이나 변화 대기·긴장·여운·결과 확인 중 구간별 기능을 기록하고 실제 화면으로 확인한다. 뒤 반응을 키우는 정적·회복·공간 호흡은 이 기능에 포함된다. 침묵 길이·RMS 피크·실패 횟수 같은 수치만으로 제거나 유지를 판정하지 않는다.
- 예외: 반복 자체가 누적 공포·코미디·클라이맥스의 기능이면 길어질 수 있다. 편집 프로필이 정적 분위기 자체를 영상 목적으로 정했으면 무발화 구간의 기본값은 그 프로필을 따른다.
- 검증: 삭제 전후로 새 정보와 감정 변화 목록을 비교하고, 없어진 기능이 반복 정보뿐인지 확인한다. exact baseline artifact와 새 revision의 실제 event·microbeat·clip diff에서 positive lock 손실과 untouched 변경이 각각 0개이며, 불가피한 변경은 사용자에게 영향과 대안을 먼저 보고했는지 확인한다. 남긴 무발화 구간마다 기능과 화면 근거가 기록돼 있는지 확인한다.
