# 영상 편집 스토리·컷 설계 규칙

- Purpose: 사건 후보를 완성 컷으로 오인하지 않고 인과·상태·공간 기능을 보존한 실제 2차 편집을 만든다.
- Read when: 사건 후보를 선택하고, 구성 순서를 정하거나 후보 내부를 분할·압축할 때.
- Authority: `extension/docs/domain/youtube/VIDEO_EDITING_WORKFLOW_CONTRACT.md`가 작업 층과 완료 gate를 소유한다.

### R05 — 분석·구성·2차 편집 분리

- 조건: 사건 후보나 이야기 블록의 범위가 정해졌다.
- 행동: 후보를 바로 최종 clip으로 확정하지 않고, 방향을 고정하지 않은 1차 내용 지도와 방향 확정 뒤의 2차 상세 분석을 분리한다. 2차 분석은 각 후보에 source anchor, 기능, 유지·축소·제외 이유, 예상 위험을 붙인 뒤 1차 구성 편집과 정보·행동·반응·화면 상태·발화 절 단위의 2차 편집을 수행한다. 화면·원본 오디오·자막·보조 음성 인식의 근거를 구분하고, 보조 인식만으로 정확한 대사나 고유명사를 확정하지 않는다.
- 예외: 후보 전체가 하나의 사건 타격점이나 끊을 수 없는 연속 체험이면 유지 이유를 기록하고 한 clip으로 둘 수 있다.
- 검증: 각 후보가 `미검수 / 2차 편집 완료` 중 하나로 명시되고, source anchor·기능·유지 이유가 실제 화면·오디오 변화와 대응하는지 확인한다. 불확실한 화면 사건·대사·오디오 원인은 사실로 승격하지 않는다.

### R06 — 스파인·인과·상태·공간 연결

- 조건: 압축이나 삭제가 원인, 목표, 시도, 결과, 공간 이동, 감정 상태 변화를 건드린다.
- 행동: 스파인에 한 문장 메시지, 도입 질문·약속, 결말의 답, 보조 메시지, 말하지 않을 주장, 장·블록의 기능을 먼저 고정하고, 시청자가 다음 장면의 위치·행동·반응을 이해하는 최소 연결을 유지한다. 본편은 원본의 원인·시도·결과 순서를 보존하며, 무발화 화면·침묵·환경음도 공간·상태·긴장 기능이 있으면 기능으로 판정한다. 원본에 없는 적·추격·감정을 만들기 위해 음악·효과음·화면 효과를 추가하지 않는다.
- 예외: 같은 기능이 인접 컷에서 이미 명확하거나 생략 자체가 의도된 연출이면 줄일 수 있다. 사용자가 별도 창작 효과를 명시적으로 승인한 경우에도 원본 사실과 추가 처리를 구분해 기록한다.
- 검증: 완성 타임라인만 순차 재생해 `왜 / 어디서 / 무엇이 바뀌었는가`에 답할 수 있고, 추가 처리가 원본 사실을 과장하거나 오인시키지 않는지 확인한다.

### R07 — microbeat 분할과 긴 컷

- 조건: 설명·설정·UI·탐색·반복 행동이 하나의 긴 후보 범위에 들어 있다.
- 행동: 새 정보, 행동 한 박자, 반응, 화면 상태 변화, 자연스러운 발화 절에서 분할하고 중복·대기를 제거한다. 분석 단계의 시간 범위는 후보 anchor로만 사용하며, 최종 인·아웃은 실제 60fps 화면·발화·숨·게임음 꼬리를 함께 들으며 정한다. 고정 컷 길이나 단일 영상의 사용 비율을 전역 기준으로 만들지 않는다.
- 예외: 사건·감정 누적·공간 체험·타격점은 필요한 만큼 길게 유지한다. 고정 컷 길이를 강제하지 않는다.
- 검증: 분할 이유 또는 유지 이유가 화면·오디오의 실제 변화와 대응하는지 확인한다.

### R09 — 반복 압축과 첫 맥락 보존

- 조건: 같은 감정·도주·사망·탐색·설명이 반복된다.
- 행동: 이미 전달된 반응과 진행 없는 반복부터 줄이고, 새 상황의 첫 반응·새 실패·새 학습·회수는 유지한다. 침묵의 길이, RMS 피크, 사망 횟수만으로 저가치라고 판정하지 않고 뒤 반응을 키우는 정적·회복·공간 호흡인지 확인한다.
- 예외: 반복 자체가 누적 공포·코미디·클라이맥스의 기능이면 길어질 수 있다.
- 검증: 삭제 전후로 새 정보와 감정 변화 목록을 비교하고, 없어진 기능이 반복 정보뿐인지 확인한다.
