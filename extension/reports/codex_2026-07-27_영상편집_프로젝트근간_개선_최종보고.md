## 5. 의도적으로 자동화하지 않은 것

다음 판단은 단일 영상의 수치나 불안정한 proxy로 자동 차단하지 않았다.

- 밝기 luma 전역 임계값
- RMS·발화 앞뒤 여유 전역 임계값
- 고정 컷 길이와 제거율
- 공간 이동의 고정 컷 개수
- 반복 사건 길이의 강제 단조 감소
- 스파인 의미의 자동 합격
- 공포·안도·코미디 리듬의 자동 합격

이 항목들은 실제 영상별 calibration과 순차 재생 검수가 필요하다. 숫자는 진단 보조이지 의미 판단의 대체물이 아니다.

## 8. 한계

- 실제 보호 영상이나 사용자 XML에는 접근하지 않았다.
- 실제 Premiere 가져오기·재생 검수는 수행하지 않았다.
- 따라서 adapter는 합성 구조 acceptance까지 검증됐으며, 첫 실제 작업에서는 사용자가 지정한 exact 원본과 출력 목적을 승인받은 뒤 Premiere import 결과를 별도 확인해야 한다.
- 의미 gate는 에이전트의 순차 재생 감사 결과를 기록하는 장치다. 영상 의미를 코드가 자동 판정한다고 주장하지 않는다.

## 9. 작업 복기

### 잘한 판단

- 원문을 운영 문서로 축약 복사하지 않고 실패 조건을 12개 규칙으로 재구성했다.
- 코드보다 규칙 replay를 먼저 통과시켰다.
- validator를 구조 오류로 제한해 의미 판단의 오탐을 막았다.
- 사용자가 반복해서 요구한 원본 계보와 XML 단일 산출물을 실제 코드 경계로 만들었다.
- 각 단계의 exact scope만 스테이징하고 성공 gate 뒤에만 커밋했다.

### 처음 계획에서 줄인 것

- C01~C17 전체 validator
- 고정 luma·RMS·컷 길이 기준
- 채널 프로필
- 새 skill
- 중간 분석 배열의 장기 보존
- 원문을 활성 owner로 유지하는 방식

### 남은 위험

- 실제 Premiere 버전별 XML 해석 차이는 합성 XML만으로 완전히 검증할 수 없다.
- 의미 gate의 품질은 스파인과 완성 타임라인을 실제로 순차 검수하는 에이전트 수행에 달려 있다.
- 첫 실제 영상에서 schema가 표현하지 못하는 transition·multi-source 요구가 나오면 현재 범위를 조용히 확장하지 말고 새 계약으로 판단해야 한다.

### 다음 작업에서 확인할 가설

1. 네 작업 층을 분리하면 통파일 중심 편집이 재발하지 않는가.
2. replay 규칙만으로 사용자 지적 전에 발화·인과·공간 결함을 발견하는가.
3. original source lineage와 산출물 예산이 불필요한 파일 생성을 막는가.
4. 한 source timeline schema가 실제 gameplay 편집에 충분한가.
5. 두 번째 영상에서도 반복되는 판단만 새 자동화 후보로 남는가.
