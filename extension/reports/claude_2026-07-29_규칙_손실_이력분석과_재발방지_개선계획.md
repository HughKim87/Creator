`direct remeasurement`

2. **규칙 예산.** `PROJECT_RULES.md` 1,000단어 상한. 초과 시 추가하려면 기존 조항을 제거해야 한다. 붕괴형 리셋을 점진 압축으로 대체한다.
3. **재작성 금지 조항.** 활성 규칙 파일을 0에서 다시 쓰지 않고 diff로만 변경한다. 이 한 줄이 2·3·4 사이클의 손실을 방지했을 것이다.
4. **폐기 게이트.** `rule-governance.md`의 controlled closeout 4분류에 5번째를 추가한다 — "매칭됐으나 어떤 행동도 바꾸지 않음 → 후보로 강등". 현재는 강화 방향만 있고 축소 방향이 없다.

### 성공 게이트

- A·B 완료 후 코퍼스 총 단어 수가 19,519 대비 증가하지 않을 것.
- `PROJECT_RULES.md`가 1,000단어 이하일 것.
- 불변식 인벤토리 테스트가 통과하고, 항목 하나를 의도적으로 제거하면 실패할 것(음성 대조).
- 기존 `core/tests/`·`extension/tests/` 회귀 전부 통과.
- 승인된 core 검증 게이트 통과.

### 미해결 위험

- 4절(3연속 실패 동작 반전)의 의도 여부가 미확정이다. 사용자 판정 전에는 A단계에서 다루지 않는다.
- 불변식 인벤토리를 정규식 문자열 매칭으로 구현하면 문구를 바꿀 때 취약해진다. 의미 단위 식별자와 대표 문구 다중 후보 방식이 필요하다.
- `core/docs/` 6,219단어의 적정성은 이번 분석 범위 밖이다. 별도 판단이 필요하다.

## 8. 교차검증 대상

다른 에이전트가 재현·반박해야 할 항목을 명시한다.

| 검증 항목 | 현재 라벨 | 요청 |
|---|---|---|
| 팽창·붕괴 6사이클 수치 | `direct remeasurement` | 동일 명령으로 재측정 |
| 8건 손실 (매칭 0건) | `direct remeasurement` | 다른 정규식·다른 표현으로 재검색해 오탐 여부 확인 |
| 검증 등급 사다리 활성 owner 부재 | `direct remeasurement` | 반례 탐색 |
| 3연속 실패 동작 반전의 의도 여부 | `reported / unverified` | 사용자 확인 필요 |
| failures 통합이 정상 압축이라는 판정 | `direct remeasurement` (표본 1건) | 나머지 6개 통합 파일로 표본 확대 |
| 개선안 A의 owner 배치 적절성 | 미검증 제안 | `rule-governance.md` 배치 규칙 대조 |

`shared-source agreement` 주의: 이 문서와 직전 대화의 분석은 동일 근거를 사용하므로 독립 확증이 아니다. 교차검증은 저장소 원본에서 직접 재측정해야 한다.

## 9. 다음 실행 가능한 행동

1. 사용자가 4절(3연속 실패 반전)의 의도 여부를 판정한다.
2. 사용자가 단계 A·B·C 중 실행 범위와 core 변경을 승인한다.
3. 승인 후 C-1(불변식 인벤토리 테스트)을 먼저 구현한다. 방지 장치 없이 복구부터 하면 복구분이 다음 사이클에서 재손실될 수 있다.
4. C-1 통과 후 A·B를 하나의 논리 체크포인트로 실행하고 성공 게이트를 검증한다.
