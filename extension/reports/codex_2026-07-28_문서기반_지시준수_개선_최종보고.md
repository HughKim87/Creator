## 1. 최초 목적과 최종 판정

채팅 기억이나 에이전트의 즉석 해석보다 프로젝트 문서가 최신 사용자 지시·상태 owner·승인 경계·다음 행동을 안정적으로 복구하도록 구조를 바꿨다. AGENTS·CLAUDE는 PROJECT_RULES 포인터만 남았고, PROJECT_RULES가 startup·작업 분류·worktree별 상태 선택·조건부 rule routing을 단독 소유한다.

main은 `SESSION_HANDOFF.md`, ainotebook은 `extension/work/AINOTEBOOK_WORKTREE_STATE.md` 하나를 선택한다. 사용자 교정 후 기존 plan을 계속 실행하거나 다른 세션의 미커밋 변경을 recovery·승인 없이 restore하는 경로는 규칙과 자동 회귀로 차단했다.

첫 G1 maintenance는 ainotebook 전용 경로를 main의 Markdown link로 표현해 실패했다. 조건부 코드 경로로 수정한 뒤 동일 gate가 통과했다. ainotebook sandbox 검증은 runtime cache 읽기 권한으로 중단됐고, 권한 있는 동일 명령에서 전체 통과했다. G5 최종 Extension 재검증의 첫 실행은 표준 `PYTHONPATH`가 빠져 6개 test module import에서 중단됐고, README와 core change control이 정한 경로를 설정한 동일 게이트에서 113개가 통과했다.

Repository 상태·commit·경로·테스트 수·SHA-256은 이번 세션의 `direct remeasurement`다. ainotebook 영상 작업의 기존 내용은 전용 상태 문서에서 이전한 `reported / unverified` 상태로 유지했으며 이번 구조 개선의 완료 근거로 계산하지 않았다.

## 5. 미실행 검증과 남은 사용자 gate

- 선택 항목 I-15 독립 세션 eval은 실행하지 않았다.
- 보호 데이터와 영상 산출물은 현재 개선 범위가 아니므로 열거나 재검증하지 않았다.
- push·publish·외부 저장은 수행하지 않았다.
- ainotebook의 기존 영상 작업은 전용 상태 문서에 기록된 사용자 승인 gate를 그대로 유지한다.

## 6. 복구하지 못한 정보

이전 세션에서 restore된 6개 파일의 정확한 byte diff는 Git backup이 없어 복구할 수 없다. 사용자 지시·세션 기록·현재 문서에서 요구 의미를 재구성했고, 최종 구조와 부정 회귀로 검증했다. 재구성 자료를 backup으로 부르지 않는다.

## 7. 프로젝트 목적·구조 적합성

플랫폼 진입점, 상시 정책과 router, 조건부 core rule, extension 작업 데이터, worktree별 현재 상태가 분리됐다. 새 장문 규칙이나 새 스킬을 만들지 않고 기존 owner를 강화했으며, 보호 데이터와 외부 효과 없이 문서 기반 자율 실행과 안전한 복구 가능성을 높였다.

## 8. 자체 복기

기존 실패의 직접 원인은 네 가지였다.

1. AGENTS가 플랫폼 진입점과 프로젝트 router를 동시에 소유했다.
2. 첨부 대화의 에이전트 답변을 사용자 지시와 분리하지 않았다.
3. 사용자가 의도 오해를 교정한 뒤에도 기존 plan과 mutation을 무효화하지 않았다.
4. 다른 세션의 미커밋 변경을 exact diff·recovery·승인 없이 restore했다.

이번 개선은 최신 사용자 지시를 목표·금지·owner·승인 경계로 고정하고, 각 단계의 mutation 전·후 성공 gate와 자동 부정 회귀로 같은 실패를 차단한다.

## 9. 다음 세션의 첫 행동

repository root를 확인하고 PROJECT_RULES가 선택한 상태 문서 하나만 읽는다. main에는 이 개선의 미완료 구현이 없으며 새 사용자 요청을 확인한다. ainotebook에서는 전용 상태 문서의 사용자 승인 대기 작업부터 재개한다.
