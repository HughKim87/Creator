## 2. 사용자 의도와 범위 해석

이번 작업은 ignored 파일만 추적하거나 문서 몇 개만 정리하는 작업이 아니었다. `inputs/**`만 분석에서 제외하고 프로젝트 내부의 tracked·untracked·ignored 파일, 백룸 작업 산출물, 개선 과정 자료, `extension/outputs/**`, runtime, cache, local state, 과거 보고·설계를 모두 감사하는 작업이었다.

완료 상태는 단순한 `git status clean`보다 넓다.

1. 남은 tracked 파일은 현재 owner·실행·검증 역할이 있다.
2. 남은 ignored 파일은 보호 current output 또는 검증된 local runtime으로 설명된다.
3. 재사용 지식은 한 canonical owner에 있고, 삭제 파일 자체를 읽어야만 다음 작업을 수행하지 않는다.
4. 삭제 자료는 사용자 지시에 따른 Git 복구점에서 되살릴 수 있다.
5. Git index와 작업트리는 clean이고, inputs 밖 예상 외 untracked·ignored·임시·cache 파일은 0이다.

## 14. 최종 판정

프로젝트 전역 정리, 재사용 지식의 기존 owner 흡수, runtime·current output 보존, 삭제 전 actual bytes commit, 승인된 처분, Git object 위생, 규칙별 계보 보고, initiative self-clean의 목표는 달성됐다.

남은 제한은 두 가지다.

1. runtime source 재설치 자동화가 없어 W4-S1은 4.8/5다. 현재 설치본의 version·digest·실행 readiness는 검증됐다.
2. rule-surface 읽기 비용이 M0보다 7.35% 증가해 이전 “비증가” 기준은 실패했다. 이는 안전 의미를 보존한 선택이며, 향후 별도 의미 보존 압축 과제로만 다룬다.

이 두 제한은 현재 workspace clean 상태나 기능 회귀를 막는 blocker는 아니다.
