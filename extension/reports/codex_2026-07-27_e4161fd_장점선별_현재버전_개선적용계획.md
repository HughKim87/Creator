## 3. 적용 원칙

### 3.1 복원이 아니라 현재 owner로 이식

- `main_old`를 merge하지 않는다.
- 과거 커밋을 통째로 cherry-pick하지 않는다.
- `video_workflow` package를 되살리지 않는다.
- 현재 `extension/src/video_editing/`에 기능을 추가한다.
- 과거 코드는 동작 계약을 확인하는 참고 자료로만 사용한다.

### 3.2 작업 데이터와 기능 분리

- importer 테스트에는 합성 CSV만 사용한다.
- v18 CSV·XML·생성기·프레임값을 fixture로 커밋하지 않는다.
- 실제 과거 CSV를 이관해야 할 때는 사용자가 exact 항목과 목적을 지정한 별도 작업으로 다룬다.
- 운영 문서와 코드에서 `e4161fd`, 과거 보고서, 외부 백업을 runtime 의존성으로 참조하지 않는다.

### 3.3 상태를 과장하지 않음

- 합성 XML 검증은 `structure-validated`다.
- 실제 Premiere import 전에는 `app-validated`가 아니다.
- 실제 재생과 사용자 확인 전에는 `user-approved`가 아니다.
- importer가 만든 timeline은 의미를 추론하지 않고 `semantic_gate: pending`으로 둔다.

### 3.4 기존 동작 보존

- 현재 `sequence-v5` XML profile의 결과와 CLI는 회귀시켜 유지한다.
- Premiere CS6 형식은 새 explicit profile로 추가한다.
- 기존 schema의 정상 입력은 계속 통과해야 한다.
- 새 기능은 기존 출력의 자동 덮어쓰기를 허용하지 않는다.

### G4 — Premiere CS6 호환 XML profile

목표:

- 이전 구현의 검증된 FCP XML v4 구조를 현재 일반 schema에 적용한다.
- 현재 profile을 깨지 않고 CS6용 profile을 명시적으로 선택하게 한다.

예정 변경:

- 수정 `extension/src/video_editing/__init__.py`
- 신규 `extension/tests/test_video_editing_premiere_cs6.py`

Profile:

| ID | 역할 | 기본값 |
|---|---|---|
| `sequence-v5` | 현재 경량 sequence XML | 기존 호환을 위해 기본 유지 |
| `premiere-cs6-v4` | FCP XML v4 project 구조 | CS6 작업에서 explicit 선택 |

`premiere-cs6-v4` 구조:

1. XML declaration과 `DOCTYPE xmeml`
2. `xmeml version="4"`
3. project·bin·masterclip·sequence
4. master source file 정의 1개
5. video와 channel별 audio track
6. `sourcetrack`, `outputchannelindex`, clip link
7. source in/out·timeline start/end·audio gap 보존
8. source metadata 기반 frame rate·width·height·sample rate·channel
9. deterministic UUID
10. atomic write와 기본 비덮어쓰기

과거 대비 수정:

- 60fps·1920×1080·48kHz·stereo를 hard-code하지 않는다.
- UUID를 수동 입력 필수값으로 두지 않고 timeline canonical fingerprint에서 결정적으로 만든다.
- source URL을 사용자 문자열 그대로 신뢰하지 않고 현재 path URL 정규화를 사용한다.
- 의미 gate와 현재 validator를 반드시 선행한다.

검증:

- 두 profile의 기존/신규 회귀
- XML well-formed
- project·bin·masterclip·sequence exact 수
- source file 정의 1개
- video/audio clip 수·범위 일치
- audio gap과 split boundary 보존
- link target 전건 존재
- deterministic byte·SHA-256
- 잘못된 timeline·semantic pending에서 출력 0
- 기존 파일 비덮어쓰기
- XML 외 미디어 산출물 0

성공 gate:

- 합성 fixture에서 두 profile 모두 구조 검증 통과

## 6. 실제 Premiere 사용자 gate

G0~G5는 보호 데이터 없이 완료할 수 있다. 실제 Premiere 호환성은 별도 사용자 승인 없이는 완료로 가장하지 않는다.

필요한 별도 승인:

- exact 원본 미디어
- exact timeline 또는 합성 검수용 입력
- exact XML 출력 위치
- Premiere 앱을 사용한 import·재생 목적

앱 검수 항목:

1. XML이 프로젝트·bin·masterclip·sequence로 import되는가
2. 원본 media relink 또는 path 연결이 정상인가
3. frame rate·해상도·duration이 일치하는가
4. video와 L/R 또는 channel별 audio track이 정상인가
5. audio gap과 split boundary가 유지되는가
6. clip link·unlink 상태가 의도와 일치하는가
7. 두 대표 접합을 재생했을 때 audio·video sync가 맞는가

판정:

- 합성 테스트만 통과: `structure-validated`
- Premiere import·구조 확인: `app-validated`
- 사용자 재생 확인: `user-approved`

## 9. 완료 정의

다음 조건을 모두 만족할 때 선택 이식을 완료로 판정한다.

1. Claude와 Codex가 같은 startup owner를 사용한다.
2. 원본 SRT를 바꾸지 않고 명시 보정·제외를 수행할 수 있다.
3. 기존 9열 CSV를 현재 timeline으로 손실 없이 이관할 수 있다.
4. importer가 의미 역할이나 승인 상태를 조작하지 않는다.
5. validator가 한 실행에서 가능한 오류를 전건 보고한다.
6. 현재 XML profile의 기존 동작이 유지된다.
7. CS6 profile이 일반 source metadata로 FCP XML v4 구조를 만든다.
8. 합성 수직 acceptance가 과거 branch와 작업 데이터 없이 통과한다.
9. 실제 Premiere 검수 전 상태를 `app-validated`로 표시하지 않는다.
10. Core·보호 데이터·과거 작업 데이터에 변경이 없다.
11. 단계별 커밋이 있고 push는 없다.

## 10. 승인 후 진행 경계

사용자가 이 계획을 승인하면 G0~G5를 순차 실행한다. 일반적인 구현 선택은 이 문서의 권장안으로 자동 진행한다.

다음 상황에서는 중단하고 사용자에게 보고한다.

- 실제 `inputs/`·`outputs/` 접근이 필요한 경우
- Premiere 앱 검수가 필요한 경우
- `core/**` 변경이 필요한 경우
- 과거 작업 데이터를 fixture로 커밋해야만 진행할 수 있는 경우
- 현재 `sequence-v5` profile의 byte 회귀를 유지할 수 없는 경우
- 이 계획에 없는 삭제·이동·branch 조작이 필요한 경우

현재는 계획서만 작성했으며 개선 구현은 시작하지 않았다.
