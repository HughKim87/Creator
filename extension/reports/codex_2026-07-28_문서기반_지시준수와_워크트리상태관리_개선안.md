- 작성일: 2026-07-28
- 상태: G0~G3 완료 — G4 자동 회귀 진행 중
- 역할: 이 개선 initiative의 계획·진행 상태·성공 게이트를 소유하는 단일 정본
- 범위: 사용자 지시 망각 방지, 문서 기반 실행 복구, worktree별 상태 owner 분리, 미커밋 변경 보존
- 제외: 영상·SRT·썸네일·보호 데이터 작업, 외부 시스템 변경, push
- 실행 권한: 이 문서는 계획이다. 사용자의 별도 실행 지시와 core 변경 승인을 대신하지 않는다.

## 1. 목적

규칙 원문을 더 쌓는 것이 아니라 다음 실패를 구조적으로 차단한다.

1. 최신 사용자 지시를 읽었지만 실행 중 잊거나 임의 해석하는 실패
2. 문서를 EOF까지 읽지 않거나 적용 조항을 확인하지 않는 실패
3. 사용자 교정 후에도 폐기된 계획으로 계속 작업하는 실패
4. 현재 상태 문서보다 채팅 기억과 즉석 추론을 우선하는 실패
5. 다른 세션의 미커밋 변경을 무승인 restore하는 실패
6. main과 ainotebook이 같은 `SESSION_HANDOFF.md`를 읽는 실패

최종 결과는 과거 대화가 없어도 프로젝트 문서만으로 동일하게 작동해야 한다.

## 3. 사용자 지시 불변조건

다음 조건은 모든 단계보다 높은 실행 경계다.

- `AGENTS.md`에는 startup 절차·작업 분류·worktree 조건·세분화 규칙 링크를 두지 않음
- `AGENTS.md`는 Codex가 `PROJECT_RULES.md`를 찾기 위한 최소 플랫폼 진입점
- `CLAUDE.md`도 `PROJECT_RULES.md`를 불러오는 최소 플랫폼 진입점
- `PROJECT_RULES.md`가 worktree별 상태 문서와 `core/rules/*`·extension owner를 모두 라우팅
- ainotebook에서는 `SESSION_HANDOFF.md` 대신 `extension/work/AINOTEBOOK_WORKTREE_STATE.md` 사용
- ainotebook의 로컬 `SESSION_HANDOFF.md` 변경을 의미 손실 없이 전용 상태 문서로 이전
- 대화 자료는 `명시적 사용자 지시 / 프로젝트 규칙 / 에이전트 제안 / 추론`으로 구분하며 에이전트 제안을 사용자 지시로 승격하지 않음
- ainotebook local changes를 건드리기 전에 저장소 밖에 recovery copy를 만들고 파일 수·SHA-256을 검증
- 개선된 프로젝트 파일은 외부 backup을 링크하거나 의존하지 않음
- 전용 상태 문서를 먼저 커밋한 뒤 main 병합 범위를 확인하고 ainotebook에 main을 병합
- 사용자 교정이 들어오면 기존 해석과 미실행 명령을 즉시 폐기
- 다른 세션의 변경을 exact-path 승인과 복구 수단 없이 restore·overwrite 금지
- 보호 `inputs/`·`outputs/` 접근 금지
- 단계별 로컬 커밋, push 금지
- 미완료 상태로 세션을 끝낼 때 선택된 현재 상태 owner에 checkpoint·blocker·첫 다음 행동을 갱신

1. 시작 시 AGENTS 또는 CLAUDE 진입점을 통해 PROJECT_RULES를 읽는다.

4. 첫 mutation 전에 이 master의 불변조건과 현재 사용자 지시를 대조한다.
5. 대화·보고서·첨부 자료의 각 핵심 문장을 화자와 권위로 분류한다.
6. 사용자가 의도 오해를 지적하면 즉시 중단한다.
7. 기존 계획을 무효화하고 master를 갱신하기 전에는 다음 mutation을 실행하지 않는다.
8. 단계 문서는 절차만 소유하고 현재 상태·진행도는 이 master만 소유한다.
9. 다른 세션 local changes는 소유자와 exact diff를 확인한다.
10. restore·clean·overwrite 전에는 exact 대상 승인과 복구 수단이 모두 필요하다.
11. stage는 승인된 exact path만 사용한다.
12. 각 커밋 후 object·경로·보호 경로 수·잔여 status를 확인한다.
13. 미완료로 세션을 끝내기 전에 선택된 상태 owner를 갱신한다.
14. 비파괴적이고 범위 안인 구현 선택은 단계 문서의 권장안으로 자동 진행한다.
15. core 승인, merge 범위, restore·삭제·overwrite, 외부 효과는 권장안 자동 진행의 예외다.
16. 실행하지 않은 검증은 통과로 기록하지 않는다.
17. push하지 않는다.

## 7. 전체 성공 게이트

다음 조건을 모두 만족해야 완료다.

- AGENTS·CLAUDE에는 PROJECT_RULES 포인터 외 프로젝트 규칙·분류·라우팅이 없다.
- AGENTS·CLAUDE에서 `core/rules/*`와 extension owner로 직접 연결되는 링크가 0개다.
- PROJECT_RULES가 main과 ainotebook 상태 owner를 배타적으로 선택한다.
- PROJECT_RULES가 `core/rules/*`와 extension owner의 단일 라우터다.
- Obsidian graph에서 AGENTS가 아니라 PROJECT_RULES가 모든 활성 core rule과 연결된다.
- main은 `SESSION_HANDOFF.md` 하나만 읽는다.
- ainotebook은 `AINOTEBOOK_WORKTREE_STATE.md` 하나만 읽는다.
- ainotebook `SESSION_HANDOFF.md` local diff가 없다.
- 로컬 SESSION 변경의 의미 단위가 전용 상태 문서에 누락 없이 존재한다.
- `SESSION_HANDOFF.md는 항상 unstaged` 문구가 에이전트 제안으로 분류되고 사용자 승인 없이 정책으로 승격되지 않는다.
- ainotebook local changes의 외부 recovery copy가 파일 수·SHA-256으로 검증되고 프로젝트 파일은 이를 참조하지 않는다.
- 전용 상태 커밋 후 승인된 main 범위가 ainotebook에 병합되고 G1 라우팅 commit이 ancestry에 존재한다.
- 사용자 교정 후 기존 계획을 계속 실행하지 못하도록 규칙과 검증이 있다.
- 미커밋 변경에 대한 무승인 restore를 금지하는 실행 게이트가 있다.
- 관련 Core·Extension·라우팅 회귀와 통합 maintenance가 통과한다.
- 단계별 커밋이 존재하고 관련 없는 변경·보호 경로·push가 0건이다.
- 최종 보고가 실제 검증 수준, 미실행 검증, 남은 위험, 자체 복기를 기록한다.
- 미완료·완료 상태가 각각 선택된 상태 owner에 반영돼 다음 세션이 채팅 없이 재개할 수 있다.

## 8. 중단 조건

다음 중 하나면 자동 진행을 중단하고 사용자에게 보고한다.

- 현재 Git 상태가 이 master의 기준 상태와 달라 기존 변경과 충돌함
- 제거된 미커밋 변경을 세션 기록으로 재구성할 수 없음
- SESSION 변경과 AINOTEBOOK 상태 문서 사이에 의미 손실이 있음
- core 변경에 대한 현재 대화의 명시적 승인이 없음
- exact-path 커밋에 관련 없는 변경이 포함됨
- 같은 목표가 세 번 연속 실패함
