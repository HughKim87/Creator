## 승인 범위와 잠금

사용자는 2026-07-16 대화에서 r2의 제작 의도와 세 대표 표본 방향으로 진행하도록 승인했다. 이 승인은 전체 확장 **설계**와 working 기준본 선택을 허용한다. 실제 연속 A/V·Premiere 검증을 본 승인은 아니므로 `approved_baseline`, `generation_lock_released`, `current_deliverable`은 아직 허용하지 않는다.

## 확장할 중심 문장

> 영화로 보던 백룸은, 직접 헤매고 규칙을 배우며 익숙해질수록 무서움은 줄어도 끝내 긴장이 남는 체험이었다.

전체 편집은 `호기심 → 첫 진입 → 방향 상실 → 허세 붕괴와 부분 학습 → 규칙 실험 → 환경 이해 → 적응과 공포 잔존 → 긴장된 퇴각` 한 줄만 증명한다.

## 7D 실행 순서

1. r2 A·B·C의 연속 A/V 검증 표면을 확보하고 문맥·피크·호흡·메시지 자립을 확인한다.
2. 통과하면 r2를 `approved` 기준본으로 승격하고 generation lock을 해제한다. 실패하면 r2를 덮어쓰지 않고 descendant를 만든다.
3. S1–S8마다 유지·압축·제거 microbeat, 실제 컷 수, 최장 컷 근거, 화면·자막·오디오 경계를 기록한다.
4. 콘텐츠 기준 단일 시퀀스 컷리스트와 품질 프로필을 만들고 Q0–Q4를 감사한다.
5. `REVIEW_REQUIRED`가 0이거나 근거 있는 `WAIVED`만 남았을 때 Premiere CS6용 XML·보조 CSV를 새 버전으로 만든다.
6. 전체본은 Premiere 전체 재생과 최종 A/V·사용자 검증 전까지 `current_deliverable`로 승격하지 않는다.

## 레드팀과 회귀 금지

- r4처럼 떨어진 발화를 의미가 이어지는 것처럼 붙이지 않는다.
- 숫자 구조 점수를 실제 영상 품질 승인으로 사용하지 않는다.
- 발화 중간 절단을 피하려는 이유만으로 후보범위 전체를 통구간 보존하지 않는다.
- 콜드오픈 뒤 미래 원본 화면을 본편 앞부분의 B-roll로 재사용하지 않는다.
- 자동 감사 경고를 없애기 위한 기계적 마이크로컷이나 근거 없는 예외를 만들지 않는다.
- r4의 활성 피드백 6개는 실제 A/V로 descendant의 해결이 확인될 때까지 회귀 조건으로 유지한다.
