# integrated-calibration-v1 r3 감사

- 기준 버전: `integrated-calibration-v1 r2`
- 현재 버전: `integrated-calibration-v1 r3`
- 상태: `CANDIDATE_READY_WITH_PLAYBACK_GAP`
- 역할: `calibration_candidate`
- 사용자 피드백: “훅 디테일은 약하지만 전체 영상 느낌은 많이 좋아짐”
- 처리 범위: 7C 국소 리듬·컷 수정
- 전체 편집·`approved_baseline`·`current_deliverable`: 승격 금지
- MP4 생성: 없음

## 결론과 임시 점수

r2의 메시지·캐릭터·시간 순서 구조는 유지하고 훅의 화면-대사 정렬, B의 누락 행동, C의 경계와 엔딩 여운을 국소 수정했다. 구조·화면 근거 기준 임시 자기평가는 r2의 78점에서 **84점**으로 올랐다. 이 점수는 실제 연속 A/V 청취와 Premiere 재생을 제외하므로 최종 영상 품질 점수가 아니다.

## r2 → r3 변경

### A 훅

- r2: 도발 5.62초 → 허세 2.20초 → 공포·도주 4.75초.
- r3: 도발 5.62초 → 허세 2.20초 → 공포 인정 1.75초 → 도주 2.83초.
- `NPC 수준?` 동안 빈 방 대신 동일 E08 사건의 엔티티 근접 `2336.500–2338.700`을 무음 V2로 사용한다.
- `근데 무서워`와 `빨리 가`를 완결 SRT cue 경계에서 분리해 감정 반전과 행동 결과를 각각 보이게 한다.
- 훅 연결 길이: 12.57초 → 12.39초. 10~16초 규칙 유지.
- 훅 뒤 E01→E02 리셋은 변경하지 않았다. 훅 V2는 E08 동일 사건 내부에만 존재한다.

### B 전원 사건

- r2에서 전원 발견 뒤 실제 조작이 생략되고 밝은 방이 마지막 순간에만 보이던 결함을 수정했다.
- `B_POWER_SWITCH 3513.940–3516.340` 2.4초를 추가해 UI 스위치 변화와 원본 게임음을 보존했다.
- `B_COMEDY_PAYOFF` 끝을 `3522.940 → 3523.740`으로 연장해 “혼자 생쇼” 뒤 밝은 방을 0.8초 더 확인한다.
- 다음 SRT cue는 3524.940에 시작하므로 새 말은 섞이지 않는다.
- B 길이: 14.98초 → 18.18초.

### C 경계와 엔딩

- `C_TENSE_BODY`: `4864.420–4866.190 → 4864.365–4865.940`, SRT cue 전체에 맞춤.
- `C_SIGNOFF`: `4914.041–4915.292 → 4914.090–4915.940`, “여기까지 하겠습니다” cue 전체에 맞춤.
- 종료 V2: `4873.940–4878.917 → 4873.940–4879.907`.
- signoff부터 자백까지 검은 원본을 덮고, 자백 뒤 24프레임(0.4초) 동일 종료 공간을 더 보여준다.
- `C_TENSE_BODY`는 큐 자체는 온전하지만 “해주고 싶어요”의 앞 문맥 생략 여부가 남아 있어 실제 청취 전 완전 통과로 보지 않는다.

## 검증

- 품질 감사: `READY`
- 콘텐츠 컷: 21개, 선택 길이 74.35초, 미해결 자동 검토 0, 예외 0
- 멀티시퀀스 컷: 23개 = 연결 A/V 21개 + 무음 V2 2개
- XML: 3개 시퀀스, 모든 비디오·오디오 클립의 소스/타임라인 프레임 길이 일치
- 검토 페이지: static 플레이어, base audio 활성, 훅 V2, C 무음 tail 재생 로직, 블라인드 모드, 중심 메시지 1회
- r2+r3 통합 회귀검사: 30개 통과
- 원본 선택 구간 A/V 디코딩: 23/23 성공
- 변경 구간 SRT 정렬: 훅 -0.15초(0.603), B 0.00초(0.534), C 긴장 -0.05초(0.715), C 종료 +0.05초(0.853)
- 신규 화면 근거: `2338.700` 엔티티 근접, `3513.940` 전원 UI, `3516.000` 스위치 변화, `3523.700` 밝은 방 홀드, `4879.250` 종료 공간 여운

## 레드팀과 남은 위험

- 훅 V2는 같은 사건의 앞부분을 재사용하므로 실제 재생에서 반복처럼 느껴지는지 확인해야 한다. 미래 사건 삽입은 아니다.
- B는 행동 인과가 복구됐지만 2.4초 조작이 실제 리듬에서 긴지 짧은지는 연속 재생으로만 확정할 수 있다.
- `C_TENSE_BODY`는 SRT cue 경계는 안전하지만 앞 문장 의존성이 남는다. 사용자가 첫 결함 탐지자가 되지 않도록 실제 청취 전 승인 요청을 열지 않는다.
- 로컬 검토 페이지는 이전과 같은 브라우저 보안 정책 때문에 인앱 실제 재생을 검증하지 못했다. 정책을 우회하지 않는다.
- Premiere 가져오기·재생은 미검증이다.

## 한 가지 권고

전체 편집으로 확장하지 말고 r3의 `위협을 화면에 유지 → 행동을 생략하지 않음 → 코미디 뒤 결과를 잠깐 홀드` 문법을 실제 A/V로 먼저 확인한다. 특히 훅 V2 반복감과 `C_TENSE_BODY`의 앞 문맥만 통과하면 사용자 방향 체크포인트를 열 수 있다.
