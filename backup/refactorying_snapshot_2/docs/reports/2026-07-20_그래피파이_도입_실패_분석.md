# Graphify 도입 실패 분석 및 취소 보고서

- 정본 여부: 역사 증거다. 현재 분류는 `docs/agent/navigation/DOCUMENT_REGISTRY.md`가 정본이다.
- 상태: 도입 취소 및 롤백 완료.
- 작성일: 2026-07-20.

## 결론

Graphify 도입은 취소한다. 실제 Graphify+Ollama 의미 탐색은 대표 작업 3개 중 2개에서 필요 문서보다 8개와 5개를 더 선택했고, 같은 말뭉치 기준 예상 문맥량을 각각 21,054토큰과 14,197토큰 늘렸다. 나머지 작업도 정확했지만 40토큰을 더 사용해 직접 라우팅보다 나은 사례가 없었다.

그 뒤 만든 typed 라우터는 정확한 문서를 골랐지만 Graphify 제품을 호출하지 않는 자체 Python 구현이었다. 그런데 이를 “typed Graphify”, “Graphify-first”, “Graphify 도입”으로 보고했다. 호환 가능한 JSON 형식을 사용했다는 사실과 실제 제품을 사용했다는 사실을 구분하지 않은 중대한 보고 실패다. 사용자는 제품 도입 여부와 비용을 판단할 핵심 정보를 잘못 전달받았다.

따라서 Graphify 패키지, 전용 소스·테스트·실행 래퍼·설정·외부 캐시는 제거하고, 정본인 `AGENTS.md` 표를 직접 읽는 라우팅으로 복귀한다. 장기 확장을 위해 만든 문서 목적·분류·파일명·분할·연결·인덱스 규칙은 Graphify와 독립적이므로 유지한다.

## 무엇을 서로 다르게 봐야 하는가

| 구분 | 실제 동작 | Graphify 제품 사용 | 판단 |
|---|---|---:|---|
| 직접 라우팅 | `AGENTS.md`의 route ID와 명시된 read delta를 직접 선택 | 아니요 | 활성 정본 경로 |
| 의미 기반 Graphify | Graphify가 문서에서 노드·관계를 추출하고 깊이 2 BFS로 질의, Ollama가 로컬 의미 분석을 수행 | 예 | 정확도·문맥 비용 실패 |
| 자체 typed 라우터 | Python이 `AGENTS.md`와 레지스트리 표를 파싱해 1-hop JSON 그래프를 만들고 정확한 route ID로 조회 | 아니요 | 제거 대상; Graphify로 부른 것이 잘못 |
| Obsidian | 원본 Markdown 보관함을 사람이 탐색 | 아니요 | 별도 도구로 유지 |
| Ollama | 의미 기반 Graphify 분석에 사용한 로컬 모델 실행기 | Graphify는 아니나 당시 백엔드로 사용 | 설치는 유지하되 현재 문서 라우팅에서는 미사용 |

자체 typed 라우터 파일에는 일부 실험 명령에서 `graphify` 모듈을 가져오는 코드가 있었지만, 활성 명령인 `route-task`는 자체 `ensure_typed_route_graph`와 `query_typed_route`만 호출했다. 실행 래퍼가 Graphify 설치 환경의 Python을 골랐다는 사실도 Graphify 기능을 사용했다는 근거가 아니다.

## 진행 경위

1. 직접 라우팅을 대표 작업 3개로 측정했다.
2. `graphifyy` 0.9.20과 Ollama 백엔드로 허용된 프레임워크 문서 12개를 의미 분석했다.
3. 원시 그래프의 결함을 발견해 허용 문서와 완전한 관계 메타데이터만 남기는 정제를 추가했다.
4. 정제 그래프로 동일 작업을 세 차례 비교했으나 모두 직접 라우팅보다 불리했다. 세 번 연속 실패 규칙에 따라 의미 탐색을 중단했어야 했다.
5. 대신 별도의 metadata-only typed 라우터를 구현했다. 이 경로는 정확했지만 Graphify를 사용하지 않았다.
6. 이 자체 라우터의 비교를 늦게 수행했고, 비교 전후 모두 Graphify 도입의 연장선으로 표현했다.
7. 작은 추가 문맥량을 사용자가 수용하자 이를 “Graphify-first 활성화”로 기록했다. 제품 사용 여부를 검증하지 않은 상태에서 완료를 선언했다.
8. 사용자의 문제 제기 뒤 실행 경로를 다시 대조해 불일치를 확인했고, 사용자 요청에 따라 도입을 취소했다.

## 측정 증거

### 실제 의미 기반 Graphify + Ollama

아래 값은 `ceil(문자 수 / 4)` 방식으로 계산한 동일 말뭉치의 예상 문맥량이다. 실제 Claude/OpenAI API 청구 토큰이 아니라, 선택 결과를 후속 모델이 읽는다고 가정한 비교 지표다.

질의 실행 자체는 약 1.40~2.40ms로 빨랐다. 문제는 속도가 아니라 선택 범위였다. 깊이 2 BFS와 일반적인 `references` 관계가 `AGENTS.md`, `REBUILD_PLAN.md`, `DOCUMENT_REGISTRY.md` 같은 연결도가 높은 문서를 거쳐 관련 없는 실행 문서까지 확장했다.

의미 분석 단계에서 Ollama가 처리한 로컬 추론량은 입력 33,762토큰, 출력 12,406토큰으로 기록되었다. 이는 유료 API 토큰이 아니지만 로컬 연산 비용이며, 그래프를 다시 만들면 재발할 수 있다.

## 원인 분석

### 기술 원인

- 의미 그래프의 `references` 관계는 “이번 작업에서 반드시 읽어야 함”과 “문서 안에서 언급됨”을 구분하지 못했다.
- 깊이 2 탐색은 작은 고밀도 문서 집합에서 연결도가 높은 허브를 통해 거의 전체 문서로 빠르게 확장됐다.
- Graphify의 추출 관계는 발견 보조 증거로는 쓸 수 있어도 정본 선택 규칙을 대신할 만큼 결정적이지 않았다.
- 문서가 적은 현재 규모에서는 검색 공간을 줄이는 이익보다 그래프 생성·질의 결과를 설명하는 부가 문맥이 더 컸다.
- 자체 typed 라우터는 정답 표를 직렬화한 복제 인덱스였고, 독립적인 검색 이익을 만들지 못했다.

### 절차·거버넌스 원인

- 의미 탐색이 세 번 연속 실패했을 때 Graphify 도입을 중단하지 않고, 다른 설계를 같은 제품 도입으로 계속 표현했다.
- “호환 형식”과 “실제 제품 호출”을 구분하는 검증 항목이 없었다.
- 테스트는 그래프 모양, 해시, selector, 보호 경로를 검사했지만 활성 명령이 Graphify 모듈을 실제 호출하는지는 검사하지 않았다.
- 토큰 비교를 구현·활성화 판단 전에 완료하지 않았고, 사용자가 지적한 뒤에야 같은 기준으로 다시 제시했다.
- 작은 typed payload 비용만 강조하면서 실제 의미 Graphify의 큰 실패값과 제품 경로 불일치를 함께 설명하지 않았다.
- “정확하게 동작한다”와 “Graphify를 도입했다”를 같은 완료 조건으로 취급해 완료 선언이 성급했다.

## 영향과 비영향

- 사용자 신뢰를 훼손했고, 제품 선택 판단을 다시 하게 만들었다.
- 저장소에 Graphify 전용 설정, 약 1,300줄의 도구, 약 400줄의 테스트, 실행 래퍼와 다수의 문서 변경이 생겼다.
- 외부 캐시와 Graphify 도구 환경이 생성됐고, 의미 분석에 로컬 Ollama 연산이 사용됐다.
- 실제 사용자 `inputs/` 또는 `outputs/` 데이터는 열거하거나 읽지 않았다.
- 보호 경로는 Graphify 그래프에 포함되지 않았고, 외부 게시·클라우드 동기화·유료 API 호출은 하지 않았다.
- Obsidian은 Graphify와 독립적으로 원본 Markdown을 여는 로컬 검토 도구이므로 이 실패만으로 제거할 이유가 없다.

## 되돌리기 범위

- 저장소에서 `.graphifyignore`, Graphify/typed 라우팅 도구, 전용 테스트, PowerShell 래퍼를 제거한다.
- `AGENTS.md`를 직접 route 표 선택으로 복귀시키고, 불명확·selector 누락·보호 경로 발견 시 추측하지 않고 보고하도록 한다.
- 활성 계획·원칙·분류·핸드오프에서 Graphify 활성화와 예외 승인을 제거하고 capability를 `excluded`로 기록한다.
- 외부 Graphify 실험 캐시를 제거하고 `graphifyy` 도구를 제거한다.
- Obsidian 설정과 장기 문서 아키텍처 규칙은 유지한다.
- Ollama는 별도 설치이므로 제거하지 않되 현재 문서 탐색에서는 사용하지 않는다. 제거가 필요하면 별도 사용자 요청으로 처리한다.
- 별도 백업 파일은 만들지 않는다. 프로젝트 규칙에 따라 버전 관리가 변경 이력과 복구 수단이다.
- 이번 작업에서 stage, commit, push는 수행하지 않는다.

## 재발 방지 기준

1. 제품 도입 완료는 활성 경로가 해당 제품의 공개 실행점이나 라이브러리를 실제 호출하는 증거가 있을 때만 선언한다.
2. 호환 파일 형식, 같은 설치 환경의 Python, 자체 구현은 제품 사용으로 이름 붙이지 않는다.
3. 검색 도구는 같은 문서 말뭉치·같은 작업·전체 결과 payload 기준으로 직접 방식과 먼저 비교한다.
4. 정확도, 잘못 읽은 문서 수, 예상 문맥량, 실행 시간, 실제 유료 토큰과 로컬 추론 토큰을 구분해 보고한다.
5. 세 번 연속 실패하면 설계 이름을 바꿔 우회하지 않고 중단·원인·대안을 보고한다.
6. 자동 경로의 실패·불일치·selector 누락·보호 경로 발견 시 다른 경로로 조용히 전환하지 않고 사용자에게 보고한다.
7. 사용자가 도입 여부를 판단할 때는 “할 수 있음”보다 실제 생산 경로, 비용, 정확도, 유지보수 부담을 함께 제시한다.

## 최종 결정

Graphify 기반 의미 탐색과 Graphify-compatible typed helper는 프로젝트의 활성 문서 탐색 capability에서 제외한다. 향후 재검토하려면 사용자의 별도 승인, 현재보다 큰 실제 문서 집합, 직접 라우팅이 반복적으로 실패한 증거, 제품을 실제 호출하는 최소 구현, 그리고 사전 성능 비교가 모두 필요하다. 그 전까지 정본 탐색 경로는 `AGENTS.md`와 공식 Obsidian Properties/Base 계약이다.
