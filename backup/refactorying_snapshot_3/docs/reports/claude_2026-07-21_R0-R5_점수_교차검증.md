### 3.3 재현하지 못한 항목

`F` 1차 보고의 "전체 테스트 29개 통과"는 2차 검증 환경(Linux, Python 3.10 + `tomli` shim)에서 완주하지 못했다. 런처 회귀 3건이 Windows 전용이고 구조 검증 테스트 1건이 5분 이상 지속됐다.

`D` 이는 반증이 아니라 환경 차이다. 1차 주장은 유지하되 검증 환경 의존성이 있다는 사실을 함께 기록한다. 이 항목은 §4.2 결함과 직접 연결된다.

### 3.4 후속 Codex 재현 검증

후속 검증은 원본 Windows 작업공간과 프로젝트 공개 launcher가 선택한 Python 3.12.13에서 수행했다.

- 클로드 direct-route 작성 직후 첫 회귀는 `orphan report`, `DOCUMENT_MAP.md` content hash 불일치, unit projection 불일치로 29개 중 1개가 실패했다. `context_system.py sync`로 원인을 동기화한 뒤 전체 **29/29**가 통과했다.
- 동기화 후 통합 validator는 `ok=true`, error 0, orphan 0이었다. 같은 Windows 원본에서 측정한 1회 실행 시간은 **14.934초**였다. 따라서 F-1의 증가 위험은 유효하지만 클로드 환경의 약 60초·3분 수치는 환경별 관측값이다.
- 동기화 직후 `catalog/units.jsonl`은 51,537 unit, 36,960,849바이트였다. 이 중 `context/` unit은 48,034개로 **93.2%**였다. file catalog 183개 record 중 `context/`는 105개로 **57.4%**였다. 수치는 새 context 생성 때 계속 변하므로 시점값이다.
- `context_system.py`의 `tomllib` import와 launcher의 `import sys; exit 0` probe를 확인했다. 현재 3.12.13은 성공하지만 최소 버전 거부 조건은 없다. Python 3.10 실패는 클로드 격리 환경의 재현 증거로 유지한다.
- 활성 Markdown에서 `backup/` 대상 로컬 링크 33개와, 대상의 실제 존재를 요구하는 `validate_markdown_links()`를 확인했다. F-3은 정적 코드와 문서 양쪽에서 재현됐다.
- process lock primitive가 없는 것도 확인했다. 문서 지도 중복 관측 자체는 클로드 세션 증거이며 후속 검증 시점에는 해당 행이 1개였다. 구조적 동시성 결함과 특정 중복 관측의 증거 수준을 구분한다.

### 8.1 재확인되어 유지되는 합의

`F` 29/29 테스트(Windows, Python 3.12.13), `validate` 14.934초, `ok=true`·orphan 0, 라인 수의 공백 포함 여부 차이, F-1~F-3의 유효성은 3차에서도 변경 사유가 없다. 조정 점수 **86.8/100**도 유지한다.

### 8.2 유일하게 판정이 뒤집힌 항목: F-4

`F` §3.4와 §4.2는 F-4를 "구조적 결함은 유효하나 특정 중복은 타 세션 관측이며 독립 재현이 아님"으로 분류했다. 3차 검증에서 이 분류는 실증 사건으로 대체된다.

`F` 두 세션이 동시에 `sync_catalog`를 실행하는 동안, 한 프로세스의 원자적 쓰기 임시 파일이 다른 프로세스의 파일 탐색에 포착돼 **자기 산출물인 `catalog/tmp*` 3건이 존재하지 않는 상태로 `active` 등록**됐다(`tmp373czc5g`, `tmpsupu6fp4`, `tmp9gucu02q`).

`F` 그 결과 `plan-file`, `resolve`, `sync`가 `build_unit_projection()`에서 `FileNotFoundError`로 연속 8회 실패했다. 정본 catalog가 손상된 동안에는 어떤 context 작업도 수행할 수 없었고, 해당 row를 `deleted`로 표시하는 수동 복구 후에야 12초 sync가 정상화됐다.

`D` 따라서 F-4는 이론적 위험이 아니라 **재현된 가동 중단**이다. 심각도를 중간에서 **높음**으로 상향하고, §6 권고 6(동시 실행 catalog 소유권·감지 규칙)을 1순위로 올린다. 추가로 파일 탐색이 `catalog/tmp*` 자기 산출물을 제외하고 사라진 파일의 unit 추출을 건너뛰도록 하는 수정이 필요하다. 두 항목 모두 사용자 승인 대상이다.

### 8.3 점수에 반영하지 않는 이유

`D` 다중 프로세스 안전성은 승인 설계 R-1.1의 어느 단계 완료 조건에도 없었다. §4.3에서 "범위 밖 요구로 감점하지 않는다"는 원칙을 R0와 R-4에 적용했으므로 R-3·R-5에도 동일하게 적용한다. F-4는 단계 점수가 아니라 **현재 운영 위험**으로만 승격한다.
