### 1.2 여기서 도출한 실행 원칙 6개

1. **교체가 아니라 보강.** `backup/`은 폐기 대상이 아니라 자산이다.
2. **2층 구조.** 기반(L1~L4: 프로젝트 일반의 룰·구조·툴) → 그 위에 목적층
   (L5~L8: 영상 워크플로우 룰·구조·툴·스킬). 순서를 뒤집지 않는다.
3. **단계별 도입.** 레이어 단위로 얹고, 어느 레이어에서 멈춰도 그때까지가 온전히 동작.
4. **문제 개선과 생산성 향상은 한 세트.** 안정성만 올리고 작업이 느려지면 실패.
5. **비용 상한이 설계 제약.** 반나절 원칙과 금지 목록은 편의가 아니라 요구사항.
6. **문서는 상세하게, 작업은 작게.** 계획 축약 금지, 구현 범위 축약 필수.

원문과 원칙의 정본은 `docs/improvement/LAYER_PLAN.md` §1.3~1.4에도 동일하게 있다.

## 6. 2026-07-17 재구축 산출물 처분

정본은 `LAYER_PLAN.md` §3.2. 요약:

| 구분 | 대상 | 방침 |
|---|---|---|
| 살림 | `workflow doctor`/`check`, `checks/`, `doctor.py`, `checks/baseline.py`, `BACKUP_MANIFEST.json` | L1에서 룰 검사 수단으로 재사용 |
| 동결 | `domain/`, `storage/`(SQLite), `services/`, `adapters/` | 삭제하지 않되 **어떤 레이어도 이 코드에 의존하지 않는다** |
| 폐기 | stage-05~08 지시서, 증거 패키지 규약, 레드팀·독립 QA 절차 | 이 계획으로 대체 |

**핵심 설계 결정 2개:**

1. **L2 상태 저장은 JSON 파일이다. SQLite를 쓰지 않는다.** 사용자가 "파일을 기반으로 한
   데이터 처리 구조"를 명시했고, 1인 순차 작업에 동시 writer 제어가 불필요하다.
   어제 만든 SQLite 저장소는 동결 상태다.
2. **Premiere XML은 legacy 원본을 계속 쓴다.** 어제 이식한 포트는 기능 이득이 없다.

## 8. 주의

- `.git/index.lock` 0바이트 파일이 남아 있을 수 있다(샌드박스 mount 권한 문제로 git이
  unlink 실패). Windows에서 git이 "index.lock exists"로 거부하면 수동 삭제하면 된다.
  조회성 git 명령은 정상 동작한다.
- `backup/`은 읽기 전용 자산이다. 수정하지 않는다.
- `inputs/`·`outputs/`는 열거·복사·인덱싱하지 않는다 (`PROJECT_RULES.md` User Data Boundary).
- `docs/rebuild/`는 폐기된 이력이다. 실행 근거로 읽지 않는다.
