# 단계 06 작업 지시서: 전환 후보·가역적 임시 전환과 즉시 롤백

## 1. 단계 목적

신규 구조를 `cutover_candidate`에서 가역적인 `provisional_cutover`로 전환하되,
퇴행이나 거짓 성공이 발견되면 코드·상태·산출물 각각을 검증된 지점으로 되돌릴 수 있게
한다. 이 단계는 안정화 완료를 선언하지 않는다. 구체계는 삭제하지 않고 역사적 읽기
전용 기준선으로 유지한다.

## 2. 시작 게이트

- 단계 05에서 기술 게이트와 사용자 A/V 승인이 완료됐다.
- Stage 05가 `pilot_limited_legacy_baseline`이면 사용자의 `legacy_execution_waived`가
  유효하고 결과에 계속 표시돼야 한다. 원격 CI 여부와 혼합하지 않으며, Stage 07의
  실제 작업 안정화 전에는 다른 경우와 마찬가지로 provisional 상태만 허용한다.
- Critical·Major 미해결 결함 0건이다.
- 신규 구조 전체 검사와 clean-clone 검증이 통과했다.
- 구체계 보존 태그 또는 SHA가 있다.
- Stage 05의 SQLite 일관 백업과 코드·입력·승인 산출물 빈 경로 최소 복구 시험이
  완료됐다.
- 사용자에게 전환 범위, 비용, 롤백 책임자가 제시됐다.

## 3. 역할

### 전환 총괄 에이전트

- 기본 CLI, 문서, 훅, CI의 최종 통합
- 전환 체크리스트와 승인 기록
- 다른 에이전트의 공용 파일 수정 금지

### 복구 검증 에이전트

- DB 백업·복구, 코드 롤백, 산출물 복구를 독립 실행
- 프로덕션 코드 수정 금지

### 원격 검증 에이전트

- 사용자 승인과 접근 권한이 있을 때만 GitHub Actions와 보호 규칙 확인
- 접근 실패를 성공으로 기록하지 않음

## 4. 금지 사항

- `backup/` 삭제·정리·이름 변경
- 구체계 폐기 선언
- 복구 시험 없이 기본 경로 변경
- 사용자 승인 없는 커밋·태그·푸시·브랜치 보호 설정
- Git 롤백만으로 DB와 산출물도 복구됐다고 가정
- 진행 중 실패 산출물 자동 삭제
- 원격 CI 미확인 상태를 완전 전환으로 선언

## 5. 전환 전 스냅샷

다음을 보존한다.

- 신규 릴리스 후보 식별자
- 구체계 최종 정상 식별자
- SQLite backup API로 만든 일관된 DB 사본
- 입력 해시 목록
- 현재 산출물 매니페스트
- Python·의존성·FFmpeg 버전
- 기술 검증과 사람 승인 증거
- 정확한 롤백 명령·경로와 예상 소요시간
- 애플리케이션 커밋·버전, DB `schema_version`, 마지막 migration
- 해당 코드가 지원하는 최소·최대 schema, 자동 migration 허용 여부, downgrade 가능 여부

## 6. 세부 작업

### 작업 06-1: 카나리 운영

첫 실제 프로젝트 하나만 신규 기본 경로 후보로 실행한다.

- 기존 작업 공간을 덮어쓰지 않는다.
- 새 세대 ID를 발급한다.
- 단계 소요시간, 실패, 재시도, 승인을 기록한다.
- 첫 카나리 동안 자동 정리 작업을 비활성화한다.
- 구체계 복귀 경로를 유지한다.
- 전환 전부터 DB 이벤트에 성공·실패, 종료 코드, 실패 지문, 재시도, 입력 변조,
  승인 우회, 미등록 artifact를 기록한다.
- Stage 07의 완전한 metrics CLI가 없어도 조정 에이전트가 읽기 전용 고정 질의로 카나리
  게이트 수치를 산출하고 결과·질의 버전을 증거화한다.

### 작업 06-2: 공용 진입점 정리

- README와 에이전트 진입 문서를 신규 CLI 기준으로 갱신한다.
- 훅과 CI에서 stale 구체계 경로를 제거한다.
- 기본 명령은 하나의 `workflow` CLI만 사용한다.
- 과거 배치 래퍼를 문서 기본 경로로 제시하지 않는다.
- 신규 프로덕션 코드가 `backup/`을 import하지 않는지 다시 검사한다.

### 작업 06-3: 원격 CI와 보호 규칙

- 원격 접근이 가능하면 Actions의 실제 성공 실행을 확인한다.
- 비공개 저장소에서 필수 상태 검사를 강제할 플랜·비용을 사용자에게 확인한다.
- 사용자 승인 후에만 branch protection 또는 ruleset을 적용한다.
- CI가 미디어를 업로드하거나 외부 AI를 호출하지 않게 한다.
- 접근이 불가능하면 기본 상태는 `remote_ci_pending`이며 완전 전환으로 보고하지 않는다.
- 로컬 전용 운영을 계속해야 한다면 사용자가 위험을 명시적으로 승인한 경우에만
  `remote_ci_waived_by_user`를 기록하고 `provisional_local_cutover`로 Stage 07에 넘길 수
  있다. 이를 원격 보호가 완료된 전환 또는 `stabilized`라고 부르지 않는다.

### 작업 06-4: 롤백 훈련

서로 별도로 수행한다.

1. 코드: 마지막 정상 신규 릴리스 또는 구체계 보존 SHA 실행
2. 상태: 복원 코드와 DB schema 호환성을 먼저 검사한 뒤 일관된 DB 사본 복원과 verify.
   불일치 시 자동 migration하지 않고 실패
3. 산출물: 매니페스트 기준 격리·복원
4. 입력: 해시 재검증
5. 전체: 복원 상태에서 스모크 흐름 실행

모든 절차와 실제 소요시간을 기록한다.

### 작업 06-5: 기본 경로 승격

카나리, A/V 승인, 원본 무결성, 산출물 등록, 롤백 훈련, 독립 QA가 모두 통과하고
사용자가 전환을 승인한 뒤에만 신규 CLI를 `provisional_cutover` 기본 경로로 선언한다.
`stabilized` 승격은 Stage 07의 실제 작업 관찰 게이트에서만 가능하다.

## 7. 즉시 롤백 조건

다음 중 하나가 발생하면 신규 실행을 차단한다.

- 실패가 성공으로 표시됨
- 입력 원본 해시 변경
- 승인 없이 다음 단계 진입
- 등록되지 않은 산출물 생성
- DB와 실제 파일이 복구 불가능하게 불일치
- 동일 중대 결함 두 번째 재발
- 실제 영상의 Critical A/V 퇴행
- 백업 복구 시험 실패

첫 10개 실제 작업 성공률은 즉시 전환 시점에 알 수 없으므로 Stage 07 안정화 롤백
기준으로 추적한다.

## 8. 롤백 절차

1. 신규 실행 진입을 차단한다.
2. 진행 중 실행을 `aborted`로 기록한다.
3. 현재 실패 DB, 산출물, 이벤트, 매니페스트를 삭제하지 않고 읽기 전용 증거로 동결하고
   해시한다.
4. 원본 입력 해시를 재검증한다.
5. 사용자에게 DB 복원·덮어쓰기 범위를 확인한다.
6. 마지막 정상 코드가 백업 DB schema를 지원하는지 검사한다. 불일치하면 자동
   migration 없이 중단한다.
7. 마지막 정상 DB 백업을 별도 경로에 복원한다.
8. 마지막 정상 신규 릴리스 또는 구체계 보존 SHA를 승인된 별도 worktree에서 실행한다.
9. 롤백 후 동일 입력으로 스모크 검사를 수행하고 `rollback_performed` 증거를 남긴다.
10. 근본 원인과 회귀 테스트가 추가되기 전 재전환하지 않는다.

## 9. 완료 기준

- 사용자 전환 승인
- 신규 기본 경로의 clean-clone 검증
- 원격 접근 가능 시 실제 CI 성공과 필수 검사 확인
- 원격 접근 불가 시 사용자의 명시적 로컬 전용 위험 승인과
  `remote_ci_waived_by_user`가 있음. 단순 `pending`만으로는 완료 불가
- stale 실행 경로 참조 0건
- 코드·DB·산출물 롤백 훈련 성공
- 30분 이내 복구 또는 실제 기준값 기록
- 구체계와 `backup/` 무변경
- 문서와 실제 CLI 일치
- 결과 상태가 `provisional_cutover` 또는 승인된 `provisional_local_cutover`이며
  `stabilized`로 오표기되지 않음

## 10. 중단 조건

- 원격 설정 변경에 필요한 사용자 승인이 없음
- 기본 경로와 문서가 불일치
- 복구 훈련에서 상태 또는 산출물이 누락됨
- 구체계 보존 SHA가 실행되지 않음
- 자동 정리로 실패 증거가 사라짐

## 11. 롤백

이 문서의 롤백 절차가 단계의 핵심 산출물이다. 전환 자체를 되돌릴 때도 `backup/`을
원위치로 이동하지 않는다. 기본 진입점, 상태 DB, 산출물 포인터를 각각 검증된 지점으로
돌리고 전체 스모크 검사로 확인한다.
