# 게임 플레이 영상 분석

이 스킬은 워크플로우의 **데이터 분석 단계**를 수행한다.

목표는 하이라이트나 메시지를 새로 invent 하는 것이 아니라, **원본에서 확인되는 사건·감정·화면·음성과
시청자 관심 가설의 근거를 분리해 기록하고, 다음 영상 기획 단계가 사용할 분석 지도와 인계 브리프를 만드는 것**이다.

데이터 분석 출력은 컷리스트, XML, 러프컷이 아니다. 영상 기획 승인 뒤에만 편집 단계의
`premiere-editing-export`가 컷 경계와 편집 자료를 만든다.

## 선행 조건 — 원본 데이터 필수 게이트

촬영 완료본에서는 이 스킬을 **영상 기획보다 먼저** 쓴다. 실행 순서의 정본은
`docs/WORKFLOW_CONTRACT.json`이다.

필수 입력:

- 고정된 `source_id`와 원본 지문
- 끝까지 읽을 수 있는 원본 영상
- 원본 자막 또는 발화·오디오 인덱스와 신뢰도
- 검증할 시청자 관심 가설
- 기존 원본 시간 기반 화면 자산 목록

이 입력이 없거나 데이터 분석 게이트를 통과하지 않았으면 메시지·스파인·컷리스트를 만들지 않는다.
기존 기획서는 비교 자료로 읽을 수 있지만 분석 기준본으로 승격하지 않는다.

## 핵심 원칙

- **분석 단위는 원본 사건과 근거 묶음이다.** RMS, 키워드, 비명 크기가 사건 의미를 대신하지 않는다.
- **신호는 보조다.** 자막·RMS·피크는 사건·반응·경계 후보를 찾는 데만 쓴다.
- **자막만으로 최종 판단하지 않는다.** 핵심 근거는 실제 화면 근거를 확인한다.
- **화면만 무작정 많이 보지 않는다.** 자막·오디오 인덱스와 기존 자산으로 범위를 먼저 좁힌다.
- **사건-결과-반응을 분리해서 자르지 않는다.** 조우, 사망, 규칙 발견, 엔딩은 앞뒤 맥락을 기록한다.
- **핵심/보조/제외를 구분한다.** 같은 기능의 비명·사망·탐색을 모두 살리지 않는다.
- 원본 영상과 원본 자막은 절대 수정하지 않는다.
- 한 번 본 구간은 Markdown/CSV로 저장하고, 다음 세션에서 다시 이미지 판독을 반복하지 않는다.
- 화면 자산은 편집본 시간이 아니라 원본 `source_id`와 원본 시간/프레임으로 식별한다.
- 새 캡처 전에 원본 자산 목록을 조회하고, 범위·해상도가 충분하면 기존 자료를 그대로 사용한다.

## 입력 확인

1. 원본 영상 경로를 확인한다.
2. `source_asset_manifest.csv`에서 원본 경로·크기·수정 시각이 맞는 기존 `source_id`를 찾는다.
   같은 원본에 새 ID를 만들거나, 지문이 달라진 원본을 기존 ID에 섞지 않는다.
3. 같은 이름의 원본 `.srt`가 있으면 우선 사용한다. 새 전사는 비용이 필요할 때만 생성한다.
4. 데이터 분석 질문표에서 아래 정보를 가져온다.

| 필드 | 설명 |
|---|---|
| `evidence_id` | 분석 근거 ID |
| `source_range` | 원본 확인 범위 |
| `event_question` | 사건·결과·반응에서 확인할 질문 |
| `audience_interest_question` | 시청자 관심 가설과 연결할 질문 |
| `screen_question` | 화면에서 확인할 질문 |
| `audio_subtitle_question` | 음성·자막에서 확인할 질문 |

5. `ffprobe`로 원본이 끝까지 읽히는지 확인한다. 메타데이터 길이만 믿지 않는다.

```powershell
tools\ffmpeg\bin\ffprobe.exe -v error -show_entries format=duration,size -of default=noprint_wrappers=1 "원본.mkv"
tools\ffmpeg\bin\ffprobe.exe -v error -read_intervals 02:24:00%+00:00:45 -select_streams v:0 -show_entries packet=pts_time -of csv=p=0 "원본.mkv"
```

## 토큰 예산 규칙

긴 영상 전체를 프레임으로 읽지 않는다.

| 작업 | 기본 화면 사용량 | 설명 |
|---|---:|---|
| 근거 묶음별 1차 확인 | 6~12프레임 | 사건 주변 화면 확인 |
| 후보 구간 1개 검증 | 8~16프레임 | 3~5분 구간 기준 |
| 사건-반응 경계 확인 | 6~12프레임 | 조우, 사망, 규칙 발견, 엔딩 주변 |
| 화면 글자 확인 | 1024px | 필요할 때만 사용 |
| 일반 흐름 확인 | 512px | 기본값 |

한 세션에서 이미지 읽기는 가능한 한 16~40장 안에 둔다. 더 필요하면 후보 하나를 끝내고 저장한 뒤 다음 후보로 넘어간다.

## 작업 순서

### 1. 데이터 분석 질문 로드

원본 자막·오디오 인덱스·기존 화면 자산에서 확인할 근거 질문을 표로 옮긴다.

```csv
evidence_id,source_range,event_question,audience_interest_question,screen_question,audio_subtitle_question
E01,00:34~01:13,게임 진입 전 기대와 불안이 어떻게 드러나는가?,원작 매체 경험과 연결되는가?,화면이 원작/게임 연결을 보여주는가?,발화 의미와 감정은 무엇인가?
E05,10:39~10:59,적 조우의 사건·결과·반응이 이어지는가?,장르의 미지성·추격 기대와 연결되는가?,적/도망/반응이 모두 보이는가?,비명과 대사가 화면 사건과 일치하는가?
```

이 표가 없으면 데이터 분석을 시작하지 않는다.

### 2. 저비용 확인 범위 잡기

화면을 바로 많이 보지 않는다. 먼저 자막과 오디오로 각 근거 묶음의 확인 범위를 정한다.

- 일반 발화 근거: `target_time -30초 ~ +60초`
- 직전 사건과 직후 반응이 필요한 근거: `target_time -90초 ~ +90초`
- 사망·추격·비명 후보: 오디오 RMS/피크를 보조로 확인
- 조용한 소감·정리 대사: 오디오 피크가 없어도 유지

```powershell
tools\ffmpeg\bin\ffmpeg.exe -i "원본.mkv" -af "astats=metadata=1:reset=1,ametadata=print:key=lavfi.astats.Overall.RMS_level:file=rms.txt" -f null -
```

이 단계에서 만드는 것은 **후보 범위표**다. 컷 경계를 확정하지 않는다.

### 3. 화면 검증

기존 원본 자산 목록을 먼저 조회하고, 없는 원본 시각만 `source_frame_assets.py`로 추출한다.

```powershell
<python> `
  tools\source_frame_assets.py "원본.mkv" `
  --source-id <source_id> --start 00:07:00 --end 00:11:10 --count 16 `
  --width 1024 --asset-root outputs\06_analysis\source_assets\<source_id> `
  --manifest outputs\06_analysis\source_asset_manifest.csv
```

큰 구간에서 사건·반응 경계가 거칠면 지정 시각 프레임만 추가로 뽑는다.

```powershell
<python> `
  tools\source_frame_assets.py "원본.mkv" `
  --source-id <source_id> --timestamps "00:10:35,00:10:45,00:10:58,00:11:05" `
  --width 1024 --asset-root outputs\06_analysis\source_assets\<source_id> `
  --manifest outputs\06_analysis\source_asset_manifest.csv
```

편집본 시각으로 받은 요청은 최신 컷리스트의 누적 타임라인 범위를 이용해 원본 시각으로 변환한 뒤 조회한다.
자막·오버레이·전환·합성 결과처럼 렌더 자체를 확인해야 할 때만 편집본 캡처를 별도 검증 근거로 만든다.

각 후보는 아래 네 단위로 본다.

| 단위 | 확인할 것 |
|---|---|
| `pre_context` | 대사 직전 무슨 일이 있었는가 |
| `event` | 화면에서 실제 사건이 보이는가 |
| `reaction` | 대사·플레이 반응이 이어지는가 |
| `result` | 사망, 성공, 이동, 규칙 발견 같은 결과가 보이는가 |

### 3-1. synccheck 조건부 사용

`tools/synccheck`는 모든 후보에 쓰지 않는다. 아래 상황에서만 보조 검증으로 사용한다.

- 자막 타임코드와 실제 발화가 어긋난다.
- 후보 시작/끝이 말 중간을 자를 위험이 있다.
- 사건, 결과, 반응 경계가 화면만으로 불명확하다.
- 7B 컷 경계 검증으로 넘길 조정 근거가 필요하다.

synccheck 결과는 제안 근거일 뿐, 핵심 근거나 컷 경계를 자동 확정하지 않는다.

### 4. 후보 판정

후보마다 아래 필드를 기록한다.

| 필드 | 의미 |
|---|---|
| `evidence_id` | 근거 ID |
| `source_id` | 고정 원본 ID |
| `source_start`, `source_end` | 원본 기준 후보 범위 |
| `frame_asset_ids` | 재사용한 원본 프레임 자산 ID |
| `event_type` | 진입, 탐색, 조우, 추격, 실패, 규칙 발견, 이완 등 |
| `audience_interest` | 원작·장르 공간·캐릭터 반응 등 검증할 관심 연결 |
| `planning_opportunity` | 기획에서 사용할 수 있는 가능성과 한계. 메시지 확정 금지 |
| `screen_evidence` | 화면에서 보이는 것 |
| `subtitle_evidence` | 대사 근거 |
| `audio_evidence` | 비명, 웃음, 침묵, 긴장 |
| `context_needed` | 앞뒤 맥락 필요 여부 |
| `hook_potential` | 오픈 루프 후보 여부 |
| `risk` | 화면 약함, 반응 잘림, 중복, 공략 과다, 자막 어긋남 |
| `decision` | 핵심 근거, 보조 근거, 제외, 재검증 |

판정 기준:

- 핵심 근거: 해당 사건·감정·관심 연결을 가장 잘 보여주는 장면.
- 보조 근거: 핵심 근거가 약하거나 다른 관점이 필요할 때 보완하는 장면.
- 제외: 같은 기능 반복, 화면 약함, 분석 질문과 무관한 장면.
- 재검증: 화면·자막·오디오가 충돌하거나 경계가 불명확한 장면.

### 5. 시청각 충돌 점검

아래 상황은 반드시 위험으로 표시한다.

- 대사는 중요하지만 화면이 밋밋하다.
- 화면은 강하지만 어떤 시청자 관심이나 인물 변화 근거인지 설명할 수 없다.
- 자막 타임코드와 실제 발화·화면 사건이 어긋난다.
- 사건 화면은 있는데 직후 반응이 빠져 있다.
- 시청자 조언·공략 설명이 길어져 주인공 변화가 묻힌다.
- 같은 기능의 비명, 실패, 탐색이 중복으로 남아 있다.

### 6. 영상 기획 인계 브리프 작성

데이터 분석 끝에는 컷리스트나 스파인이 아니라 다음 영상 기획 단계용 근거 브리프를 만든다.

포함:

- 사건·감정 유형별 핵심 근거
- 시청자 관심 가설별 핵심·보조·반증 근거
- 인물 변화로 해석할 수 있는 원본 순서
- 반복·저정보·관련 없는 근거
- 기획에서 단정하면 안 되는 불확실성
- 화면 확인 완료/미완료 표시

## 화면 판정 기준

### 사건 시작

아래 중 하나가 보이면 사건 시작 후보로 잡는다.

- 새 공간 진입
- 게임 플레이 화면으로 전환
- 적/엔티티 등장
- 추격 시작
- 퍼즐·문·장치와 상호작용 시작
- 시청자 조언을 받아 행동을 바꾸는 순간

### 사건 결과

아래 중 하나가 보이면 결과 후보로 잡는다.

- 사망, 실패, 클리어, 탈출, 다음 구역 진입
- 결과표, 테이프 화면, 챕터 전환
- 규칙 발견 후 안전 확보
- 대기방/시작 지점 복귀
- 직후 소감 또는 반응

### 보존 규칙

- 사건 전 맥락 발화가 있으면 필요한 만큼만 보존한다.
- 결과 화면과 직후 반응은 함께 판단한다.
- 질문/대답, 원인/반응은 함께 보존한다.
- 게임 한 판의 결과가 중요하면 시작, 진행, 결과, 후속 반응을 함께 보존한다.
- 대기방, 설정, 반복 탐색, 공략 설명은 기획서 기능이 없으면 줄인다.

## 저장 위치

화면을 확인한 구간은 반드시 Markdown과 가능하면 CSV로 저장한다. 원본 프레임은 영상별 공용 자산으로 등록한다.

권장 위치:

- `outputs/06_analysis/*_data_evidence_map_YYYY-MM-DD.md`
- `outputs/06_analysis/*_data_evidence_map_YYYY-MM-DD.csv`
- `outputs/06_analysis/source_asset_manifest.csv`
- `outputs/06_analysis/source_assets/<source_id>/`

검토 HTML과 접촉 시트는 공용 자산 경로를 참조한다. 같은 장면을 작업별 폴더에 복제하지 않는다.

## 완료 게이트

### G1. 원본·질문 추적성

통과:
- 모든 핵심 근거가 데이터 분석 질문과 원본 시간에 연결된다.

실패:
- "재밌어서", "리액션이 커서"만으로 들어간 근거가 있다.

### G2. 화면 증거

통과:
- 핵심 근거에는 화면 근거가 있다.
- 화면 근거가 없는 대사 중심 근거는 그 이유가 기록되어 있다.
- 화면 근거가 원본 `source_id`와 원본 시간/프레임으로 역추적된다.
- 보존한 모든 화면·오디오 파일이 `source_asset_manifest.csv`에 등록되어 있다.

실패:
- 대사만 보고 화면 검증 완료로 처리한다.

### G3. 맥락 보존

통과:
- 사건, 결과, 반응의 보존 필요 여부가 기록되어 있다.

실패:
- 사망, 조우, 규칙 발견, 엔딩 구간에서 직전 사건이나 직후 반응이 빠진다.

### G4. 중복 정리

통과:
- 같은 기능의 근거는 핵심/보조/제외로 구분되어 있다.

실패:
- 비슷한 비명, 실패, 탐색이 모두 후보로 남아 있다.

### G5. 영상 기획 인계 가능성

통과:
- 다음 영상 기획 단계가 시청자 약속, 중심 논지, 인물 변화를 기획할 수 있도록 핵심·보조·반증 근거가 기록되어 있다.

실패:
- 근거표는 있지만 어떤 기획 질문에 답하는지 알 수 없다.

### G6. 기준본과 재실행

통과:
- 같은 입력의 재실행은 기존 후보지도와 자산을 재사용한다.
- 변경된 입력이나 판단이 있을 때만 새 버전을 만들고, 게이트 통과 후 `CURRENT.json`을 갱신한다.

실패:
- 날짜나 실행 횟수만 바뀌었는데 새 후보지도·캡처를 만든다.

## 후속 단계 연결

데이터 분석 산출물은 다음 영상 기획 단계의 입력이다. 컷리스트, XML, EDL, 러프컷은 여기서 만들지 않는다.

## 다음 단계 전달물

영상 기획 단계에는 현재 근거지도 경로, `source_id`, 원본 지문, 원본 시간 범위,
`frame_asset_ids`, `source_asset_manifest.csv`, `CURRENT.json`과 데이터 게이트 상태를 넘긴다.

영상 기획 단계에서는 먼저 근거 지도의 `decision`, `event_type`, `audience_interest`,
`planning_opportunity`, `risk`를 확인한다. 결과가 이상하면 원본을 다시 무작정 보지 말고 먼저 근거 질문과 판정을 수정한다.

## 중단 조건

- 원본이 후반부까지 읽히지 않는다.
- 데이터 분석 질문과 화면·음성 근거가 충돌한다.
- 후보 구간의 화면 근거가 자막과 충돌한다.
- 사건의 시작/결과/반응을 화면으로 구분할 수 없다.
- 같은 후보가 두 번 이상 "포인트 누락" 또는 "필요 없는 부분 과다"로 실패한다.

이 경우 계속 후보를 늘리지 말고, 원본 상태, 분석 질문, 화면 검증 방식 중 무엇이 문제인지 먼저 확인한다.

## AI가 확정하지 말 것

- 영상의 최종 메시지와 스파인
- 컷 경계
- 컷리스트
- XML, EDL, 러프컷
- 영상의 최종 재미 판단
- 화면 검증 없이 대사만으로 후보 확정
