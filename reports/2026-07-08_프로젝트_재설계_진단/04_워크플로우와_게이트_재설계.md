# 04. 워크플로우와 게이트 재설계

## 1. 문제 정의

이전 워크플로우는 1~8단계의 큰 흐름은 있었지만, 각 단계가 다음 단계로 넘어가도 되는지 확인하는 게이트가 약했다.

그 결과:

1. 기획이 확정되기 전에 분석과 컷 후보가 생겼다.
2. 후보 검증이 끝나기 전에 컷리스트와 XML 같은 후속 산출물이 생겼다.
3. 기술적으로 생성된 결과물이 콘텐츠 품질을 통과한 것처럼 취급됐다.
4. 사용자가 불만족해도 작업이 멈추지 않고 문서나 산출물만 늘었다.

따라서 워크플로우는 "순서표"가 아니라 "게이트 시스템"이어야 한다.

## 2. 게이트 방식의 기본 구조

각 단계는 아래 6개 요소를 가져야 한다.

```text
입력
↓
작업
↓
산출물
↓
게이트 검수
↓
사용자 승인 또는 재작업
↓
다음 단계 전달물
```

중요한 점은 산출물이 생겼다고 다음 단계로 넘어가는 것이 아니라, 게이트를 통과해야 넘어간다는 것이다.

## 3. 단계별 게이트 초안

| 단계 | 목적 | 게이트 |
|---:|---|---|
| 1 | 소재 조사 | 후보가 최신 근거, 수요, 채널 적합도, 제외 이유를 가진다. |
| 2 | 채널 기획 | 김실버 관점, 시청자 클릭 이유, 핵심 주장, 차별화 각도가 명확하다. |
| 3 | 대본 구성 | 주장 흐름과 근거가 연결되고 촬영/영상 내용과 충돌하지 않는다. |
| 4 | 자막 생성/정리 | 원문 보존, 정리본 구분, 타임코드 신뢰도가 표시된다. |
| 5 | 대사 기반 영상 기획 | 컨트롤링 아이디어가 원본 대사로 추적되고, 대사 스파인이 성립한다. |
| 6 | 영상 분석 | 후보 장면이 기획서 비트와 연결되고 화면/자막/오디오 근거가 있다. |
| 7 | 편집 자료 생성 | 컷리스트가 최신 기준이고 XML/EDL/러프컷의 기술 검증이 분리된다. |
| 8 | 최종 검수 | 완성본이 기획 의도, 흐름, 오디오, 자막, 원본 보호를 통과한다. |

## 4. 각 단계의 출력 규칙

각 단계는 다음 단계가 바로 이해할 수 있는 전달물을 남겨야 한다.

예:

| 단계 | 다음 단계 전달물 |
|---:|---|
| 1 | 소재 후보표와 추천/제외 이유 |
| 2 | 영상 콘셉트와 핵심 주장 |
| 3 | 대본 구조와 장면 목적 |
| 4 | 원본 자막, 정리 자막, 신뢰도 표시 |
| 5 | 컨트롤링 아이디어, 대사 스파인, 6단계 검증 브리프 |
| 6 | 후보지도, 대표/예비/제외 후보, 7단계 인계 브리프 |
| 7 | 컷리스트, XML/EDL/CSV, 사용 방법, 검증 수준 |
| 8 | 최종 검수표, 수정 필요 목록 |

## 6. 프로젝트에 필요한 적용안

1. `01_유튜브_제작_워크플로우.md`를 단계 지도와 게이트 중심으로 재작성한다.
2. 각 단계 스킬에는 `입력`, `출력`, `게이트`, `중단 조건`, `다음 단계 전달물`을 둔다.
3. 단계별 산출물은 `workspace/outputs/<단계명>/`에 저장한다.
4. 게이트를 통과하지 못하면 다음 단계 산출물을 만들지 않는다.
5. 사용자 판단이 필요한 게이트를 명시한다.

## 8. 적용하지 말아야 할 방식

1. 1~8단계를 한 번에 자동 진행하지 않는다.
2. 게이트를 통과하지 않은 산출물을 다음 단계 입력으로 쓰지 않는다.
3. 러프컷을 먼저 만들고 기획을 끼워 맞추지 않는다.
4. "기술적으로 생성됨"을 "영상으로 좋음"으로 취급하지 않는다.
5. 사용자 불만족이 반복되는데 같은 방식으로 재생성하지 않는다.
