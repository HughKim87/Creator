## 1. 문제 정의

이전 작업에서는 요청이 크고 넓었다.

예:

```text
이 영상 편집해줘.
좋은 장면 뽑아줘.
워크플로우대로 진행해줘.
```

이런 요청은 AI가 알아서 판단해야 하는 범위를 너무 크게 만든다. AI는 그럴듯한 구조를 만들 수는 있지만, 사용자가 원하는 품질과 취향을 안정적으로 맞추지 못한다.

따라서 프롬프트는 부탁이 아니라 작업 계약에 가까워야 한다.

## 2. 좋은 작업 요청의 조건

좋은 작업 요청은 아래를 포함해야 한다.

1. 이번 작업의 단계
2. 사용할 입력
3. 현재 기준 파일
4. AI가 할 일
5. AI가 하지 말 일
6. 출력 형식
7. 판단 기준
8. 멈출 조건

## 3. 기본 프롬프트 템플릿

```markdown
## 작업 요청

단계:
목표:
입력:
현재 기준 파일:

AI가 할 일:
- 

AI가 하지 말 일:
- 

출력 형식:
- 

판단 기준:
- 

멈출 조건:
- 
```

이 템플릿은 길게 쓰기 위한 것이 아니라, AI가 범위를 벗어나지 않게 하는 안전장치다.

## 4. 영상 작업용 프롬프트 예시


## 6. 프로젝트에 필요한 적용안

1. 단계별 프롬프트 템플릿을 만든다.
2. 모든 스킬 문서에 "사용자가 이렇게 요청하면 좋다" 예시를 둔다.
3. 큰 요청을 받으면 AI가 먼저 작업 범위를 축소해서 제안한다.
4. 출력 형식을 표준화한다.
5. "하지 말 일"을 프롬프트에 반드시 포함한다.
6. 사용자가 불만족하면 같은 프롬프트로 재생성하지 않고, 프롬프트 조건부터 바꾼다.

## 7. 적용하지 말아야 할 방식

1. "알아서 잘 해줘" 방식으로 긴 작업을 시작하지 않는다.
2. 한 프롬프트에서 기획, 분석, 컷리스트, XML을 모두 요청하지 않는다.
3. 출력 형식 없이 자유 서술로 맡기지 않는다.
4. AI에게 "좋은 장면"을 바로 판단하게 하지 않는다.
5. 실패한 프롬프트를 수정 없이 반복하지 않는다.
