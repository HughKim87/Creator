지금 당장 영상 작업으로 돌아가면 같은 문제가 반복될 가능성이 높다.

먼저 해야 할 일은 새 영상 편집이 아니라, AI가 안정적으로 일할 수 있는 프로젝트 운영 구조를 만드는 것이다.

다만 구조 재설계도 너무 크게 하면 다시 문서만 늘어난다. 따라서 적용은 작은 순서로 진행해야 한다.

## 5. 3차 실행 범위

3차 목표는 새 영상 작업을 실제로 테스트하는 것이다.

조건:

1. 새 원본 영상이 있다.
2. 새 원본 자막이 있다.
3. `CURRENT_TASK.md`가 있다.
4. 현재 기준 파일이 지정되어 있다.
5. 단계별 게이트가 있다.

테스트 방식:

1. 전체 영상이 아니라 5~10분 샘플로 시작한다.
2. 자막 분석 → 후보 추출 → 화면 검증 → 컷 후보 정리까지만 한다.
3. XML이나 러프컷은 만들지 않는다.
4. 사용자가 후보 품질을 확인한 뒤에만 다음 단계로 간다.

## 7. 작업 순서 제안

### 1단계: 운영 구조 최소 재정리

작업:

1. `PROJECT_RULES.md`를 더 줄인다.
2. `문서_인덱스.md`에 문서 상태 체계를 추가한다.
3. `CURRENT_TASK.md` 초안을 만든다.
4. `SESSION_HANDOFF.md`를 현재 작업 중심으로 줄인다.

완료 조건:

1. 세션 시작 시 읽을 문서가 명확하다.
2. 긴 보고서는 기본 로드 대상이 아니다.
3. 현재 작업과 하지 않을 일이 한눈에 보인다.

### 2단계: 워크플로우 게이트 정리

작업:

1. `01_유튜브_제작_워크플로우.md`를 게이트 중심으로 정리한다.
2. 각 단계의 입력, 출력, 사용자 승인 지점을 명시한다.

완료 조건:

1. 어떤 조건에서 다음 단계로 넘어가는지 명확하다.
2. AI가 임의로 후속 산출물을 만들 수 없다.

### 3단계: 1단계 스킬부터 보강

작업:

1. `game-trend-research`를 리서치 출처, 최신성, 점수화, 제외 기준 중심으로 보강한다.

완료 조건:

1. "인기 게임 목록"이 아니라 "김실버 채널용 영상 소재 후보"가 나온다.
2. 출처와 약한 주장 표시가 있다.
3. 사용자가 최종 선택할 수 있는 표가 나온다.

### 4단계: 작은 샘플로 검증

작업:

1. 실제 영상 전체가 아니라 짧은 샘플로 5~6단계만 테스트한다.
2. AI의 후보 추출 품질을 사용자가 확인한다.

완료 조건:

1. 기획 기준과 화면 검증 결과가 연결된다.
2. 산출물이 다음 단계에 쓸 수 있는지 판단된다.

## 8. 즉시 하지 말아야 할 일

1. 새 영상 전체 편집을 시작하지 않는다.
2. XML, EDL, 러프컷을 만들지 않는다.
3. 스킬을 한꺼번에 전부 고치지 않는다.
4. 긴 통합 문서를 새로 만들지 않는다.
5. 백업 폴더를 만들지 않는다.
6. 외부 도구를 도입하기 전에 프로젝트 내부 운영 규칙부터 고친다.

## 9. 최종 제안

다음 실제 작업은 1단계 소재 조사 개선이 아니라, 아래 순서가 맞다.

```text
CURRENT_TASK.md 도입
↓
문서 상태 체계 정리
↓
워크플로우 게이트 정리
↓

↓
작은 샘플 검증
↓
새 영상 작업 재개
```
