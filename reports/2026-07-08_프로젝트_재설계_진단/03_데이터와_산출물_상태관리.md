# 03. 데이터와 산출물 상태관리

- 작성일: 2026-07-08

- 적용 필요성: 필수

## 1. 문제 정의

이전 실패에서 가장 치명적인 문제 중 하나는 산출물이 계속 기준처럼 남았다는 점이다.

AI는 폴더 안에 파일이 있으면 그것을 현재 작업에 사용할 수 있는 자료로 오해하기 쉽다. 특히 `workspace/outputs/`, `temp/archive/`, 과거 컷리스트, 과거 XML, 과거 러프컷이 남아 있으면 현재 기준과 섞인다.

따라서 파일은 위치뿐 아니라 상태를 가져야 한다.

## 2. 데이터 상태 분류

김실버 프로젝트에는 아래 상태 체계가 필요하다.

| 상태 | 의미 | AI 사용 가능 여부 |
|---|---|---|
| 원본 | 사용자가 제공한 영상, 자막, 자료 | 읽기만 가능. 수정 금지 |
| 기준 입력 | 현재 단계의 판단 기준 | 사용 가능 |
| 작업 산출물 | 현재 단계에서 만든 결과 | 다음 단계 사용 전 검증 필요 |
| 참고 자료 | 배경 이해용 | 직접 기준으로 사용 금지 |
| 검증 자료 | 프레임, 로그, 검사 결과 | 근거로 사용 가능 |
| 폐기 | 더 이상 사용하지 않음 | 읽지 않음 |
| 보류 | 정확성 미확정 | 사용자 확인 전 사용 금지 |

## 3. 산출물 메타데이터

모든 중요한 산출물에는 아래 메타데이터가 있어야 한다.

```markdown
## 산출물 상태

- 상태:
- 생성일:
- 생성 목적:
- 기준 입력:
- 사용한 원본:
- 사용한 기준 문서:
- 생성 도구:
- 검증 수준:
- 다음 단계 사용 가능 여부:
- 사용 금지 조건:
```

이 메타데이터는 길게 쓰기 위한 것이 아니다. AI가 파일을 열었을 때 이 파일을 어떻게 취급해야 하는지 바로 알게 하기 위한 장치다.

## 4. 폴더 구조 제안

```text
workspace/
  inputs/
    video/
    subtitles/
    references/
  active/
    CURRENT_TASK.md
    current_source.lock.md
  outputs/
    01_research/
    02_planning/
    03_script/
    04_subtitles/
    05_video_plan/
    06_analysis/
    07_edit_export/
    08_review/
  rejects/
    do_not_use_index.md
```

중요한 점:

1. `inputs/`는 원본만 둔다.
2. `active/`는 현재 작업 기준만 둔다.
3. `outputs/`는 단계별 결과만 둔다.
4. `rejects/`는 폐기된 판단을 명시한다.
5. `temp/`는 가능하면 사용하지 않는다. 꼭 필요할 때만 임시 프레임이나 로그를 둔다.

## 5. 현재 기준 파일 잠금

현재 단계가 믿는 기준 파일은 하나여야 한다.

예:

```markdown
# current_source.lock.md

현재 단계: 6단계 영상 분석
현재 기준 파일: workspace/outputs/05_video_plan/백룸_5단계_기획서.md
원본 영상: workspace/inputs/video/백룸.mkv
원본 자막: workspace/inputs/subtitles/백룸.srt
사용 금지:
- workspace/outputs/old/
- temp/archive/
- 이전 컷리스트
```

이 파일이 없으면 AI는 과거 산출물을 기준처럼 사용할 위험이 있다.

## 6. 외부 자료와의 연결

DVC의 데이터 파이프라인 방식은 단계별 입력, 출력, 의존성을 기록해 재현 가능하게 관리한다. 김실버 프로젝트에 DVC를 바로 도입할 필요는 없지만, "어떤 입력에서 어떤 출력이 만들어졌는지"를 기록하는 원칙은 반드시 가져와야 한다.

출처: https://doc.dvc.org/start/data-pipelines

DVC 실험 관리 자료도 코드, 데이터, 지표, 파라미터, 결과를 함께 추적하는 구조를 강조한다.

출처: https://doc.dvc.org/start/experiments

Git LFS는 대용량 영상 파일을 Git 바깥에 두고 포인터만 관리하는 방식이다. 다만 지금 프로젝트는 대용량 원본을 Git에 넣지 않는 운영이 우선이므로 도입은 보류한다.

출처: https://git-lfs.com/

## 7. 프로젝트에 필요한 적용안

1. 산출물 상태 메타데이터를 모든 주요 Markdown/CSV 결과에 붙인다.
2. 단계별 output 폴더를 고정한다.
3. `current_source.lock.md` 같은 현재 기준 잠금 파일을 도입한다.
4. 폐기된 자료는 삭제 여부와 별개로 `do_not_use_index.md`에 기록한다.
5. `workspace/outputs/`의 파일은 자동으로 기준이 되지 않게 한다.
6. 기준 파일이 바뀌면 파생 산출물은 `Superseded` 상태로 표시한다.

## 8. 적용하지 말아야 할 방식

1. 과거 산출물을 "혹시 쓸 수 있으니" 기본 로드하지 않는다.
2. `temp/archive/`를 사실상 보관소로 쓰지 않는다.
3. 파일명만 보고 최신 기준을 판단하지 않는다.
4. 생성 시각만으로 기준성을 부여하지 않는다.
5. 도구가 만든 결과를 검증 없이 다음 단계 입력으로 사용하지 않는다.
