## 1. 문제 정의

이번 실패의 중요한 원인은 AI의 한계를 프로젝트 구조에서 제대로 보완하지 못한 것이다.

AI에게 "잘 읽어라", "정확히 판단해라", "맥락을 잃지 마라"라고 규칙을 쓰는 것만으로는 부족하다. AI는 긴 문서, 많은 산출물, 애매한 기준, 반복 수정, 오래된 자료가 섞인 환경에서 쉽게 기준을 잃는다.

따라서 프로젝트는 AI가 잘못하기 쉬운 상황을 구조적으로 줄여야 한다.

## 2. AI 특성별 실제 문제와 보완책

| AI 특성 | 실제로 생긴 문제 | 프로젝트 보완책 |
|---|---|---|
| 긴 문서를 끝까지 안정적으로 반영하지 못함 | 앞부분, 최근 문장, 강한 표현만 붙잡고 핵심 기준을 놓침 | 현재 작업 패킷을 별도 운영한다. 기준 문서는 짧고 역할별로 쪼갠다. |
| 많은 문서에서 기준을 혼동함 | 참고 자료, 과거 산출물, 현재 기준을 섞음 | `현재 기준 파일`을 단계마다 하나만 지정한다. |
| 그럴듯하게 말함 | 실제 근거 없이 "정리됐다", "검증됐다"처럼 표현함 | 산출물마다 입력, 근거, 검증 수준을 기록한다. |
| 실패해도 계속 진행하려 함 | 잘못된 방향으로 컷리스트, XML, 러프컷이 누적됨 | 같은 방향 2회 실패 시 생성 금지, 원인 재분류로 전환한다. |
| 추상 규칙을 좋아함 | 작업 개선 대신 문서가 길어짐 | 문서 길이 제한과 새 문서 생성 조건을 둔다. |
| 긴 영상 이해가 약함 | 전체 영상을 이해한 것처럼 요약함 | 구간 단위 후보, 프레임 근거, 자막 근거를 분리한다. |
| 취향 판단이 불안정함 | "재미있다", "살릴 만하다"를 일반론으로 판단함 | AI는 후보와 근거를 정리하고, 최종 선택은 사용자가 한다. |
| 이전 맥락 오염 | 폐기한 산출물을 다시 참고함 | 폐기 목록과 읽지 말 것 목록을 명시한다. |
| 도구 성공을 품질 성공으로 착각함 | XML 생성 성공을 좋은 편집으로 착각함 | 기술 검증과 콘텐츠 검증을 분리한다. |
| 프롬프트마다 행동이 달라짐 | 세션마다 다른 작업 방식으로 흘러감 | 단계별 고정 템플릿과 출력 형식을 만든다. |

## 3. 외부 자료와의 연결

Context Engineering 자료는 프롬프트보다 모델이 판단하는 정보 환경이 중요하다고 본다. 특히 relevance, sufficiency, isolation, economy, provenance가 중요하다.

김실버 프로젝트에 적용하면 다음과 같다.

| 기준 | 프로젝트 적용 |
|---|---|
| relevance | 현재 단계에 필요한 문서만 읽게 한다. |
| sufficiency | 단계 수행에 필요한 입력과 기준은 빠뜨리지 않는다. |
| isolation | 기준 파일, 참고 자료, 폐기 자료를 분리한다. |
| economy | 문서는 짧게 유지하고 중복을 없앤다. |
| provenance | 산출물이 어떤 입력과 판단에서 나왔는지 남긴다. |

출처: https://arxiv.org/abs/2603.09619

## 4. 프로젝트에 반드시 적용할 내용

1. `현재 작업 패킷` 개념을 도입한다.
   - 세션마다 긴 문서를 모두 읽게 하지 않는다.
   - 현재 목표, 기준 파일, 금지 작업, 입력, 출력, 검증 조건만 짧게 제공한다.

2. 단계마다 `현재 기준 파일`을 하나만 둔다.
   - 예: 5단계 작업 중이면 5단계 기획서가 기준이다.
   - 후보표, 러프컷, XML은 기준이 아니라 파생 산출물이다.

3. 모든 산출물에 `근거 추적` 섹션을 둔다.
   - 입력 파일
   - 사용한 기준 문서
   - 판단 근거
   - 검증 수준
   - 다음 단계 사용 가능 여부

4. AI의 임의 판단 금지 구역을 표시한다.
   - 영상 메시지 최종 확정
   - 채널 톤 최종 결정
   - 편집감 최종 승인
   - 썸네일/제목 최종 선택

5. AI가 맡을 수 있는 반복 작업은 적극 자동화한다.
   - 후보 추출
   - 표 정리
   - 구간 비교
   - 자막/프레임 근거 연결
   - XML/CSV 생성
   - 형식 검증

## 5. 적용하지 말아야 할 방식

1. "규칙을 더 자세히 쓰면 AI가 잘할 것"이라는 접근은 피한다.
2. 긴 문서를 하나로 합쳐서 모든 내용을 담지 않는다.
3. AI가 전체 영상을 한 번에 이해한다고 가정하지 않는다.
4. 기술 산출물 생성 성공을 콘텐츠 품질 검증으로 취급하지 않는다.
5. 불만족이 반복될 때 계속 수정하지 않는다.
