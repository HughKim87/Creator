## 1. 문제 정의

현재 프로젝트는 많이 정리됐지만, 앞으로 다시 작업을 시작하면 문서와 산출물이 다시 섞일 위험이 있다.

특히 아래가 반복되면 다시 실패한다.

1. 규칙 문서가 길어진다.
2. 핸드오프가 규칙처럼 쓰인다.
3. 문서 인덱스가 모든 파일 목록이 된다.
4. 스킬이 전체 워크플로우를 반복한다.
5. 산출물이 기준처럼 사용된다.
6. 임시 파일이 사실상 보관소가 된다.

파일 구조는 AI가 봐도 역할을 바로 알 수 있어야 한다.

## 4. 추가해야 할 핵심 파일

### 4.1 `CURRENT_TASK.md`

현재 작업 패킷이다. AI가 매번 짧게 현재 목표를 잡는 용도다.

초안:

```markdown
# CURRENT_TASK.md

- 현재 단계:
- 현재 목표:
- 현재 기준 파일:
- 입력:
- 출력:
- 하지 않을 일:
- 검증 기준:
- 멈출 조건:
```

### 4.2 `workspace/active/current_source.lock.md`

현재 단계의 기준 입력 잠금 파일이다.

초안:

```markdown
# current_source.lock.md

- 현재 단계:
- 기준 원본:
- 기준 자막:
- 기준 기획서:
- 기준 후보지도:
- 읽지 말 것:
- 파생 산출물 상태:
```

### 4.3 `workspace/rejects/do_not_use_index.md`

폐기한 산출물을 다시 읽지 않기 위한 목록이다.

초안:

```markdown
# do_not_use_index.md

| 파일/폴더 | 폐기 이유 | 폐기일 | 대체 기준 |
|---|---|---|---|
```

## 5. 현재 문서에서 조정이 필요한 부분

| `SESSION_HANDOFF.md` | 다음 작업과 현재 상태만 남기고 길어지지 않게 유지 |
| `문서_인덱스.md` | 문서 상태와 읽는 조건 중심으로 재구성 |
| `01_유튜브_제작_워크플로우.md` | 게이트와 단계 전달물 중심으로 단순화 |
| `skills/README.md` | 스킬 공백과 보강 순서 표시 |

## 6. 적용하지 말아야 할 방식

1. `reports/`의 긴 문서를 기본 로드하지 않는다.
2. `temp/`를 보관소로 쓰지 않는다.
3. 단계별 산출물을 프로젝트 루트에 두지 않는다.
4. 새 문서를 만들 때마다 인덱스 없이 방치하지 않는다.
5. 파일명이 최신처럼 보여도 기준으로 자동 인정하지 않는다.

## 7. 외부 자료와의 연결

AnimAgents 연구는 단계별 보드와 요소 단위 산출물 관리가 창작 워크플로우의 일관성과 통제에 유리하다고 설명한다.

출처: https://arxiv.org/abs/2511.17906

DVC 파이프라인 문서는 단계별 입력과 출력, 의존성을 기록해 재현 가능하게 만드는 구조를 제공한다.

출처: https://doc.dvc.org/start/data-pipelines
