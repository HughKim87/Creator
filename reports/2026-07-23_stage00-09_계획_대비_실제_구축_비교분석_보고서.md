- 작성일: 2026-07-23
- 범위: [마스터 구축 계획](../docs/build/MASTER_BUILD_PLAN.md)과 11개 단계 계획 문서에 정의된 계획 대비 Stage 00~09의 실제 산출물·검증·커밋
- 비교 기준 정본: `docs/build/MASTER_BUILD_PLAN.md`와 `docs/build/stage-*.md` 11개
- 실제 근거: 저장소 추적 파일, 경계 커밋 이력, 테스트 독립 재실행, `data/` 구조화 기록, `maintenance-verify` 실제 실행
- 작성 주체: 프로젝트 에이전트(독립 세션). 이 문서는 시점 증거이며 현재 상태 정본은 [SESSION_HANDOFF](../SESSION_HANDOFF.md)다.

## 1. 결론 요약

계획된 11개 단계(00, 01, 01.5, 02~09)는 모두 실제 산출물·검증 기록·경계 커밋과 함께 구현됐다. 단계 순서와 선행 의존성은 마스터 계획 §3 단계 지도와 일치하고, 각 단계의 제외 범위(미래 기능 선행 유입 금지)는 실제 코드·파일 기준으로 준수됐다. 미승인 편차는 발견하지 못했다.

계획과 실제의 차이는 대부분 사용자가 2026-07-23 승인한 상시 정책(미확정 선택의 권장안 자동 선택, 단계 성공 게이트 후 자동 전환, Stage 01~03 누적 커밋)으로 설명되며 각 단계 문서의 사용자 결정 기록에 남아 있다. 경미한 관찰 사항은 §6에 정리했다(단계 문서 헤더 상태줄의 시점 고착 등 3건).

## 2. 비교 방법

1. 마스터 계획 §3 단계 지도·§5 공통 문서 계약·§6 공통 게이트를 계획 기준으로 읽었다.
2. 11개 단계 계획 문서의 구현할 기능·예상 산출물·제외 범위·완료 조건을 각 단계의 실제 파일·커밋과 대조했다.
3. 실제 검증은 문서 주장에 의존하지 않고 독립 재실행했다: 전체 테스트 재실행, `maintenance-verify` 실행, 경계 커밋별 파일·테스트 수 조회, 구조화 record 전수 파싱.
4. 재실행 환경은 격리된 Linux 샌드박스(Python 3.10, `datetime.UTC` 호환 조정)이며 원본 폴더는 읽기 전용으로 다뤘다. 실행 전후 `git status` 차이 0건을 확인했다.

## 6. 경미한 관찰 사항

1. 단계 문서 헤더의 `상태:` 줄이 단계 종료 시점에 고착돼 있다. `stage-04`~`stage-09`는 "경계 커밋 대기", `stage-00`은 "커밋 승인 대기"로 남아 있으나 실제 커밋은 모두 존재한다. 현재 상태 정본은 핸드오프라는 소유 규칙 덕분에 기능적 충돌은 없지만, 마스터 §5 문서 계약의 상태 항목과 현재 사실이 표면상 어긋난다.
2. 프로젝트는 Python 3.12 표준 라이브러리를 전제한다(`from datetime import UTC`는 3.11 미만에서 동작하지 않음). 승인된 실행 환경 결정과 일치하므로 결함은 아니며, 다른 런타임에서 재실행할 때의 이식성 제약으로만 기록한다.
3. 최종 복기 보고서 §3 표는 Stage 00 커밋을 `8dc034e` 하나로 표기하며 후속 정리 커밋 `6dd4ea9`는 언급하지 않는다. 사실 왜곡은 아니고 표기 단순화다.

## 8. 종합 판정

계획 문서 체계(마스터 계획 + 단계 계획)와 실제 구축 결과 사이에 실질적 괴리는 없다. 계획이 요구한 산출물은 전부 실재하고, 계획이 금지한 기능은 전부 부재하며, 계획이 정의한 게이트는 전 단계에서 기록과 함께 이행됐다. 편차는 승인 이력이 추적되는 절차 대체(상시 승인)에 한정된다. §6의 관찰 3건은 문서 표기 수준이며 사용자가 원할 때 단계 문서 상태줄 일괄 정리로 해소할 수 있다.
