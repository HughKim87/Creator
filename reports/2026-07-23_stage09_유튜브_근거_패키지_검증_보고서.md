## 1. 검증 목적과 범위

공통 지식 운영 기반을 수정해 유튜브 필드를 섞지 않고, 별도 도메인 adapter가 현재 문서·record·source 상태를 사용해 하나의 촬영 전 evidence pack을 실제로 만들 수 있는지 확인했다.

검증한 첫 작업은 [명시 예시 요청](../examples/youtube/stage09-foundation-evidence.request.json)의 근거 패키지 생성이다. 대본·썸네일·촬영·편집·게시, 외부 앱, `inputs/`·`outputs/`, 결과 파일 저장, 창작 방향 승인은 범위에서 제외했다.

## 2. 실제 입력과 실행

- video ID: `stage09-foundation-context`
- 작업 제목: `AI 작업 기억을 가볍게 만드는 선택적 컨텍스트`
- 대상: 반복 제작에서 AI 작업 기억 비용을 줄이고 싶은 1인 크리에이터
- 직접 문서: `docs/CONTEXT_PACKAGE_CONTRACT.md`

- 비교 기준선: 315,497 Unicode 문자

같은 요청을 같은 활성 정본에서 두 번 실행했고 stdout JSON을 byte 단위로 비교했다. 실행 전후 lifecycle·work event 파일 hash도 비교했다.

## 5. 발견·해결한 실패

- 중첩된 미추적 도메인 Markdown을 기본 `git status --short`가 디렉터리로 축약해 inventory가 놓친 문제를 발견했다. `--untracked-files=all`과 회귀 테스트로 보정하고 [Windows 문서 검증 명령의 환경·문구 가정](../failures/windows-validation-command-assumptions.md)에 병합했다.
- Python AST 검사가 `src/file_data`만 대상으로 삼아 별도 `src/youtube_domain`을 누락한 문제를 발견했다. `src/**/*.py` 검사와 도메인 패키지 문법 오류 회귀를 추가하고 [구현 폴더와 정보 구조 계약의 드리프트](../failures/structure-contract-folder-drift.md)에 병합했다.
- 두 문제 모두 보정 뒤 전용 회귀와 누적 95개 테스트를 다시 실행해 성공했다. 현재 미해결 실패는 없다.

## 6. 잔여 위험과 다음 결정

- 예시 요청은 보호 사용자 원본이 아닌 프로젝트 자체 주제다. 실제 영상 원본 품질이나 외부 플랫폼 동작은 검증하지 않았다.
- adapter는 full context를 stdout으로 반환하므로 호출자가 결과를 외부로 보내거나 저장하는 작업은 별도 승인 대상이다.
- 작업 제목과 창작 방향은 사용자가 검토하기 전까지 승인된 제작 방향이 아니다.
- 지식 환류 절차는 candidate로만 등록하며 자동 current 승격하지 않는다.
