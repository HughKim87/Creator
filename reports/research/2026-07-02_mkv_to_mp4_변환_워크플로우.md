# MKV → MP4 변환 워크플로우 리서치 보고서

작성: 2026-07-02 | 배경: Premiere에서 `CRA_PLAY_EDIT_ASSIST_3P_TEST.xml` 가져오기 성공(빈 구조·시퀀스 생성 확인), 그러나 원본 `.mkv` 미디어 연결 실패("미디어 오프라인").

## 결론 요약

원본 mkv의 내부 코덱은 **H.264(High) + AAC(LC)**로, MP4 컨테이너와 완전히 호환된다.
따라서 재인코딩 없이 컨테이너만 바꾸는 **무손실 remux**가 가능하며, 이것이 1순위 권장 방법이다.
화질 손실 0, 처리 시간은 파일 복사 수준(수 분 이내)이다.

참고: 사용자가 언급한 "mp3 변환"은 오디오 전용 포맷이므로 영상 편집에는 부적합. **mp4 변환**이 올바른 방향이다.

## 원본 파일 분석 결과 (ffprobe, Syntax-validated)

| 항목 | 값 |
|---|---|
| 파일 | `workspace/inputs/crazy_arcade/2026-06-26 19-42-34.mkv` (약 6.69GB) |
| 컨테이너 | Matroska (mkv) |
| 비디오 | H.264 High, 1920x1080, yuv420p |
| 프레임레이트 | 60fps **고정(CFR)** — r/avg 모두 60/1, 30초 구간 패킷 1,800개로 교차 확인 |
| 오디오 | AAC LC, 48kHz, 2ch |
| 길이 | 8,682초 (02:24:42), 평균 비트레이트 약 6.2Mbps |

## 문제 원인

Premiere Pro는 버전과 무관하게 **MKV 컨테이너 자체를 지원하지 않는다**. 내부 코덱(H.264/AAC)은 Premiere가 지원하는 코덱이므로, 문제는 코덱이 아니라 컨테이너뿐이다. 이런 경우 표준 해법이 remux다.

## 방법 1 — 무손실 Remux (권장, 1순위)

컨테이너만 mkv → mp4로 교체. 비디오/오디오 스트림은 그대로 복사(`-c copy`).

```powershell
# 프로젝트 루트에서 실행 (프로젝트 내부 FFmpeg 사용 — Tier-2 규칙)
tools\ffmpeg\bin\ffmpeg.exe -i "workspace\inputs\crazy_arcade\2026-06-26 19-42-34.mkv" -c copy "workspace\inputs\crazy_arcade\2026-06-26_19-42-34_remux.mp4"
```

- 장점: 무손실, 6.7GB 기준 수 분 이내, 용량 거의 동일.
- 주의: 출력 파일명에서 공백을 `_`로 바꿔 경로 문제를 예방.
- OBS 자체 remux 기능(파일 메뉴)도 있으나, FFmpeg 직접 실행이 타임스탬프 처리에 더 안정적이라는 보고가 있음.

## 방법 2 — CFR 강제 재인코딩 (remux 후에도 싱크 문제 시)

MKV→MP4 remux 시 타임스탬프 해석 차이로 편집기가 VFR로 오인해 오디오 싱크가 밀리는 사례가 보고됨. 이 원본은 CFR로 확인됐지만, 만약 remux 결과물에서 싱크가 어긋나면 재인코딩으로 해결:

```powershell
tools\ffmpeg\bin\ffmpeg.exe -i "...remux 실패한 원본.mkv" -c:v libx264 -preset fast -crf 16 -r 60 -vsync cfr -c:a aac -b:a 192k "출력.mp4"
```

- CRF 16은 시각적 무손실 수준. 2시간 24분 원본이라 인코딩에 상당한 시간 소요.
- 대안 도구: HandBrake(Production 프리셋), Shutter Encoder.

## 방법 3 — 편집용 중간 코덱, 컷 구간만 변환 (구형 Premiere 재생 버벅임 시)

장시간 1080p60 H.264(long-GOP)는 구형 Premiere에서 스크럽/재생이 무거울 수 있다. 이 경우 전체(2.4시간, 중간 코덱 시 수십~수백 GB)가 아니라 **기준 컷리스트의 13개 구간만** 잘라서 변환하는 것이 효율적:

```powershell
# 예: 1번 컷 구간만 DNxHR LB로 추출
tools\ffmpeg\bin\ffmpeg.exe -ss 02:15:23 -to 02:17:42 -i "원본.mkv" -c:v dnxhd -profile:v dnxhr_lb -c:a pcm_s16le "cut01.mov"
```

- 단, 이 방식은 XML의 타임코드 기준이 원본 전체가 아닌 개별 클립으로 바뀌므로 `make_premiere_xml.py` 수정 필요. 방법 1·2가 모두 실패할 때만 검토.

## 변환 후 XML 재연결 — 2가지 경로

1. **XML 재생성(권장)**: `make_premiere_xml.py`로 원본 경로만 mp4로 바꿔 재생성. 구형 Premiere의 "미디어 연결(Link Media)"은 확장자가 다른 파일 재연결이 불안정할 수 있어 재생성이 안전.
2. **Premiere에서 직접 재연결**: 오프라인 클립 우클릭 → 미디어 연결 → remux된 mp4 지정. 성공하면 가장 빠름. 실패해도 손해 없음.

## 검증 절차 (Tier-1 Verification Levels 적용)

1. remux 실행 → ffprobe로 출력 파일 스트림/길이 일치 확인 (Syntax-validated)
2. 재생성 XML 가져오기 → 미디어 연결 확인
3. 시퀀스에서 앞/중간/끝 3지점 재생하며 **입모양·타격음 등으로 A/V 싱크 확인**
4. 3까지 통과 시에만 App-validated 표기 (규칙: Premiere 확인 전 "사용 가능 확정" 금지)

## 다음 작업 연결

- remux 성공 + XML 재연결 확인 후 → 핸드오프 2단계(기준 컷리스트 1번 컷 `02:15:23-02:17:42` 갱신 → 13컷 XML 재생성) 진행.
