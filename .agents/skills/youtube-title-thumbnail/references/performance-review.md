# 게시 영상 실적 진단

- 목적: 공개 metadata의 점검을 실적 분석으로 오인하지 않고, 실제 노출·클릭·시청 지표에서 개선 가설을 만든다.
- 읽는 시점: 특정 게시 영상의 SEO·클릭률·시청 지속 시간 또는 다음 영상으로의 학습 반영을 요청받을 때.
- 책임: 에이전트가 읽기 전용으로 근거와 한계를 확인하고 사용자가 수정·게시·실험 실행 범위를 결정한다.
- 상태: youtube-title-thumbnail의 조건부 실적 점검 절차.
- 관련 권위: ../SKILL.md와 대상 프로젝트의 영상 편집 owner. 이 문서는 채널 전체 진단·외부 쓰기 승인을 소유하지 않는다.

## 대상과 근거부터 확인

대화에 영상 URL·ID가 있으면 재사용한다. 없으면 연결된 Studio의 대상 영상이나 작업 기록에서 식별할 수 있는지 확인하고, 특정할 수 없을 때만 사용자에게 묻는다. 현재 제공되는 브라우저/connector 목록에서 연결된 Studio를 찾아 채널과 영상 ID를 대조한다. 다른 작업의 업로드·편집 화면은 건드리지 않고 필요한 경우 별도 분석 탭을 사용한다. 지원되지 않는 도구·접근을 추정하지 않는다.

SEO 요청에는 공개 제목·설명과 영상의 검색 의도를 확인하되, 성과 판단이 필요하면 도달범위·검색 유입까지 확인한다. 클릭률·시청 지속 시간 요청을 metadata 평가로 대체하지 않는다. Studio가 없거나 로그인·권한 때문에 열리지 않으면 실제 접근 제한과 확인한 범위를 알리고, 필요한 지표를 요청하면서 공개 근거로 가능한 분석을 진행한다. 공개 조회수만으로 노출·CTR·유입 검색어·시청 시간을 추정하지 않는다.

진단 요청은 읽기 전용이다. 제목·썸네일·설명·영상·예약을 변경하거나 실험을 실행하지 않는다. 사용자가 다음 영상에만 반영하라고 했으면 기존 게시물의 재편집·교체를 작업 목표로 바꾸지 않는다.

## 요청에 맞는 지표 수집

- 확인 시각, 보고서 기간, 집계 지연·처리 중 표시를 먼저 읽는다. 게시 이후 누적과 최근 기간, 상단 요약과 유지율 세부 보고서의 범위가 다르면 각각 표시한다. 반올림 표시를 정확한 원시 수치로 바꾸지 않는다.
- 도달범위에서 노출수·CTR과 유입 경로별 노출·CTR·조회수 비중을 대조한다. 홈/탐색·추천·검색은 시청 의도와 모집단이 다르므로 전체 CTR 하나를 보편 기준과 비교해 원인을 확정하지 않는다. 노출에서 발생한 조회수와 전체 조회수도 구분한다.
- 검색은 유입 조회수와 실제 검색어를 확인한다. 작은 표본, 숨김·누락된 검색어, 개인정보 임계값은 한계로 남긴다. 개인화된 검색 화면의 한 번의 순위나 공개 검색 결과에 안 보였다는 사실을 영상 전체의 검색 노출 부재로 일반화하지 않는다.
- 참여도에서 평균 시청 지속 시간·평균 조회율·초반 유지율과 전체 곡선을 함께 본다. 전체 평균만으로 특정 구간을 원인으로 지목하지 않는다. 급락·완만한 감소·재시청 상승을 구별하고, 구간 비율을 그래프에서 읽으면 근삿값임을 표시한다.
- 현재 적용 제목·썸네일을 직접 확인한다. 변경 이력·실험별 자료가 없으면 누적 지표를 현재 버전이나 특정 제작자의 인과 효과로 귀속하지 않는다. 공개 조회수와 Studio 수치가 달라도 억지로 맞추지 않고 범위·갱신 시점을 구분한다.

확인한 수치와 필요한 미확인 항목을 먼저 짧게 제시한다. 요청된 지표를 직접 확인할 수 있었다면 사용자에게 같은 데이터를 다시 제공하도록 떠넘기지 않는다. 수집을 채널 전체·타 영상·수익 등 무관한 영역으로 확대하지 않는다.

## CSV와 자막의 로컬 보조 분석

사용자가 제공했거나 읽기가 승인된 exact 유지율 CSV와 **최종 영상 좌표** SRT가 있으면 보조 도구를 사용할 수 있다. 기존 Studio 곡선 관찰만으로 요청에 답할 수 있으면 CSV 제공을 추가로 요구하지 않는다. 도구 사용을 위해 별도 업로드·설치하지 않는다.

```powershell
python -B .agents/skills/youtube-title-thumbnail/scripts/analyze_retention.py <유지율.csv> --position-column "영상 위치" --retention-column "시청 지속률" --axis percent --unit percent --duration 600 --srt <최종자막.srt>
```

열 이름은 실제 CSV 헤더 그대로 지정한다. 시간축 `seconds`·`percent`·`ratio`, 유지율 단위 `percent`·`ratio`를 보고서 정의에서 확인해 명시한다. `seconds`는 초 또는 MM:SS/HH:MM:SS를 받는다. 최대값을 보고 단위를 추정하지 않는다. 누락·NaN·중복/역순 좌표·영상 범위 밖 값은 오류로 처리하고 원 자료를 확인한다. 유지율 100% 초과는 재시청일 수 있어 보존한다.

출력의 감소량은 퍼센트포인트(pp), 감소 속도는 pp/초다. 초반은 관측 범위 안에서만 0초와 min(30초, 영상 길이)를 보간하며 범위가 부족하면 값을 내지 않는다. 후반 순감소 속도는 관측 시간으로 가중하고 상승도 반영한다. 급락 후보는 관측 두 점 사이의 구간이며 원인이나 정확한 이탈 순간이 아니다. SRT와 겹치는 전체 발화를 표시하므로 자막 내용·유입 경로·실제 화면과 함께 읽는다. 길이 검사 통과만으로 SRT 버전 일치나 청취를 확인했다고 하지 않는다.

가장 중요한 후보 하나에 `관측 구간·감소량 → 발화/장면 → 가능한 원인과 대안 → 다음 영상에서 바꿀 선택 → 확인할 지표`를 연결한다. 일률적인 초반 합격률이나 ‘대본/편집이 항상 원인’이라는 규칙은 쓰지 않는다. 방법 참고: [yt-retention](https://github.com/Jakeschincariol/youtube-agent-skill/tree/main/skills/yt-retention); 계산·단위 처리는 별도 구현이다.

## 유지율과 실제 내용을 연결

하락 구간의 최종 영상 좌표를 SRT·챕터와 연결하고, 가능한 경우 실제 영상 화면과 음성을 확인한다. SRT 읽기·정지 화면·실제 청취의 범위를 구별하며, 청취하지 않은 음질·발화·리듬을 확인했다고 보고하지 않는다. 자막이 보여주는 내용 순서와 화면에서 확인한 사건을 원인 가설의 근거로 쓴다.

도입 질문, 예고 뒤 본편 첫 진행, 답·결과 회수 위치를 대조한다. 예고 뒤 소개·설정·반복으로 돌아가는 구간이 사건을 진행시키거나 필요한 맥락을 제공하는지 검토한다. 컷 구성과 예외의 기준은 프로젝트의 스토리·컷 설계 owner를 따르고, 분석만 요청받았으면 편집을 실행하지 않는다. 특정 시각의 하락과 장면의 동시 발생은 원인 확정이 아니다. 유입 시청자의 기대 차이·노출 경로·영상 길이·변경 시점 등 확인 가능한 대안도 함께 고려한다.

## 결론과 다음 영상 적용

관측 사실, 내용과 지표를 연결한 가설, 아직 미확인인 원인을 나눈다. 지표가 부진하면 이전 추천을 정정하되, 수치만으로 특정 썸네일·제목·한 장면이 유일한 원인이라고 단정하지 않는다. 공개 metadata가 정돈됐다는 평가와 실제 클릭·시청 성과가 좋다는 평가는 별개다.

가장 영향을 크게 받는 경로와 구간을 기준으로 개선 우선순위를 정한다. 검색 표본이 작고 추천 노출이 대부분이면 키워드 추가만으로 처방을 끝내지 않는다. 클릭이 약한 경우의 약속·시각적 전달과 클릭 뒤 이탈하는 경우의 본편 구성은 각각 검토하고, 약속과 본편의 연결도 확인한다.

다음 영상에 반영할 때는 `관측 → 편집 가설 → 바꿀 선택 → 확인할 지표·구간`을 해당 영상의 기존 작업 근거에 연결한다. 한 영상의 길이·도입 초 수·CTR·유지율을 모든 영상의 합격값으로 만들지 않는다. 실험 가능 여부와 데이터 확보 범위에 맞춰 비교 기간·유입 경로·변경 버전을 구분하는 검증을 제안하고, 개선 효과는 실제 게시 후 데이터가 생기기 전까지 미검증으로 남긴다. 공개 수치·계정 정보·개별 영상 자료를 공통 스킬·합성 fixture로 복제하지 않는다.
