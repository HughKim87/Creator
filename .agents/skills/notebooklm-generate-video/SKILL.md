# NotebookLM 동영상 생성

준비된 NotebookLM 출처를 근거로 맞춤 설명 영상을 한 번 생성하고, 다음 단계가 사용할 수 있는 완성 아티팩트인지 검증한다.

## 입력 확정

다음 항목을 사용자 요청과 노트북 상태에서 확정한다.

- 대상 노트북과 사용할 출처
- 영상 형식: 설명 동영상 또는 요약
- 언어, 대상 시청자, 목표 길이
- 반드시 포함할 핵심 흐름
- 시각적 스타일과 모델·범주별 색상 규칙
- 구분해야 할 사실·체감·해석과 피해야 할 과장

구성이 복잡하면 `references/video-brief-template.md`를 읽고 호스트 집중 프롬프트와 시각 스타일 프롬프트를 각각 만든다.

## Chrome 연결 게이트

1. browser runtime bootstrap이나 다른 `agent.browsers.*` 호출보다 먼저 작업 기록의 `browser.profile_directory`와 `browser.required_origin`을 그대로 `$connect-chrome-profile`에 전달한다. 둘 중 하나라도 없으면 기본값을 만들지 말고 작업 기록 검증 실패로 멈춘다.
2. 연결 스킬이 `status: connected`를 반환할 때만 영상 생성을 시작하고, 반환된 Chrome 바인딩과 검증된 탭을 재사용한다.
3. 이 스킬은 Chrome을 다시 선택하지 않는다. `agent.browsers.get("extension")`, `getDefault()`, `getForUrl()`와 기존 일반 `chrome`·`browser` 바인딩을 사용하지 않는다.
4. 반환 바인딩이 명시적 unavailable·disconnected 오류를 내면 임의 fallback 없이 `$connect-chrome-profile`을 다시 실행한다.
5. 공식 프로필 진단과 프로필 대상 실행 경로가 끝나기 전에 사용자에게 프로필 메뉴 전환이나 확장 패널 준비를 요구하지 않는다.
6. 연결 스킬이 `needs_user` 또는 `unavailable`을 반환하면 그 결과를 그대로 기록하고 멈춘다. 다른 브라우저나 계정으로 우회하지 않는다.
7. 쿠키, 로컬 저장소, 전체 프로필 경로, 브라우저 ID, 확장 인스턴스 ID, 비밀번호 또는 계정 주소를 검사하거나 기록하지 않는다.

## 사전 점검

1. `$connect-chrome-profile`이 이번 브라우저 런타임에서 `connected`를 반환했는지 점검한다.
2. 노트북 제목과 URL이 대상 작업과 일치하는지 확인한다.
3. 출처 로딩 표시가 사라졌고 사용 가능한 출처가 하나 이상 선택되어 있는지 확인한다.
4. 오류 출처는 선택 수와 별개로 취급한다.
5. 동일한 목적의 완성 영상이나 진행 중 영상이 이미 있으면 새로 생성하지 않는다.
6. 영상 생성이 유료 결제, 추가 구매 또는 권한 변경을 요구하면 사용자 확인 없이 진행하지 않는다.

## 동영상 설정

1. 스튜디오에서 `동영상 개요`를 연다.
2. 교육·비교·분석 영상은 기본적으로 `설명 동영상`을 사용한다. 짧은 핵심 정리 요청만 `요약`을 사용한다.
3. 사용자 언어를 선택한다.
4. 채널 스타일이 정해져 있으면 `맞춤` 시각 스타일을 선택하고 시각 프롬프트를 입력한다. 정해져 있지 않으면 목적에 가장 가까운 기본 스타일을 사용한다.
5. `AI 호스트가 어떤 부분에 집중해야 하나요?`에 다음을 포함한다.

   - 목표 시청자와 목표 길이
   - 관심을 끄는 첫 질문 또는 문제 제기
   - 설명할 항목의 순서
   - 마지막 실무 선택 기준 또는 행동 지침
   - 공식 사실·벤치마크·커뮤니티 체감·해석의 구분
   - 소스에 없는 단정과 과장 금지

6. 형식, 언어, 시각 스타일, 호스트 프롬프트를 화면에서 다시 확인한 뒤 `생성`을 한 번만 누른다.

## 생성 대기

1. `설명 동영상 오버뷰 생성 중...` 또는 같은 의미의 진행 상태가 나타났는지 확인한다.
2. 첫 완료 확인은 생성 시작 5분 뒤에 한다.
3. 이후에도 **5분 간격으로만** 완료·실패 상태를 확인한다. 30초나 1분 단위로 반복 확인하지 않는다.
4. 진행 상태가 유지되는 동안 새로고침, 중지, 같은 설정 재제출, 중복 생성을 하지 않는다.
5. 고정된 짧은 타임아웃을 두지 않는다. 명시적 실패가 없고 진행 상태가 살아 있으면 기다린다.
6. 사용자에게는 5분 확인 시점이나 상태 변화가 있을 때만 간단히 알린다.

## 결과 검증

완료 카드가 나타나면 다음을 한 번씩 확인한다. 재생 검증은 짧게 끝내야 한다.

1. 아티팩트 제목, 총 길이, 형식, 사용한 소스 수를 기록한다.
2. 목표 길이 범위에 들어오는지 확인한다. 벗어나도 자동 재생성하지 말고 사용자에게 보고한다.
3. 아티팩트를 열고 플레이어의 총 길이가 0보다 큰지 확인한다.
4. 재생 버튼을 누른 시각을 기준으로 **30초 안에** 진행 시간이 실제로 증가하는지 확인하고 즉시 일시중지한다. 30초 안에 진행이 확인되지 않으면 재생을 계속 두지 말고 일시중지한 뒤 검증 실패로 보고한다. 재생 검증의 경과 시간(`playback_check_seconds`)과 일시중지 여부를 기록한다.
5. 첫 장면 또는 대표 프레임을 시각적으로 확인해 선택한 스타일과 읽을 수 있는 텍스트가 적용됐는지 본다.
6. 다운로드 버튼의 존재만 확인한다. 사용자가 다음 단계를 승인하기 전에는 파일을 다운로드하지 않는다.

반환 결과:

- NotebookLM 노트북 URL
- 영상 아티팩트 제목
- 영상 길이와 형식
- 사용 소스 수
- 재생 검증 결과
- 재생 검증 경과 시간과 일시중지 여부
- 다운로드 가능 여부
- 목표 길이·스타일과 다른 점

## 정지 조건

완성 영상의 재생과 다운로드 가능 상태를 검증한 뒤 멈춘다. 파일 다운로드, 음성 추출, SRT 생성, 제목·썸네일 제작, 수동 업로드 자료 준비는 후속 스킬의 책임이며, 실제 YouTube 업로드는 사용자가 직접 수행한다.

다음 중 하나면 중복 생성하지 말고 상태를 보고한다.

- 기존 진행 중 영상이 있음
- `$connect-chrome-profile`이 공식 복구 절차 후 `needs_user` 또는 `unavailable`을 반환함
- NotebookLM이 명시적 생성 실패를 표시함
- 진행 표시가 사라졌지만 완성 아티팩트도 없음
- 유료 사용, 권한 변경, 공유 또는 게시가 필요함
