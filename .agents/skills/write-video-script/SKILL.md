# Write Video Script

영상이 전달할 내용과 실제로 보여줄 수 있는 근거를 연결해, 사용자가 말할 수 있는 대본을 만든다. 촬영 후 원본 컷·음성·자막 검수는 편집 스킬이 소유한다.

## 요청한 범위부터 선택

| 요청 | 수행·종료 |
|---|---|
| 기획·흐름만 | 목적, 시청자 질문, 이야기 순서와 장면 역할까지. 전체 대본은 요청한 경우에 작성 |
| 새 대본 | 기존 의도·자료를 바탕으로 초안을 작성하고 아래 검토 후 요청 형식으로 전달 |
| 기존 대본 수정 | 기준본과 수정 목적을 확인하고 보존할 부분·제외 범위를 유지하며 수정 |
| 시청자 관점 검토 | 문제 위치·근거·최소 수정안을 제시. 분석만 요청했다면 파일을 바꾸지 않음 |

대사만, 발화/화면 구분, 문장별 줄바꿈 등 전달 형식은 사용자 지시를 따른다. 기본적으로 대사와 화면 제안을 구분하되 대사만 요청하면 설명·연출 지시를 섞지 않는다. 단순 채팅 결과에 새 job·브리프 파일·스키마를 요구하지 않는다.

총괄에서 받으면 job/root, 선택된 방향, 자료와 접근 범위, 최신 대본, 사용자 확정·제외와 이번 종료점을 재사용한다. 단독 요청도 이미 알려진 결정을 다시 묻지 않는다. 결과를 바꾸는 필수 정보만 확인하고, 선택 가능한 편집 판단은 가정을 밝히고 진행한다.

## 목적과 근거를 먼저 연결

기존 기획 owner나 대화에서 다음을 짧게 정리한다. 모든 요청에 별도 양식이나 사용자 승인 단계를 만들 필요는 없다.

- 이번 영상으로 무엇을 전달하며, 시청자는 무엇을 궁금해할 수 있는가.
- 실제 자료로 답할 수 있는 범위와 아직 답하지 못하는 부분은 무엇인가.
- 사용자가 확정한 방향, 유지할 내용, 제외한 장면과 표현은 무엇인가.
- 결말에 남기려는 이해·감정은 무엇인가. 의도한 반응과 관측된 시청 반응을 구분한다.

사용자 진술, 원본에서 관찰한 사실, 기획 해석, 앞으로의 제안을 구분한다. 사용자의 감정·동기·실패 원인을 그럴듯한 이야기로 메우지 않는다. 정확한 인용·사건·시간 순서가 중요하면 지정된 자료의 해당 부분을 대조하고 관찰 방식·불확실성을 함께 둔다. 기록을 조사했다는 사실만으로 현재 상황을 확인했다고 쓰지 않는다.

자료가 없는 내용은 확인 질문·생략·조건부 제안으로 처리한다. 실제 말하지 않은 예시는 발화 제안이며 과거 직접 인용이 아니다. 전체 채팅·프로젝트 전수 조사나 외부 검색은 요청의 필요 범위와 자료 접근 권한 안에서만 한다.

## 문장보다 이야기의 기능을 먼저 검토

영상 형식에 맞게 순서를 정한다. 경험담은 사건→생각/선택→현재 행동의 연결, 설명은 질문→근거→답, 리뷰는 조건→관찰→판단처럼 필요한 관계를 확인한다. 모든 영상에 갈등·개발자의 꿈·반전·인생 회고를 강제하지 않는다.

문단이나 장면마다 시청자의 어떤 질문을 진행시키는지, 추가하는 정보와 근거가 무엇인지 확인한다. 자료가 풍부하다는 이유만으로 중심 장면으로 삼지 않는다. 과거 설명은 현재를 이해시키는 역할, 현재 결과는 행동을 보여주는 역할처럼 기능을 구분하며 주제에 맞게 배분한다. 화면을 보여주는 시간과 해당 내용을 말로 설명하는 시간은 다를 수 있다.

인과가 약하면 ‘그래서·그 마음’ 같은 연결어만 바꾸지 말고 빠진 생각·선택의 근거를 찾는다. 근거가 없으면 인과로 단정하지 않는다. 도입의 질문이 실제 내용에서 진행되고 결말에서 회수되는지 확인하되, 억지 질문이나 답하지 못할 성공 약속을 만들지 않는다.

사용자가 정한 길이는 적용하되 과거 결과 길이·단일 사례의 비율·낭독 속도를 보편적 상한이나 합격 기준으로 만들지 않는다. 분량은 잠정 추정으로 표시하고, 내용이 부족한데 반복 설명으로 늘리지 않는다.

## 초안과 국소 수정

초안은 사용자에게 확인된 말투와 자료를 따른다. 말투 자료가 제공됐거나 반영을 요청한 경우에만 [채널 말투 참고](../youtube-title-thumbnail/references/channel-voice.md)를 읽는다. 인위적인 유행어·분노·감동을 추가하지 않는다. 한 호흡에 읽히는 문장을 지향하되 감정이나 정보 기능이 있는 짧은 문장까지 획일적으로 합치지 않는다.

기존 대본을 고칠 때 기준본, 이번 증상, 바꿀 부분, 유지할 부분을 대조한다. ‘조금 추가/줄이기’ 요청은 필요한 최소 범위부터 수정한다. 연결 문장의 조정이 필요하면 인접 부분까지 검토하되 무관한 도입·결말·주장·말투를 다시 쓰지 않는다. 제외된 장면을 다른 수정 중 다시 넣지 않는다. 구조 변경이 불가피하면 이유와 바뀌는 범위를 알리고 사용자 승인 범위에 맞춰 처리한다.

단어가 달라도 같은 감정·결론을 반복하는 문단은 새 정보·선택·변화를 추가하는지 확인한다. 기능 없는 반복을 줄이면서 실제 경험과 행동의 근거까지 지우지 않는다. 사실의 범위나 영상의 목적이 달라졌다면 그 변경을 드러내고 단순 문장 교정처럼 처리하지 않는다.

## 검토와 전달

구조 검토·반복 수정·시청자 관점 요청에는 [대본 검토](references/script-review.md)의 해당 항목을 사용한다. 기계적 문구 점검으로 인과·사실·말투의 의미 판단을 대신하지 않는다.

요청 형식의 결과를 제공한다. 검토/수정이면 무엇이 왜 달라졌고 무엇을 보존했는지 간단히 설명하되, 대사만 달라고 했다면 해당 설명을 낭독문에 삽입하지 않는다. 불명확한 사실은 전달 전에 해소하거나 대본에서 빼고 필요한 확인만 별도로 알린다.

파일 저장 요청이면 기존 대본·근거 owner를 우선하고 지정된 파일만 갱신한다. 과거 자료를 최신 원본으로 되돌리거나 다른 제작 상태를 덮지 않는다. 총괄에는 실제 결과/기준본 참조, 근거와 미확인, 사용자 선택·제외, 요청 완료 수준을 반환한다. 제목·썸네일 제작은 [전문 스킬](../youtube-title-thumbnail/SKILL.md), 녹음 이후의 게임 영상 편집은 [편집 스킬](../edit-gameplay-video/SKILL.md)로 요청 범위만 넘긴다. 대본을 썼다는 이유로 촬영·TTS·편집·업로드를 실행하지 않는다.

문장/구조를 검토한 것, 실제 낭독해 본 것, 영상에서 전달된 것, 공개 후 시청 반응을 측정한 것은 서로 다른 검증이다. 수행하지 않은 검사를 통과로 표현하거나 더 높은 CTR·유지율·무수정 완성을 보장하지 않는다.
