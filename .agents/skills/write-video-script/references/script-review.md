# 대본 검토와 수정 판단

요청한 검토 범위에 맞는 항목만 사용한다. 이 문서는 대본 판단을 돕는 참고이며 고정 분량·필수 승인·점수 제도를 만들지 않는다.

## 목적과 자료

- 문장 다듬기 전에 전달하려는 내용과 사용자 제외 범위를 재확인한다. 이미 명확한 목적을 새 질문으로 흔들지 않는다.
- 한 문단에 사용자 진술·관찰·해석이 섞였으면 발화의 주장 범위를 나눈다. 정확한 인용은 지정된 원문과 대조한다.
- 과거 자료는 당시 경험의 근거다. 과거 인터뷰·녹화를 오늘의 상태나 아직 듣지 못한 현재 감정으로 바꾸지 않는다.
- 자료가 없는 최초 시행착오는 현재 설명·현재 시연으로 대체할 수 있다. 새 시연·정리 문서를 당시의 녹화·원문처럼 소개하지 않는다.

## 인과와 역할

| 검토 질문 | 문제가 있다면 |
|---|---|
| 이 문단은 시청자가 무엇을 이해하게 하는가? | 기능 없는 부수 설명을 줄이거나 필요한 위치로 이동 |
| 다음 행동이 앞선 사건만으로 설명되는가? | 빠진 생각·선택이 실제 근거에 있는지 확인. 없으면 인과 단정 완화 |
| 과거·현재·결과가 각자 맡을 일을 하는가? | 하나의 분량만 늘리는 대신 역할과 연결을 다시 잡음 |
| 도입의 궁금증을 본문에서 실제로 진행시키는가? | 답이 없는 예고를 줄이고 제공할 수 있는 질문으로 조정 |
| 기능을 보여주는 장면이 긴 기능 설명을 요구하는가? | 화면의 증거 역할과 발화의 설명량을 구분 |

예: ‘고장이 싫었다. 그래서 수리 서비스를 만들었다’에는 본인이 왜 직접 서비스까지 만들려 했는지 빠져 있을 수 있다. 편리한 이유를 새로 만들어 넣지 말고 실제 선택의 근거를 찾는다. 반대로 단순 수리 사용법 영상에 창업 동기나 감정선을 추가할 필요는 없다.

## 반복과 낭독

문장 표현이 달라도 같은 사실·감정·결론을 되풀이하는지 순서대로 읽는다. 새 정보·행동·의미 변화가 있으면 같은 단어를 썼다는 이유로 제거하지 않는다. 의도된 반복·유머·여운은 그 기능을 유지한다.

문어적인 명사 나열, 주어가 바뀌는 연결, 한 문장에 과도하게 얹힌 이유를 점검한다. 접속어만 바꿔 인과를 가장하지 않는다. 실제로 읽어보지 않았으면 ‘낭독 자연스러움 확인’이라고 하지 않는다. 읽을 대사와 화면·기술 지시의 분리는 요청한 형식을 따른다.

## 국소 수정의 회귀 대조

1. 어떤 기준본과 요청을 반영하는지 특정한다. 이전 제안을 사용자 확정으로 바꾸지 않는다.
2. 바꾼 문단을 인접 부분과 읽어 목적·논리·근거·말투가 이어지는지 본다.
3. 수정 범위 밖의 도입·결말·핵심 주장과 이미 제외한 내용을 기준본과 대조한다.
4. 분량을 줄이면서 선택의 이유나 필요한 첫 맥락까지 지우지 않았는지 확인한다.
5. 범위 밖 구조 변경이 필요하면 영향을 설명한다. 이미 승인된 범위 안의 수정마다 새 승인을 요구하지 않는다.

‘게임 특징을 조금 더 설명’ 요청에 초반 회고를 전부 되살리거나, ‘과거를 줄이기’ 요청에 현재 행동의 이유까지 삭제하면 회귀다. 이 예시는 형식만 바꾼 합성 사례이며 어느 채널의 고정 구성도 뜻하지 않는다.

## 유지보수 때의 행동 평가 사례

아래는 합성 요청이다. 스킬을 실제로 적용해 초안/수정 결과와 근거를 대조한다. 이 항목의 존재나 특정 단어 검출만으로 행동 통과를 선언하지 않는다.

| 합성 입력 | 확인할 결과 | 피해야 할 확대 |
|---|---|---|
| 복원한 라디오를 소개하며 왜 수리를 계속하는지 말하고 싶다. 회로 자료가 많다 | 회로 설명이 목적을 대체하지 않고 확인된 경험·현재 작업을 연결 | 가족 추억·창업 결심을 지어내기 |
| 기존 5문단 중 세 번째 기능 설명만 한 문장 보강. 나머지와 결말 유지 | 해당 부분과 필요한 연결만 바뀌고 주장·결말 보존 | 전체 대본 새로 작성 |
| 제품 비교 설명 영상이며 개인 회고는 원하지 않음 | 비교 조건·관찰·판단 중심으로 작성 | 모든 영상에 꿈·갈등·과거 서사 삽입 |
| 과거 실험 녹화는 없고 지금 같은 방법을 시연할 수 있음 | 현재 시연을 구분하고 실제로 확인할 수 있는 주장만 사용 | 새 화면을 최초 실패의 기록처럼 제시 |
| 첫 기획에서 도구 조작을 제외했고 이후 도입만 더 짧게 요청 | 제외가 유지되며 도입의 필요한 변화만 반영 | 자료가 있다는 이유로 도구 강의 부활 |

행동 검토, 형식/경로/묶음 검사, 실제 사용자 낭독, 공개 후 반응은 별도로 보고한다. 한 사례의 개선을 보편적인 성과 입증으로 사용하지 않는다.
