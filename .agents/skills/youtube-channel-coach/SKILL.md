# 유튜브 채널 코치 스킬

- 목적: 채널 진단·주간 편성·공개 시간 추천을 요청 범위에서 제공한다.
- 읽는 시점: 채널 운영 분석 또는 편성·공개 시간 요청.
- 책임: 이 프로젝트의 전문 스킬이 분석하고 총괄은 호출·입력·결과만 연결한다.
- 상태: 프로젝트 관리 원본. 같은 이름의 플러그인 캐시 사본으로 대체하지 않는다.
- 관련 권위: 프로젝트 정책과 [총괄 호출 계약](../coordinate-video-production/SKILL.md#하위-스킬-호출-계약).

이 스킬은 유튜브 채널을 데이터 기반으로 진단하고, 크리에이터가 실제로 실행할 수 있는 개선안을 제시한다. 숫자 없이 막연한 조언이 아니라, 채널의 실제 지표를 읽고 그에 맞는 전략을 짜는 것이 핵심이다.

## 공개 시간만 추천하는 요청

이 모드는 채널 전체 진단을 실행하지 않는다. 기존 대화/작업 기록의 채널 ID와 현재 Chrome Studio의 채널 ID를 대조하고 표시 채널명은 실제 화면을 따른다. 연결된 Chrome은 현재 `mcp__cua_repl.js`의 지원 API로 재사용한다. 예전 Claude Chrome 도구 이름이나 스킬 파일이 없다는 이유로 멈추지 않는다. 진행 중 업로드·편집 화면은 건드리지 않고 필요하면 같은 브라우저의 별도 분석 탭을 사용한다.

1. Studio → 분석 → 시청자층에서 ‘내 시청자가 YouTube를 이용하는 시간대’를 먼저 확인하고 조회 기간과 시간대를 기록한다. 연결 상태를 확인하기 전에 사용자에게 데이터 확인을 떠넘기거나 데이터를 못 본다고 단정하지 않는다.
2. 데이터가 있으면 해당 분포와 소재의 시의성으로 공개 시각 하나를 추천한다. 데이터 부족 문구가 보이면 이를 사실로 보고하고, 사용자 현지 날짜·요일·대상 지역·소재 시의성을 근거로 미래의 구체적인 시각 하나를 잠정 추천한다. 주말이라는 이유만으로 저녁이나 낮을 보편적 최적으로 단정하지 않는다.
3. 추천에는 날짜·시각·시간대와 실측/잠정 여부를 함께 밝힌다. 새 데이터나 사용자 일정 제약이 없으면 근거 없이 추천 시각을 바꾸지 않는다. 이미 지난 시각이면 다음 실행 가능한 시각을 고르고 변경 이유를 밝힌다.
4. 필요한 결과가 확인되면 종료한다. 전체 채널 분석, SocialBlade, 웹서치는 이 질문만으로 확대하지 않는다. 업로드·예약·메타데이터 변경은 하지 않는다.

## 주간 편성만 요청한 경우

이번 주 제작 계획·가용 시간에 맞춘 편성 요청은 전체 채널 진단을 실행하지 않는다. 기존 대화의 주간 가용 시간, 진행 중 영상, 재사용 가능한 자료, 소재의 유효기간을 먼저 재사용한다. 결과를 바꾸는 필수 정보가 없을 때만 묶어서 묻고, 미정이면 가정을 표시한 잠정 계획을 제공한다. 사용자 자료는 지정한 항목만 읽는다.

- 표는 `요일/날짜 | 소재·형식 | 시청자 질문 | 남은 제작 작업 | 예상 시간·근거 | 선행 작업 | 대체/보류 순서`로 작성한다.
- 시간은 조사·촬영·편집·검수·패키징의 남은 일을 기준으로 합산하고, 실제 관측과 추정·범위를 구별한다. 같은 원본 작업을 롱폼과 쇼츠에 이중 계산하지 않는다. 예산을 넘으면 우선순위가 낮은 일을 보류하고 여유 시간을 남긴다.
- 핵심 영상, 기존 자료 재사용, 쇼츠 파생을 검토하되 주간 업로드 수·롱폼/쇼츠 비율을 고정하지 않는다. 미완성 선행 영상의 쇼츠를 확정 산출물처럼 계획하지 않는다.
- 공개 시간 분석을 요청했거나 기존 분석이 있으면 위 공개 시간 절차를 사용한다. 없으면 사용자의 일정에 맞춘 잠정 시각으로 표시하고 최적 시간이라 하지 않는다. 캘린더 등록·예약·게시는 실행하지 않는다.
- 제작을 요청받은 영상 하나의 실행은 기존 [coordinate-video-production](../coordinate-video-production/SKILL.md), 쇼츠 제작은 프로젝트의 [create-shorts](../create-shorts/SKILL.md), 소재 실측은 [game-trend-brief](../game-trend-brief/SKILL.md)에 맡긴다. 편성표만 요청받았으면 제작을 자동 시작하지 않는다.

참고 아이디어: https://github.com/Jakeschincariol/youtube-agent-skill/tree/main/skills/yt-plan . 한국어 편성과 실제 시간 예산에 맞게 재작성했다.

## 진단 결론과 역할 분담

채널 진단의 마지막에는 이번 주 바꿀 선택 하나와 근거·확인할 지표·비교 조건을 정한다. 실제 근거가 있는 유지할 요소와 아직 판단/실행을 보류할 항목도 구별한다. 칭찬이나 문제 개수를 채우기 위해 내용을 만들지 않는다. 숫자와 장면의 동시 발생을 인과관계로 단정하지 않는다.

특정 영상의 CTR·검색 유입·유지율 분석은 현재 프로젝트의 기존 [youtube-title-thumbnail](../youtube-title-thumbnail/SKILL.md) 실적 진단 절차로 연결한다. 채널 전체 진단을 영상 단일 지표 요청에 강제하지 않는다. 공개 조회수에서 CTR·초반 유지율을 추정하지 않으며, 구독자/누적 조회수는 실제 구독 전환율이 아니다. 실제 전환을 확인하려면 같은 기간의 구독 증가·관련 조회 자료를 확인한다. 14일/30일 비율과 고정 임계값만으로 성장 정체나 원인을 확정하지 않는다.

제목 길이·앞부분 키워드는 한국어 가독성의 참고치이며 최소 길이나 성공 기준이 아니다. 실제 모바일 썸네일·제목의 역할과 영상 약속을 확인한다. 제목·이미지 제작은 [youtube-title-thumbnail](../youtube-title-thumbnail/SKILL.md), 수동 업로드 자료는 [prepare-youtube-upload](../prepare-youtube-upload/SKILL.md), 댓글 초안은 [youtube-comment](../youtube-comment/SKILL.md)가 담당한다. 이 진단은 수정·게시·실험 실행 승인을 포함하지 않는다.

참고 아이디어: https://github.com/Jakeschincariol/youtube-agent-skill/tree/main/skills/yt-audit . 별도 채널 진단 스킬을 중복 생성하지 않는다.

## 1단계: 채널 URL 확보

일반 전략·주간 편성 요청에는 채널 URL을 필수로 요구하지 않는다. 실제 채널 진단은 기존 대화·작업 기록·현재 검증된 연결에서 대상을 먼저 특정하고, 그래도 특정할 수 없을 때만 요청한다:

> "분석할 유튜브 채널 URL을 알려주세요."

URL 형식 예시:
- `https://youtube.com/channel/UC...`
- `https://youtube.com/@채널명`
- `https://youtube.com/c/채널명`

## 2단계: 데이터 수집

현재 제공된 연결 도구·공식 공개 자료·브라우저에서 다음 근거를 수집한다. 브라우저는 `mcp__cua_repl.js`의 현재 문서에 있는 탭 탐색·상태/본문 읽기 API만 사용한다. 초기화 전이면 도구 지침대로 `await cua.getState();` 한 번으로 문서와 연결 상태를 확인하고, 이후에는 같은 런타임을 재사용한다. 지정 프로필이 필요하면 [connect-chrome-profile](../connect-chrome-profile/SKILL.md)에 확정 프로필과 대상 origin을 전달한다. 예전 도구명이나 지원되지 않는 일괄 호출을 필수로 요구하지 않는다. 현재 화면에서 관측한 사실과 검색·통계의 집계 기간을 구분한다.

### A. YouTube 채널 페이지 직접 방문

채널 메인 페이지에서 수집:
- 채널명, 구독자 수, 총 영상 수
- 채널 소개글 (채널 정체성 파악)
- 최근 업로드 영상 목록 (제목, 조회수, 업로드일)
- 영상 유형 패턴 파악 (플레이 시리즈 vs 정보 영상 vs 리뷰 등)

탐색 뒤 로딩·오류·로그인 상태를 확인하고 지원 API로 화면/본문을 읽는다. 빈 화면을 데이터 없음으로 단정하지 않는다. 근거가 없는 반복 이동·고정 지연·임의 스크립트 실행을 요구하지 않고, 접근 불가이면 실제 확인 범위와 제한을 보고한다.

### B. SocialBlade 통계

URL: `https://socialblade.com/youtube/channel/{채널ID}`

채널ID는 URL의 `UC...` 부분. 수집 항목:
- 총 조회수, 구독자 수, 등급
- 최근 30일 / 14일 조회수 (성장 추이 파악)
- 일일 평균 업로드 빈도

### C. 최신 전략 웹서치

다음 두 가지를 검색한다:
1. 채널이 다루는 게임/주제의 현재 유튜브 경쟁 환경
2. 해당 장르에서 현재 효과적인 콘텐츠 유형 (2025~2026 기준)

예: 메이플스토리 채널이면 → `"메이플스토리 유튜브 채널 성장 전략 2026"` 또는 `"MapleStory YouTube content strategy 2026"`

## 3단계: 핵심 지표 계산

수집한 데이터로 다음 지표를 계산한다:

| 지표 | 계산 방법 | 의미 |
|------|-----------|------|
| 누적 규모 참고 비율 | 구독자 ÷ 총 조회수 × 100 | 실제 구독 전환율이나 원인 진단에 사용하지 않음 |
| 영상당 평균 조회수 | 총 조회수 ÷ 영상 수 | 콘텐츠 효율성 |
| 최근 기간 참고 비율 | 최근 14일 조회수 ÷ 최근 30일 조회수 | 기간 길이·업로드·시의성 차이와 함께 해석 |
| 업로드 빈도 | 영상 수 ÷ 채널 나이(일) | 양 vs 질 판단 |

벤치마크:
- 고정 구독 전환율 기준으로 진단하지 않는다. 같은 기간의 실제 구독 증가와 관련 조회 자료를 확인한다.
- 정보/리뷰와 플레이 시리즈는 업로드 경과·길이·유입 조건을 대조하고, 배수만으로 콘텐츠 방향 전환을 확정하지 않는다.

## 4단계: 분석 리포트 작성

아래 구조로 분석 결과를 작성한다. 막연한 조언보다 **채널의 실제 숫자와 영상 패턴에 근거한 구체적인 진단**이 핵심이다.

### 출력 형식

```
## 채널 현황 진단 — [채널명]
(데이터 수집 시각)

### 핵심 지표
| 지표 | 수치 | 평가 |
(표 형식)

### 발견된 문제 [1~3개, 숫자 근거 포함]
각 문제마다:
- 문제가 뭔지
- 숫자로 근거 제시
- 왜 이게 문제인지 (알고리즘/시청자 심리 관점)

### 개선 액션 플랜
우선순위 순서로, 각 항목마다:
- 구체적으로 무엇을 할 것인가
- 왜 이게 효과가 있는가
- 실제 예시 (제목 변경 전/후, 채널 소개 변경 전/후 등)

### 빠른 실행 체크리스트
지금 당장 할 수 있는 것들 (유튜브 스튜디오 설정 포함)
```

## 분석 시 반드시 체크하는 항목

### 콘텐츠 방향
- 조회수 상위 영상 유형 vs 자주 올리는 영상 유형이 일치하는가?
- 채널 내 가장 잘 된 영상이 어떤 패턴을 갖는가? (제목, 주제, 포맷)
- 그 패턴을 다른 영상에도 적용하고 있는가?

### 채널 정체성
- 채널 소개글이 방문자에게 "이 채널은 X를 다루는 채널"임을 5초 안에 전달하는가?
- 채널 홈에서 가장 먼저 보이는 영상들이 채널 정체성을 대표하는가?
- 다루는 게임/주제가 1~2개로 좁혀져 있는가, 분산되어 있는가?

### SEO / 제목
- 제목 앞 4~5단어에 검색 키워드가 있는가?
- 시청자가 실제로 검색할 법한 단어를 쓰는가? (예: "메이플 직업 추천" vs "나의 메이플 일기 3편")
- 제목 앞부분에서 대상과 클릭 이유가 전달되는가? 40~65자는 참고 범위이며 짧은 제목을 길이만으로 탈락시키지 않는다.

### 구독 전환율
- 영상 중간이나 끝에 구독 유도가 있는가?
- 유도 방식이 "구독 부탁드려요" 수준인가, 아니면 시청자에게 득이 되는 이유를 제시하는가?
- 엔드카드(최종화면)에 관련 영상 2개 + 구독 버튼이 설정되어 있는가?

### 업로드 패턴
