# 범위·권한·목적 경계

- 상태: 해결
- 적용 범위: 사용자 목표 해석, 승인, 과거 자료 검토, 큰 작업의 범위 결정

## 증상

기반 기능이나 과거 예시를 최상위 목표로 확대하거나, 승인된 현재 범위를 넘어 미래 기능·역사 전체·추가 절차를 작업에 포함했다.

## 확인된 원인

최신 사용자 지시, 활성 정본, 과거 증거의 권위 차이를 구분하지 않았고 승인을 절차 통과 표시로만 취급했다.

## 실패·해결 이력

과거 재구축에서 시스템 완성도와 문서 수가 사용자 결과를 대신했고, 이후 작업 등급과 exact scope를 먼저 고정하는 방식으로 바꿨다. 영상 편집 분석에서는 보고서만 요청된 범위를 추가 제안서와 지속 문서 생성으로 넓히는 재발이 있었다. 첨부 대화의 에이전트 제안을 사용자 지시로 취급하고, 사용자가 교정한 뒤에도 이전 라우팅 전제를 유지한 재발도 확인됐다.

## 해결과 검증

- 최신 사용자 지시와 exact 대상·변화·제외·위험을 먼저 고정하고 그 안에서만 실행한다.
- `quick / standard / controlled` 분류와 보호 경계 회귀를 통해 범위 확장을 차단했다.

## 재사용 규칙

- 최신 사용자 지시 → 상시 정책 → 현재 상태 → task owner 순으로 권위를 판정한다.
- 역사 자료는 질문에 필요한 범위만 읽고 활성 구조로 자동 이관하지 않는다.
- 대화·보고서·delegated result는 화자와 권위를 분리한다. 에이전트 제안은 승인 없이 사용자 지시나 정책으로 승격하지 않는다.
- 사용자가 의도 오해를 교정하면 현재 해석과 대기 중 mutation을 무효화하고, 활성 plan과 성공 gate를 갱신한 뒤에만 재개한다.
- 미래 기능이 현재 결과에 필수인지 증명되지 않으면 구현하지 않는다.
- 쓰기 전에 exact artifact budget을 고정한다. 분석 권한은 구현이나 추가 산출물 생성 권한이 아니다.
- 승인 요청에는 대상, 실제 변화, 제외 범위, 위험, 승인 뒤 첫 행동을 포함한다.
