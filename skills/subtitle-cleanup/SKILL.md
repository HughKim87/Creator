# 자막 생성/정리

이 스킬은 4단계 자막 생성/정리 작업을 담당한다.
목표는 자막을 예쁘게 고치는 것이 아니라, 이후 기획·분석·편집에서 믿고 쓸 수 있는 텍스트 자료로 정리하는 것이다.

## 입력

- 원본 영상 또는 오디오
- 기존 작업 카드나 자산 목록의 안정된 `source_id`
- 원본 자막 파일: SRT, VTT, TXT 등
- 자동 전사 결과
- 3단계 대본 구조 산출물
- 정리 목적: 기획용, 분석용, 업로드용, 편집용
- 허용할 수정 범위

## 원칙

- 원본 자막과 자동 전사는 절대 덮어쓰지 않는다.
- 정리본은 원본과 분리한다. 같은 입력·정리 기준의 재실행은 기존 정리본을 재사용한다.
- 의미 변경, 맞춤법 수정, 화자 표시, 타임코드 수정은 구분해서 기록한다.
- 자동 자막은 배경음, 억양, 발음, 방언, 겹침 발화 때문에 틀릴 수 있으므로 검토 전제 자료로만 쓴다.
- SRT/VTT는 UTF-8을 기준으로 다룬다.

## 작업 절차

1. 원본 보존 상태를 확인한다.
   - 기존 원본 지문과 `source_id`
   - 원본 파일 경로
   - 복사/수정 금지 여부
   - 출력 파일 경로

2. 자막 형식을 판정한다.
   - SRT, VTT, TXT, 자동 전사
   - 타임코드 유무
   - 화자 정보 유무
   - 비언어 소리 표기 유무

3. 정리 수준을 나눈다.
   - `원문 보존`: 원문과 타임코드를 그대로 둔다.
   - `읽기 정리`: 띄어쓰기, 오탈자, 줄바꿈을 다듬는다.
   - `의미 확인 필요`: 뜻이 바뀔 수 있는 부분을 표시한다.
   - `타임코드 확인 필요`: 말과 시간이 맞는지 확인이 필요하다.

4. 신뢰도를 표시한다.
   - 높음: 원문과 영상이 일치하고 타임코드가 안정적이다.
   - 중간: 의미는 맞지만 일부 타이밍이나 단어 확인이 필요하다.
   - 낮음: 자동 전사 오류, 겹침 발화, 배경음, 게임 사운드 때문에 재확인이 필요하다.

5. 필요한 경우 `tools/synccheck`를 보조로 쓴다.
   - 원본 자막과 실제 발화 시간이 흔들릴 때만 사용한다.
   - 자동 전사 신뢰도가 낮거나 컷 경계처럼 쓰려는 타임코드가 의심될 때만 사용한다.
   - 결과는 타임코드 신뢰도 근거로 기록하고, 컷 경계로 확정하지 않는다.

6. 다음 단계 전달물을 만든다.
   - 5단계 대사 기반 기획에 쓸 정리 자막
   - 화면 검증이 필요한 구간
   - 의미 변경 위험 목록

## 게이트

다음 조건을 모두 통과해야 5단계 대사 기반 기획으로 넘긴다.

1. 원본 자막 또는 자동 전사 원본이 보존되어 있다.
2. 정리본이 새 파일이나 새 산출물로 분리되어 있다.
3. 수정 유형과 의미 변경 위험이 표시되어 있다.
4. 타임코드 신뢰도가 표시되어 있다.
5. 5단계에서 인용 가능한 대사와 확인 필요 대사가 분리되어 있다.
6. 정리본과 5단계 전달물에 같은 `source_id`와 원본 시간 기준이 기록되어 있다.

## 다음 단계 전달물

5단계에는 기준 자막 경로, `source_id`, 원본 시간 기준, 타임코드 신뢰도,
의미 변경 위험과 화면 검증 필요 구간을 함께 넘긴다.

## 중단 조건

- 원본 자막을 덮어쓰라는 요청이면 멈춘다.
- 자동 자막만 있고 오디오 품질이 나쁘면 낮은 신뢰도로 표시하고 단정하지 않는다.
- 의미가 바뀔 수 있는 수정을 사용자가 승인하지 않았으면 반영하지 않는다.
- 타임코드가 없는데 컷 경계처럼 쓰려 하면 멈춘다.

## AI가 확정하지 말 것

- 원본 대사의 의미 변경
- 화자 확정
- 컷 경계 확정
- 자동 자막의 정확성
- 업로드용 최종 자막 승인

## 좋은 요청 예시

```text
이 SRT를 5단계 기획에서 쓸 수 있게 정리해줘.
원본은 보존하고, 정리문/수정 유형/타임코드 신뢰도/의미 변경 위험을 표로 분리해줘.
컷 경계는 확정하지 마.
```

```text
자동 전사 결과를 원본 영상 분석용 자료로 정리해줘.
확실한 대사와 확인 필요한 대사를 나누고, 인용 가능한 문장만 따로 표시해줘.
```
