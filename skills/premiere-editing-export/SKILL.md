# 프리미어 편집 자료 생성

이 스킬은 7단계 편집 자료 생성을 담당한다.
목표는 최종 영상을 자동으로 완성하는 것이 아니라, 사용자가 Premiere에서
바로 이어서 다듬을 수 있는 편집 준비 패키지를 만드는 것이다.

## 핵심 원칙

- 원본 영상을 복사하지 않는다.
- 원본 파일 이름을 바꾸지 않는다.
- 원본 파일 경로를 그대로 참조한다.
- 오디오를 비활성화하지 않는다.
- 사용자가 이해할 수 있는 짧은 사용 방법을 함께 만든다.
- 완성본 자동화보다 `원본 + 후보클립 + 연결 시퀀스` 구조를 우선한다.
- 6단계 후보범위는 탐색 범위이며 실제 컷이 아니다.
- 빠른 편집은 고정 컷 길이가 아니라 새 정보·행동·리액션·상태 변화의 빈도로 판단한다.
- 화면 근거는 원본 시간 자산을 재사용하고 편집본 타임라인 캡처를 내용 근거로 사용하지 않는다.

## 환경 전제 (사용자 편집 환경 — 영상 무관, 항상 적용)

사용자는 Premiere Pro **CS6**를 쓴다.

- **러프컷 단계에서는 mkv 원본을 mp4로 remux하지 않는다.** 사용자가 현재 요청에서 MP4 파일 생성을 명시적으로 요청하거나 허용한 경우에만 `tools/remux_mkv_to_mp4.bat`를 실행한다. CS6 가져오기가 필요하더라도 그 요청 자체를 MP4 생성 허가로 해석하지 않는다.
- **CS6는 FCP7 XML 오디오를 L/R 링크 모노 2트랙으로 가져온다(알려진 제약, 해결 불가).** 이 스크립트가 그 구조에 맞춰 오디오를 분해한다. 편집엔 지장 없고 볼륨만 2회 조정하면 된다 — 재시도하지 말 것.

## 입력

- 원본 영상 경로
- 안정된 `source_id`, 원본 지문, `outputs/06_analysis/source_asset_manifest.csv`
- 6단계 후보지도와 사용자 승인된 대표 후보
- 최신 기준 컷리스트
- 기존 `outputs/07_edit_export/CURRENT.json`과 기준 버전 컷리스트
- microbeat 유지·압축·제거 결정표와 경계 근거
- 캘리브레이션에서 확정된 편집 문법 또는 사용자 수정 지시
- 원하는 산출물 형식
- 프리미어 버전 또는 사용 가능한 가져오기 방식

6단계 후보지도 없이 XML, EDL, 러프컷을 만들지 않는다. 컷리스트가 있더라도 기준 기획서와 후보지도에서 파생된 최신본인지 확인한다.

## 7단계 하위 작업

| 하위 단계 | 목적 | 입력 | 출력 |
|---|---|---|---|
| 7A | 후보범위 해석 | 승인된 6단계 후보지도, 보존/압축 기준 | 이야기 역할, 보존점, 압축·제거 가능 범위 |
| 7B | microbeat 설계·경계 검증 | 7A 해석, 원본, 자막, 오디오·화면 근거 | 유지·압축·제거 결정표, 실제 컷리스트, 경계 주의표 |
| 7C | 캘리브레이션 | 서로 다른 리듬을 대표하는 7B 컷리스트 | 대표 시퀀스 XML/CSV, 편집 문법, 사용 방법 |
| 7D | 전체 확장 | 사용자 피드백이 반영된 편집 문법, 전체 7B 컷리스트 | 전체 XML/CSV, 검증 자료, 사용 방법 |

`tools/synccheck`는 7B에서 말 중간 컷, 자막 어긋남, 시작/끝 경계 위험이 있을 때만 보조로 사용한다.
경계 위험을 제안할 뿐 microbeat의 기능, 유지·제거, 편집 템포를 결정하지 않는다.
7B 경계 검증 전에는 XML, EDL, 러프컷을 만들지 않는다. 7C 대표 리듬 검증 없이 7D 전체 XML로
확장하지 않는다.

## 전체 품질 일관성 게이트

7D 전체 확장과 이후 수정에는 `docs/EDITING_QUALITY_STANDARD.md`를 적용한다.

1. 캘리브레이션은 압축·라디오·호흡뿐 아니라 초반·중간·후반 위치를 모두 포함한다.
2. 각 비트에 유지·압축·제거 microbeat와 최장 컷 근거를 기록한다.
3. 후보범위를 한 컷으로 옮겼다면 내부 분해가 불필요한 이유를 기록한다.
4. 콘텐츠 기준 단일 시퀀스 CSV와 품질 프로필을 `tools/edit_quality_audit.py`로 감사한다.
5. `REVIEW_REQUIRED`가 남으면 최신 전체 XML로 승격하지 않는다. 근거 있는 예외는 `WAIVED`로 보고서에 남긴다.
6. 훅은 문맥→피크→종료 신호를 확인한다. 대사 마지막 프레임에서 즉시 끊는 경우 의도한 스매시컷인지 기록한다.
7. 이전 컷리스트와 원본 `start/end`를 비교하고 변경된 경계만 화면·자막·오디오로 다시 검증한다.

감사 경고선은 고정 컷 길이가 아니다. 경고를 없애기 위한 기계적 분할이나 근거 없는 예외 등록을 금지한다.
멀티시퀀스 CSV는 같은 컷이 중복되므로 감사 입력으로 사용하지 않는다.
편집본 캡처는 자막·효과·합성·렌더 오류처럼 실제 렌더를 봐야 하는 경우에만 버전별 근거로 만든다.
다만 자막 스타일·효과·색보정·오디오처럼 전체에 파급되는 변경은 변경 경계만으로 끝내지 않고
초반·중간·후반 대표 렌더 표본이나 영향받은 전체 트랙을 다시 확인한다.

## 기준본 승격과 정리

1. `CURRENT.json`의 기준 버전과 입력 파일을 먼저 읽는다.
2. 입력 컷리스트와 결정이 같으면 기존 XML/CSV/검증 자료를 재사용한다.
3. 원본 구간이나 결정이 바뀐 경우에만 새 버전을 만들고 `baseline_version`, `changed_ranges`를 기록한다.
4. 모든 게이트를 통과한 뒤에만 `CURRENT.json`을 새 버전으로 갱신한다.
5. 이전 버전은 `superseded`와 정리 후보로 기록한다. 사용자 의도가 명확하기 전에는 삭제하지 않는다.
6. 보존하는 프레임·오디오·영상은 원본 자산 목록 또는 `CURRENT.json`의 렌더 근거로 등록한다.

## 산출물 선택

| 형식 | 용도 | 주의 |
|---|---|---|
| CSV | 사람이 확인하기 쉬운 컷리스트 | 프리미어 자동 시퀀스는 아님 |
| XML | 원본/후보클립/시퀀스를 함께 가져오는 기본 산출물 | Premiere에서 실제 가져오기 검증 필요 |
| EDL | 간단한 컷 시퀀스 가져오기 | 구조가 단순하고 파일 연결을 다시 해야 할 수 있음 |
| JSX | 프리미어 내부 자동화 | 실행 위치가 불명확하면 쓰지 않음 |
| 러프컷 MP4 (예외 산출물) | 사용자가 현재 요청에서 영상 파일 생성을 명시적으로 허용했을 때만 만드는 초안 영상 | 기본 생성 금지. 기존 파일·이전 허가·일반 검증 요청은 새 MP4 생성 허가가 아님 |

기본값:
- 사용자가 잘 모르면 XML을 우선하고, 실패 대비로 EDL/CSV를 함께 둔다.
- JSX는 사용자가 실행 방법을 알고 있을 때만 사용한다.
- "초안 보여줘", "먼저 붙여서 확인하고 싶다", "검증해" 같은 표현만으로는 러프컷 MP4를 만들지 않는다. 사용자가 현재 요청에서 MP4 또는 영상 파일 출력을 명시적으로 요청하거나 허용해야 한다.

## Premiere XML 편집 패키지 생성

컷리스트를 Final Cut Pro 7 XML(`xmeml`) 형태로 만들어 Premiere의
`파일 > 가져오기`에서 열 수 있게 한다. 이 방식은 EDL보다 풍부해서
원본 참조, 후보 클립, 연결 시퀀스를 함께 넣는 데 적합하다.

```bash
<python> skills/premiere-editing-export/scripts/make_premiere_xml.py "원본.mp4" 컷리스트.csv premiere_export/편집.xml
```

- 컷리스트.csv는 `시작,끝[,라벨]` 또는 `시작/끝/구간명` 헤더 형식을 지원한다.
- 확장 헤더의 `sequence`, `order`, `cut_id`를 사용하면 여러 시퀀스를 한 XML에 만들 수 있다.
- `cut_id` 중복, 0프레임 컷, 소스 범위 밖, 혼합 FPS·오디오 채널은 조용히 보정하지 않고 실패한다.
- XML은 기존 파일을 덮어쓰지 않는다 (존재 시 중단).
- XML 내부 구조는 `00_원본`, `01_후보클립`, `02_시퀀스`를 기본으로 한다.
- MKV 연결이 불안정하면 원본을 편집용 중간 파일로 따로 변환한 뒤 같은 컷리스트로 다시 만든다.
- XML 가져오기가 실패하면 EDL을 대체 경로로 사용한다.

## 러프컷 MP4 예외 생성

이 절은 사용자가 현재 요청에서 MP4 또는 영상 파일 출력을 명시적으로 허용한 경우에만 적용한다.
허가가 없으면 `make_roughcut.py`를 실행하지 않고 XML/CSV/HTML, 타임스탬프,
정지 프레임·접촉 시트, 컷 경계·구조 검사로 흐름을 검증한다.
기존 MP4가 남아 있거나 이전 세션에서 허가받았더라도 새 MP4 생성 권한으로 이어지지 않는다.

```bash
<python> skills/premiere-editing-export/scripts/make_roughcut.py "원본.mkv" 컷리스트.csv 출력.mp4
```

- 컷리스트.csv: `시작,끝[,라벨]` 한 줄씩 (SS/MM:SS/HH:MM:SS)
- 출력은 기존 파일을 덮어쓰지 않는다 (존재 시 중단)
- 재인코딩 방식이라 컷 경계가 정확하다. 화질 조정은 `--crf`(낮을수록 고화질)
- 산출물은 `outputs/07_edit_export/` 아래에 둔다.

## 검수 항목

- 원본 경로가 맞는가
- 시퀀스가 누락되지 않았는가
- 오디오가 포함되어 있는가
- 컷 시작/끝 시간이 맞는가
- 사용자가 제공한 원본을 훼손하지 않았는가

## 게이트

다음 조건을 모두 통과해야 8단계 최종 검수로 넘긴다.

1. 6단계 후보지도에서 승인된 후보만 사용했다.
2. 7A/7B를 거친 최신 컷리스트이며 기준 파일명이 기록되어 있다.
3. 원본 경로와 remux 경로가 구분되어 있다.
4. XML/EDL/CSV/러프컷의 검증 수준이 표시되어 있다.
5. Premiere에서 직접 열어보지 않았으면 `App-validated`라고 쓰지 않는다.
6. 사용자가 컷 흐름을 승인해야 한다고 표시되어 있다.
7. 모든 컷에서 소스 `out-in`과 타임라인 `end-start` 프레임 수가 같다.
8. 편집 품질 감사가 `READY`이거나, 남은 `REVIEW_REQUIRED` 때문에 승격 대기라고 정직하게 표시되어 있다.
9. 새 기준본은 `CURRENT.json`에 등록되고, 보존 미디어는 자산 목록이나 렌더 근거에서 추적된다.

## 중단 조건

- 6단계 후보지도 없이 편집 자료 생성을 요청받으면 멈춘다.
- 원본 경로가 불명확하거나 MKV remux 여부가 불명확하면 멈춘다.
- 컷 경계 검증 없이 XML을 확정본처럼 만들려고 하면 멈춘다.
- 캘리브레이션의 사용자 수정 지시를 반영하지 않은 채 전체 XML로 확장하려 하면 멈춘다.
- 초반 표본만 검증하고 중간·후반을 같은 품질로 간주해 전체 확장하려 하면 멈춘다.
- 품질 감사의 미해결 `REVIEW`를 무시하고 최신 기준으로 승격하려 하면 멈춘다.
- Premiere에서 열어보지 않았는데 사용 가능 확정이라고 쓰게 될 때 멈춘다.
- 같은 입력과 결정인데 날짜·실행 횟수만 바꿔 새 버전이나 새 캡처를 만들려고 하면 멈춘다.

## 다음 단계 전달물

8단계에는 `CURRENT.json`, `source_id`, 기준·신규 버전, `changed_ranges`, 현재 XML/CSV,
사용한 원본 `asset_ids`, 버전별 `render_evidence`, 품질 감사와 사용자 승인 상태를 넘긴다.

## 좋은 요청 예시

```text
6단계 후보지도에서 사용자가 대표로 승인한 항목만 기준으로 7단계 컷리스트 초안을 만들어줘.
XML은 만들되 Premiere에서 직접 검증한 것처럼 말하지 말고,
검증 수준과 사용 방법을 같이 써줘.
```

```text
최신 컷리스트 기준으로 Premiere CS6용 XML과 보조 CSV를 만들어줘.
MKV 원본이면 remux mp4 참조 규칙을 적용하고, 원본 파일은 절대 덮어쓰지 마.
```
