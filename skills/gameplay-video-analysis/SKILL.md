# 게임 플레이 영상 분석

이 스킬은 긴 게임 플레이 영상을 편집하기 전에, 원본을 훼손하지 않고 편집 가능한 구조로 바꾼다.
목표는 AI가 영상을 전부 보는 것이 아니라, 싼 신호로 후보를 좁힌 뒤 필요한 화면만 검증해 재사용 가능한
`라운드맵`과 `컷리스트`를 만드는 것이다.

## 선행 조건 — 영상 기획서 (필수 게이트)

이 스킬은 **영상 기획서(컨트롤링 아이디어 + 대사 스파인)가 확정된 뒤**에 쓴다(워크플로우 5단계).
기획서가 없으면 멈추고, 먼저 `기획_리서치/기획단계_대사기반_메시지도출_방법론_2026-07-06.md`로
기획 단계를 수행한다.

- **후보 찾기의 상위 기준은 기획서의 대사 스파인이다.** 이 스킬은 그 비트를 화면으로 검증·정밀화하고
  경계를 잡는 도구지, 이야기를 새로 만드는 도구가 아니다.
- **신호(RMS·키워드)로 이야기를 만들지 않는다.** 신호는 기획서 비트의 경계·반응을 확인하는 보조다.
  기획서에 없는 순간은 반응이 커도 기본 탈락, 기획서가 요구하는 순간은 조용해도 채택.

## 핵심 원칙

- 자막만으로 최종 판단하지 않는다.
- 화면만 무작정 많이 보지 않는다.
- 후보 찾기는 자막/음성/FFmpeg 같은 저비용 신호로 한다.
- 화면 확인은 후보 검증용으로만 쓴다.
- 한 번 본 구간은 문서와 CSV로 저장하고, 다음 세션에서 이미지를 다시 읽지 않는다.
- 게임 한 판의 결과가 중요하면 시작, 진행, 결과, 후속 반응을 함께 보존한다.
- 원본 영상과 원본 자막은 절대 수정하지 않는다.

## 입력 확인

1. 원본 영상 경로를 확인한다.
2. 같은 이름의 `.srt`가 있으면 우선 사용한다. 새 전사는 비용이 필요할 때만 생성한다.
3. **기획서의 컨트롤링 아이디어(한 문장)를 상위 기준으로 가져온다.** 후보 판단은 항상 이 문장에
   비춰 한다("이 순간이 그 이야기에 필요한가"). 기획서가 없으면 위 선행 조건으로 돌아간다.
   - 예: "영화 백룸을 보고 '별거 아니네' 했던 겁 많은 아재가 진짜 백룸에서 공포와 친해지는 이야기"
4. `ffprobe`로 원본이 끝까지 읽히는지 확인한다. 메타데이터 길이만 믿지 않는다.

```powershell
tools\ffmpeg\bin\ffprobe.exe -v error -show_entries format=duration,size -of default=noprint_wrappers=1 "원본.mkv"
tools\ffmpeg\bin\ffprobe.exe -v error -read_intervals 02:24:00%+00:00:45 -select_streams v:0 -show_entries packet=pts_time -of csv=p=0 "원본.mkv"
```

## 토큰 예산 규칙

긴 영상 전체를 프레임으로 읽지 않는다.

| 작업 | 기본 화면 사용량 | 설명 |
|---|---:|---|
| 전체 길이 감 잡기 | 0~30프레임 | 가능하면 자막/음성만 사용 |
| 후보 구간 1개 검증 | 8~16프레임 | 3~5분 구간 기준 |
| 중요한 경계 확인 | 6~12프레임 | `START`, `WIN`, 강한 반응 주변만 지정 추출 |
| 화면 글자 확인 | 1024px | 필요할 때만 사용 |
| 일반 흐름 확인 | 512px | 기본값 |

한 세션에서 이미지 읽기는 가능한 한 16~40장 안에 둔다. 더 필요하면 후보 하나를 끝내고 저장한 뒤 다음 후보로 넘어간다.

## 작업 순서

### 1. 저비용 후보 찾기

자막을 시간순으로 묶고, 다음 신호를 찾는다.

- 목표 선언: "한 판만", "다시", "가보자"
- 결과 반응: "이겼다", "나이스", "졌어", "0.1초"
- 관계성/재미: 웃음, 도발, 놀림, 협동, 당황
- 컷 후보: 설정, 대기방 반복, 매칭 실패, 긴 침묵, UI 탐색

음성은 RMS/피크로 리액션 후보와 정적 후보를 찾는다.

```powershell
tools\ffmpeg\bin\ffmpeg.exe -i "원본.mkv" -af "astats=metadata=1:reset=1,ametadata=print:key=lavfi.astats.Overall.RMS_level:file=rms.txt" -f null -
```

이 단계에서는 화면을 보지 말고 후보 시간표만 만든다.

### 2. 후보 점수화

각 후보에 역할과 위험을 붙인다.

| 필드 | 의미 |
|---|---|
| `role` | 훅, 이유, 갈등, 전환, 중심재미, 정리, 엔딩 |
| `subtitle_evidence` | 자막 근거 |
| `audio_evidence` | 음성 반응/정적 근거 |
| `screen_needed` | 화면 확인 필요 여부 |
| `risk` | 결과 잘림, 맥락 누락, 불필요 구간 과다 |

화면 확인은 `screen_needed=yes`인 후보부터 한다.

### 3. 화면 검증

`video-watch`로 후보 구간만 본다.

```powershell
C:\Users\Hugh\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe `
  skills\video-watch\scripts\watch.py "원본.mkv" `
  --no-whisper --start 02:15:00 --end 02:20:00 `
  --max-frames 16 --resolution 1024 `
  --out-dir temp\video-watch\구간명
```

큰 구간에서 시작/결과 경계가 거칠면 지정 시각 프레임만 추가로 뽑는다.

```powershell
C:\Users\Hugh\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe `
  skills\video-watch\scripts\watch.py "원본.mkv" `
  --no-whisper --detail transcript `
  --timestamps "02:15:25,02:15:30,02:17:31,02:17:38" `
  --start 02:15:10 --end 02:18:00 `
  --resolution 1024 `
  --out-dir temp\video-watch\구간명_cues
```

## 화면 판정 기준

### 한 판 시작

아래 중 하나가 보이면 시작 후보로 잡는다.

- `START` 화면
- 타이머 리셋/시작
- 캐릭터 스폰
- 대기방에서 실제 플레이 화면으로 전환

### 한 판 결과

아래 중 하나가 보이면 결과 후보로 잡는다.

- `WIN`, `LOSE`, `CLEAR`
- 결과표, 경험치/레벨업 화면
- 사망 후 결과 확정
- 대기방 복귀

### 보존 규칙

- `START` 전 맥락 발화가 있으면 3~12초만 보존한다.
- 결과 화면은 반드시 보존한다.
- 결과 직후 강한 반응은 3~8초 보존한다.
- 질문/대답, 원인/반응은 함께 보존한다.
- 대기방/설정/매칭 실패는 원칙적으로 줄인다.

## 라운드맵 저장

화면을 확인한 구간은 반드시 Markdown과 CSV로 저장한다.

권장 위치:

- `작업폴더/analysis_new/NN_화면기반_라운드맵_vN.md`
- `작업폴더/analysis_new/round_map_vN.csv`

CSV 형식:

```csv
round_id,segment_name,event_type,start,end,screen_evidence,subtitle_evidence,edit_rule,decision
R001,3인 플레이 훅,round_start,02:15:30,02:15:35,START 화면,뭐야 / 어,라운드 시작 기준점,keep
R001,3인 플레이 훅,result,02:17:31,02:17:38,WIN 결과 화면,이겼다 이겼다 나이스,결과 보존,keep
R001,3인 플레이 훅,reaction,02:17:38,02:17:42,결과 화면 유지,0.1초 차이로 이겨버리기,핵심 반응 보존,keep
```

Markdown에는 다음을 남긴다.

- 원본 상태 확인
- 검증 산출물 위치
- 라운드별 화면 근거
- 자막 근거
- 권장 컷
- 더 짧은 컷
- 다음 확인 대상

## 출력 형식

```markdown
## 전체 플레이 흐름표

| 시간 | 내용 | 중요도 | 화면 확인 |
|---|---|---:|---|

## 후보 구간

| 번호 | 시간 | 역할 | 자막 근거 | 음성 근거 | 화면 확인 필요 | 위험 |
|---|---|---|---|---|---|---|

## 화면 검증 결과

| round_id | 시간 | 화면 근거 | 자막 근거 | 판단 |
|---|---|---|---|---|

## 권장 컷

| 순서 | 시작 | 끝 | 역할 | 보존 이유 | 압축 가능 |
|---:|---|---|---|---|---|

## 제외/축소

- 제외:
- 축소:
- 다음 검증:
```

## 편집 자동화 연결

라운드맵이 끝난 뒤에만 컷리스트를 만든다. 컷리스트는 `premiere-editing-export` 스킬이나
`skills/premiere-editing-export/scripts/make_roughcut.py`로 러프컷을 생성하는 데 사용한다.

러프컷은 최종본이 아니라 검수용이다. 결과가 이상하면 원본을 다시 보지 말고 먼저 라운드맵의
`event_type`, `edit_rule`, `decision`을 수정한다.

## 중단 조건

- 원본이 후반부까지 읽히지 않는다.
- 후보 구간의 화면 근거가 자막과 충돌한다.
- 한 판의 시작/결과를 화면으로 구분할 수 없다.
- 같은 컷이 두 번 이상 "포인트 누락" 또는 "필요 없는 부분 과다"로 실패한다.

이 경우 계속 러프컷을 만들지 말고, 원본 상태 또는 라운드맵 기준을 다시 확인한다.
