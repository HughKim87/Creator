# 김실버 유튜브 작업 폴더

김실버 유튜브 제작 지원을 위한 독립 작업 폴더다.

- 재구성일: 2026-07-02
- 재정리일: 2026-07-08
- 채널: 신입 아재 유튜버, 김실버😎 (https://youtube.com/channel/UCp9Pn5dAUByhBDkH1K59HiQ)

## 현재 상태

2026-07-08 기준으로 `workspace/`와 기존 `temp/` 작업 내용이 삭제됐다.

따라서 이 프로젝트에는 현재 원본 영상, 원본 자막, 백룸 기획서, 컷리스트, XML, 러프컷, 프레임 캐시, 과거 아카이브가 없다. 남아 있는 것은 제작 시스템을 다시 시작하기 위한 기준 문서, 스킬, 도구다.

현재는 편집 재개 전 프로젝트 운영 구조와 스킬별 게이트의 1차 정리가 끝난 상태다.

## 채널 방향

> 김실버는 게임을 리뷰하는 사람이 아니라,  
> 게임이 유저의 기대를 어떻게 배신하는지 해부하는 사람.

- 잘 맞는 방향: 게임사 운영 논란·배신감 해부형
- 약한 방향: 맥락 없는 플레이 일지형
- 시청자 기대: 빠른 렉카보다 겪어본 유저의 구조 해설

이 채널 방향은 과거 정리에서 남은 운영 기준이다. 단, 수치나 사례는 최신 데이터로 다시 확인해야 한다.

## 문서 관리 방식

- `PROJECT_RULES.md`는 영구 규칙만 담는다.
- `README.md`는 프로젝트 입구와 현재 자산 상태만 담는다.
- `문서_인덱스.md`는 문서별 상태와 읽는 조건만 담는다.
- `SESSION_HANDOFF.md`는 다음 세션 인계에 필요한 현재 상태만 담는다.
- `CURRENT_TASK.md`는 현재 작업 또는 새 원본 대기 상태만 담는다.
- 커밋 SHA와 작업트리 상태는 문서에 고정하지 않고 Git 명령으로 확인한다.
- 상태 변경 후에는 위 문서들이 같은 현재 상태를 말하는지 확인한다.

## AI 에이전트 사용 방식

AI 에이전트는 이 폴더를 전부 훑지 않는다.

1. `PROJECT_RULES.md`, `SESSION_HANDOFF.md`, `문서_인덱스.md`를 먼저 끝까지 읽는다.
2. 이어지는 작업이면 `CURRENT_TASK.md`를 읽는다.
3. `문서_인덱스.md`에서 현재 요청에 맞는 단계 문서와 스킬만 고른다.
4. 고른 문서는 끝까지 읽고, 선택하지 않은 긴 참고 문서는 열지 않는다.
5. 작업 완료 직전에는 요청과 결과, 문서 상태, 검증 명령 결과를 다시 확인한다.

## 다시 시작하는 방법

1. 새 작업의 시작 단계를 정하고 `01_유튜브_제작_워크플로우.md`와 해당 단계 스킬 또는 규격을 먼저 확인한다.
2. 새 영상 작업을 시작할 때 `workspace/inputs/`, `workspace/active/`, `workspace/outputs/`, 필요 시 `workspace/rejects/`를 만든다.
3. 촬영 전 콘텐츠는 1단계부터, 촬영 완료본은 5단계부터 시작한다.
4. 컷리스트, XML, 러프컷은 선행 단계 산출물이 확정된 뒤에만 만든다.

## 작업 시 규칙

- 원본 영상, 원본 자막, 사용자가 직접 만든 파일은 절대 덮어쓰지 않는다.
- 산출물은 새 파일로 만든다.
- 삭제된 과거 `workspace/` 또는 `temp/archive/`를 현재 기준으로 삼지 않는다.
- 편집보다 기획 기준을 먼저 확정한다.
- 변경 이력은 Git으로 관리하고, 별도 사본 파일은 만들지 않는다.
