# 전체 워크플로우 단계별 개선 진단

- 작성일: 2026-07-07
- 대상 문서: `01_유튜브_제작_워크플로우.md`, `skills/*/SKILL.md`, `기획_리서치/*`
- 목적: 1~8단계를 실제로 진행할 수 있도록, 각 단계의 현재 상태와 개선 필요점, 개선 방법을 먼저 정리한다.

## 결론 요약

현재 워크플로우는 5단계와 6단계가 가장 구체적이다. 5단계는 대사 기반 메시지 도출 방식으로 개선됐고, 6단계는 기획서 비트를 실제 화면으로 검증하는 방식으로 개선됐다.

반대로 1, 2, 7단계는 스킬은 있으나 완료 기준이 얕다. 3, 4, 8단계는 상위 워크플로우에는 있지만 독립 실행 스킬이 없다. 따라서 이후 개선은 아래 순서가 적절하다.

1. 1단계 소재 조사 스킬 개선
2. 2단계 채널 기획 스킬 개선
3. 3단계 대본 구성 규격/스킬 신설
4. 4단계 자막 생성/정리 규격/스킬 신설
5. 5단계 워크플로우 본문을 v2 기획 규격과 동기화
6. 7단계 편집 자료 생성 스킬 개선
7. 8단계 최종 검수 규격/스킬 신설

실제 문서 개정은 프로젝트 규칙대로 한 번에 한 단계씩 진행한다.

## 조사 근거 요약

- YouTube는 첫 30초 유지율을 제목/썸네일 기대 충족과 연결해 설명한다. 따라서 1~2단계의 소재/콘셉트와 5~8단계의 실제 영상 첫 구간이 같은 약속을 해야 한다.  
  출처: [YouTube Help - Measure key moments for audience retention](https://support.google.com/youtube/answer/9314415)
- YouTube는 CTR을 충분한 노출 이후 장기 비교해야 하며, 클릭베이트는 높은 CTR과 낮은 평균 시청 지속 시간으로 드러날 수 있다고 설명한다. 따라서 1~2단계는 클릭 가능성뿐 아니라 본문 충족 가능성을 같이 검증해야 한다.  
  출처: [YouTube Help - Impressions & click-through-rate FAQs](https://support.google.com/youtube/answer/7628154)
- 자막 파일은 텍스트와 표시 타임스탬프를 포함한다. YouTube는 1시간 이상이거나 오디오 품질이 낮은 영상에서 자동 싱크를 권장하지 않는다고 설명한다. 따라서 4~7단계는 원본 자막을 그대로 컷 경계로 쓰지 않고, 분석용 자막과 업로드용 자막을 분리해야 한다.  
  출처: [YouTube Help - Add subtitles & captions](https://support.google.com/youtube/answer/2734796)
- 페이퍼컷은 인용문, 원본 영상, 타임코드, 보조 메모를 연결해 이야기 구조를 먼저 만드는 방식이다. 단, 글로는 좋아 보여도 영상에서는 성립하지 않을 수 있으므로 재생 검증이 필요하다. 이는 5단계와 6단계를 분리한 현재 방향과 맞다.  
  출처: [Reduct - Paper edits for documentary filmmakers](https://reduct.video/blog/paper-edits-for-documentary-filmmakers/)
- 다큐멘터리 편집 흐름은 자료 정리, 전사/시청, 페이퍼컷, 어셈블리, 러프컷, 파인컷 순서로 제시된다. 이는 현재 워크플로우에서 5단계 기획 후 6단계 분석, 7단계 편집 자료 생성으로 가야 한다는 기준을 보강한다.  
  출처: [Doc Film Academy - 6-step documentary editing workflow](https://www.docfilmacademy.com/blog/6-steps-to-editing-an-engaging-documentary)
- 주제 분석은 통독, 코딩, 후보 주제 생성, 검토, 정의, 작성의 반복 절차를 둔다. 5단계에서 도입한 인용 로그, 코드북, 후보 메시지 비교, 반례 검증은 이 방식과 맞다.  
  출처: [ThematicAnalysis.net - Doing Reflexive TA](https://www.thematicanalysis.net/doing-reflexive-ta/)
- Premiere EDL은 단순한 프로젝트에 적합하고, Final Cut Pro XML도 모든 효과와 오디오 변화가 정확히 이전되지 않을 수 있다. 따라서 7단계는 파일 생성만이 아니라 가져오기 로그, 미디어 연결, 오디오, 시퀀스 검증 수준을 명확히 나눠야 한다.  
  출처: [Adobe Help - Export a project as an EDL file](https://helpx.adobe.com/premiere/desktop/render-and-export/export-files/export-a-project-as-an-edl-file.html), [Adobe Help - Export a project as a Final Cut Pro XML file](https://helpx.adobe.com/premiere/desktop/render-and-export/export-files/export-a-project-as-a-final-cut-pro-xml-file.html)

## 1단계 소재 조사 개선안

### 현재 문제

`game-trend-research`는 유튜브 수요, 방송 수요, 커뮤니티/뉴스 이슈, 채널 적합도를 보지만, 각 근거의 신뢰도와 사용 기준이 부족하다. 지금 방식으로는 “인기 있는 게임”과 “김실버 채널에서 지금 영상으로 만들 만한 소재”가 섞일 위험이 있다.

### 개선 방법

- 자료를 `공식/플랫폼 데이터/커뮤니티 반응/뉴스/개인 추정`으로 등급화한다.
- 각 후보마다 `왜 지금인가`, `시청자가 궁금해하는 질문`, `이미 포화된 영상 각도`, `김실버가 새로 말할 수 있는 각도`를 분리한다.
- 클릭 가능성만 보지 않고, 실제 영상 본문에서 충족 가능한 약속인지 같이 본다. YouTube CTR 자료가 말하는 클릭베이트 위험을 반영한다.
- 후보별로 `채널 적합도`, `제작 가능성`, `증거 확보 가능성`, `리스크`를 점수화하되, 점수보다 판단 근거를 우선한다.

### 반영 대상

- `skills/game-trend-research/SKILL.md`
- `01_유튜브_제작_워크플로우.md` 1단계 완료 기준

### 완료 게이트 제안

- G1. 최소 2종류 이상의 근거가 있는가
- G2. 단순 인기 순위가 아니라 영상 질문으로 바뀌는가
- G3. 김실버가 직접 말하거나 보여줄 수 있는 근거가 있는가
- G4. 제목/썸네일로 약속한 내용을 본문에서 충족할 수 있는가

## 2단계 채널 기획 개선안

### 현재 문제

`youtube-channel-planning`은 소재를 핵심 주장, 시청 이유, 제목/썸네일 방향으로 바꾸지만, 1단계 조사 근거가 어떻게 영상 약속으로 변환되는지 추적이 약하다. 제목/썸네일은 나와도 본문에서 지킬 수 있는지 검증하는 장치가 부족하다.

### 개선 방법

- 1단계의 후보를 바로 기획안으로 쓰지 않고 `시청자 질문`, `김실버 관점`, `본문 증거`, `제목/썸네일 약속`으로 변환한다.
- 제목/썸네일 방향마다 “영상 안에서 반드시 보여줘야 하는 장면/주장/경험”을 적는다.
- YouTube 첫 30초 유지율 기준을 반영해, 도입부가 제목/썸네일 기대와 맞는지 사전 점검한다.
- `말할 수 있는 것`, `직접 해본 뒤에만 말할 수 있는 것`, `말하면 안 되는 추정`을 분리한다.

### 반영 대상

- `skills/youtube-channel-planning/SKILL.md`
- `01_유튜브_제작_워크플로우.md` 2단계 완료 기준

### 완료 게이트 제안

- G1. 핵심 주장이 조사 근거에서 이어지는가
- G2. 제목/썸네일 약속과 영상 본문이 충돌하지 않는가
- G3. 첫 30초에서 시청자가 기대한 질문을 열거나 답하기 시작하는가
- G4. 김실버 채널만의 관점이 단순 감정평/일반 리뷰와 구분되는가

## 3단계 대본 구성 개선안

### 현재 문제

워크플로우에는 대본 구성 단계가 있지만 실제 스킬이 없다. 또한 촬영 전 영상과 촬영 후 실황 편집 영상이 같은 “대본” 개념으로 묶여 있다. 이대로 두면 이미 촬영된 영상에서도 대본이 실제 녹화 내용을 덮어쓰는 문제가 생길 수 있다.

### 개선 방법

- 3단계를 `촬영 전 대본`과 `촬영 후 구성 초안`으로 분리한다.
- 촬영 전에는 주장, 근거, 장면 목적, 직접 확인할 포인트를 만든다.
- 촬영 후에는 대본을 새로 쓰는 것이 아니라 실제 녹화 내용의 사용 가능성을 기록한다.
- 각 문장에 `근거`, `화면 필요`, `직접 플레이 필요`, `추정 위험` 표시를 붙인다.

### 반영 대상

- 새 스킬 신설 후보: `skills/script-planning/SKILL.md`
- 새 규격 문서 후보: `기획_리서치/3단계_대본구성_규격_YYYY-MM-DD.md`
- `01_유튜브_제작_워크플로우.md` 3단계 본문

### 완료 게이트 제안

- G1. 주장마다 근거가 있는가
- G2. 촬영으로 확인해야 할 장면이 정의됐는가
- G3. 촬영 후 영상 내용과 충돌하면 대본이 아니라 실제 녹화가 우선된다는 규칙이 명확한가
- G4. 과장/추정/개발자 의도 단정이 분리 표시됐는가

## 4단계 자막 생성/정리 개선안

### 현재 문제

워크플로우에는 자막 생성/정리가 있으나 독립 스킬이 없다. 현재 프로젝트 규칙상 원본 자막은 보존해야 하고, SRT 경계는 컷 경계로 쓰면 안 된다. 그런데 4단계 문서는 분석용 자막, 편집용 대사 자료, 업로드용 자막을 구분하지 않는다.

### 개선 방법

- 원본 자막은 절대 수정하지 않고, 정리본은 새 파일로 만든다.
- 자막 산출물을 세 종류로 나눈다.
  - 원본 보존본: 자동 전사/SRT 원형
  - 분석용 대사본: 통독, 인용 로그, 기획용
  - 업로드용 자막: 맞춤법, 줄바꿈, 타이밍 품질 보정
- YouTube 자막 도움말 기준을 반영해, 긴 영상/오디오 품질 불량 영상은 자동 싱크 신뢰도를 낮게 본다.
- 5~7단계에서 쓰는 자막 타임코드는 “위치 힌트”이지 컷 경계가 아니라는 점을 4단계 산출물에 명시한다.

### 반영 대상

- 새 스킬 신설 후보: `skills/subtitle-prep/SKILL.md`
- 새 규격 문서 후보: `기획_리서치/4단계_자막정리_규격_YYYY-MM-DD.md`
- `01_유튜브_제작_워크플로우.md` 4단계 본문

### 완료 게이트 제안

- G1. 원본 자막이 보존됐는가
- G2. 정리본이 새 파일로 저장됐는가
- G3. 분석용 수정과 업로드용 수정이 구분됐는가
- G4. 타임코드 신뢰도와 컷 경계 사용 금지가 표시됐는가

## 5단계 영상 기획 개선안

### 현재 상태

5단계는 이미 개선됐다. `기획단계_규격_2026-07-06.md` v2에서 통독, 인용 로그, 코드북, 후보 메시지 비교, 컨트롤링 아이디어, 대사 스파인, 반례 검증, 6단계 검증 브리프까지 정의했다.

### 남은 문제

`01_유튜브_제작_워크플로우.md`의 5단계 본문은 아직 v2 규격 전체와 완전히 동기화되지 않았다. 현재 본문은 큰 방향은 맞지만, 인용 로그, 후보 메시지 비교, 포함/제외 기준, 반례 검증, 6단계 브리프가 완료 기준에 충분히 드러나지 않는다.

### 개선 방법

- 워크플로우 5단계 본문을 v2 규격에 맞게 요약 갱신한다.
- 워크플로우에는 세부 절차를 길게 복사하지 않고, 완료 게이트와 산출물 이름만 명확히 둔다.
- 6단계 입력으로 필요한 항목을 고정한다.

### 반영 대상

- `01_유튜브_제작_워크플로우.md` 5단계 본문
- 필요 시 `기획_리서치/기획단계_규격_2026-07-06.md` 템플릿 보강

### 완료 게이트 제안

- G1. 컨트롤링 아이디어가 원본 대사 인용으로 추적되는가
- G2. 대사 스파인이 소리만으로 이야기 흐름을 만든다는 테스트를 통과하는가
- G3. 포함/제외 기준이 있어 6단계가 후보를 흔들지 않는가
- G4. 6단계 검증 질문이 명확한가

## 6단계 영상 분석 개선안

### 현재 상태

6단계는 이미 개선됐다. `gameplay-video-analysis`는 5단계 기획서 비트를 화면, 오디오, 맥락으로 검증하고, 7단계가 사용할 후보지도와 인계 브리프를 만드는 방식으로 개정됐다. 워크플로우 6단계도 이 기준을 반영했다.

### 남은 문제

현재 남은 문제는 방식 자체보다 실제 적용이다. 앞으로 영상 작업에서 6단계를 실행할 때, 하이라이트를 새로 찾는 방식으로 되돌아가지 않아야 한다.

### 개선 방법

- 6단계 산출물 이름을 실제 작업 파일명에 고정한다.
- 6단계 후보지도에는 반드시 `기획서 bit_id`, `story_function`, `screen_evidence`, `decision`, `risk`, `7단계 인계 메모`가 들어가야 한다.
- 화면 확인이 안 된 후보는 대표 후보가 아니라 재검증 후보로 둔다.

### 반영 대상

- 이미 반영됨: `skills/gameplay-video-analysis/SKILL.md`
- 이미 반영됨: `01_유튜브_제작_워크플로우.md` 6단계
- 실제 작업 산출물 템플릿은 6단계 실행 시 생성

### 완료 게이트 제안

- 기존 G1~G5 유지
- 추가 운영 규칙: 6단계에서는 컷리스트, XML, 러프컷을 만들지 않는다.

## 7단계 편집 자료 생성 개선안

### 현재 문제

`premiere-editing-export`는 XML, EDL, CSV, 러프컷 생성 방법은 갖고 있다. 하지만 6단계 후보지도에서 실제 컷리스트로 넘어가는 판단 기준이 부족하다. 즉 “어떤 후보를 어느 경계로 잘라서 어떤 순서로 둘 것인가”가 아직 자동화 생성 단계 안에 충분히 들어오지 않았다.

### 개선 방법

- 7단계 시작 입력을 `컷리스트`가 아니라 `6단계 후보지도 + 7단계 인계 브리프`로 확장한다.
- 먼저 후보지도를 기준으로 컷리스트 초안을 만든 뒤, 컷 경계 검증을 통과해야 XML/EDL/러프컷을 만든다.
- 프로젝트 규칙의 컷 경계 검증을 7단계 필수 게이트로 둔다. SRT 경계는 위치 힌트일 뿐이고, XML 생성 전 경계 스캔이 필요하다.
- Adobe EDL/XML 문서 기준을 반영해 검증 수준을 나눈다.
  - 파일 생성됨
  - 구조 검사 통과
  - Premiere 가져오기 시도
  - 미디어 연결 확인
  - 오디오 확인
  - 시퀀스 재생 확인
- Premiere에서 직접 확인하지 않았으면 `App-validated`라고 쓰지 않는다.

### 반영 대상

- `skills/premiere-editing-export/SKILL.md`
- `01_유튜브_제작_워크플로우.md` 7단계 완료 기준

### 완료 게이트 제안

- G1. 모든 컷이 6단계 후보지도 또는 인계 브리프에 연결되는가
- G2. 컷 경계가 문장 단위 완결과 VAD/자막 가드 기준을 통과했는가
- G3. 원본 파일 참조와 오디오가 유지되는가
- G4. XML/EDL/러프컷의 검증 수준이 명확히 표시됐는가
- G5. Premiere에서 직접 확인하지 않은 산출물을 확정본처럼 말하지 않는가

## 8단계 최종 검수 개선안

### 현재 문제

8단계는 워크플로우에만 있고 독립 스킬이 없다. 확인 항목은 있으나 “어떤 문제가 나오면 어느 단계로 돌아갈지”가 부족하다. 최종 검수는 단순 오탈자/오디오 확인이 아니라, 5단계 기획 의도가 최종 영상에 실제로 남았는지 확인하는 통제 루프가 되어야 한다.

### 개선 방법

- 8단계 검수를 `기획 검수`, `구조 검수`, `기술 검수`, `자막 검수`, `업로드 전 검수`로 나눈다.
- 5단계 컨트롤링 아이디어와 7단계 결과물이 맞는지 먼저 본다.
- 첫 30초가 제목/썸네일 기대와 맞는지 확인한다.
- 자막, 오디오, 원본 보호, 컷 누락, 게임 한 판 결과 보존 여부를 체크한다.
- 실패 시 되돌아갈 단계를 정한다.
  - 메시지가 안 보이면 5단계로 복귀
  - 화면 근거가 약하면 6단계로 복귀
  - 컷 경계/오디오 문제가 있으면 7단계로 복귀
  - 제목/썸네일 약속이 안 맞으면 2단계 또는 메타데이터 조정으로 복귀

### 반영 대상

- 새 스킬 신설 후보: `skills/final-video-review/SKILL.md`
- 새 규격 문서 후보: `기획_리서치/8단계_최종검수_규격_YYYY-MM-DD.md`
- `01_유튜브_제작_워크플로우.md` 8단계 본문

### 완료 게이트 제안

- G1. 완성본이 5단계 컨트롤링 아이디어를 담고 있는가
- G2. 첫 30초가 제목/썸네일 기대와 충돌하지 않는가
- G3. 오디오, 자막, 컷 경계, 원본 참조 문제가 없는가
- G4. 영상 안에서 필요한 사건 결과와 반응이 잘리지 않았는가
- G5. 실패 항목이 있으면 되돌아갈 단계가 명확한가

## 단계 간 연결 개선안

각 단계의 산출물이 다음 단계의 입력으로 명확히 이어져야 한다.

| 이전 단계 | 다음 단계로 넘길 핵심 입력 |
|---:|---|
| 1 → 2 | 후보 소재, 근거 등급, 시청자 질문, 시기성, 포화도, 채널 적합도 |
| 2 → 3 | 핵심 주장, 제목/썸네일 약속, 첫 30초 기대, 본문에서 보여줄 경험 |
| 3 → 4 | 촬영/녹화 기준, 말할 내용, 확인해야 할 장면 |
| 4 → 5 | 원본 자막, 분석용 대사본, 타임코드 신뢰도 |
| 5 → 6 | 컨트롤링 아이디어, 대사 스파인, 감정 아크, 포함/제외 기준, 검증 브리프 |
| 6 → 7 | 후보지도, 대표/예비/제외, 화면 근거, 위험, 보존 맥락 |
| 7 → 8 | 컷리스트, XML/EDL/러프컷, 검증 수준, 사용 방법, 미확인 위험 |
| 8 → 이전 단계 | 실패 항목별 복귀 단계 |

## 리스크와 방지책

### 리스크 1. 단계가 너무 무거워져 작업 속도가 느려짐

방지책: 모든 단계에 풀 리서치를 강제하지 않는다. 단계별로 `필수 게이트`와 `선택 심화`를 나눈다.

### 리스크 2. 문서끼리 같은 내용을 반복함

방지책: 워크플로우는 단계 목적과 완료 기준만 둔다. 세부 절차는 각 스킬 또는 규격 문서에 둔다.

### 리스크 3. 6단계 이후 다시 하이라이트 모으기로 퇴행함

방지책: 6단계와 7단계 모두 `5단계 bit_id` 연결을 필수 필드로 둔다.

### 리스크 4. 자동 생성 파일을 검증 완료처럼 착각함

방지책: 7단계에 검증 수준 라벨을 둔다. Premiere에서 직접 확인하지 않은 결과는 `App-validated`가 아니다.

### 리스크 5. 제목/썸네일과 실제 영상이 어긋남

방지책: 2단계에서 제목/썸네일 약속을 만들고, 8단계에서 첫 30초와 본문 충족 여부를 다시 확인한다.
