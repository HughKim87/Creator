# User-Data Work Rules

- Purpose: govern authorized work on an exact user or task item under `inputs/` or `outputs/`.
- Read when: after the user identifies the exact protected item and purpose, before any access to that item.
- Owner: user-approved policy; project agents maintain accepted wording.
- Authority: task-specific; `PROJECT_RULES.md` remains higher authority.

## Rules

- Confirm the exact item, requested outcome, permitted reads and writes, and destination before access.
- Access only that item and the minimum directly required metadata. Do not enumerate sibling files or directories.
- Never overwrite, rename, move, or delete a user original without explicit authorization for that action.
- Keep originals in `inputs/` and task-derived results in `outputs/`; do not promote user-specific facts or artifacts into framework files.
- Never stage, commit, index globally, or include protected material in reusable reports or caches.
- Reuse an unchanged derivative when appropriate. Preserve prior results unless the user requests replacement or cleanup.
- Report what was accessed and produced only within the user's named scope.
