## 2. 문서 상태 체계

문서와 산출물은 아래 역할 상태 중 하나로 취급한다. `Generated`, `Tool-validated` 같은 검증 수준은 `PROJECT_RULES.md`의 별도 라벨이며, 아래 상태와 섞지 않는다.

| 상태 | 의미 | 사용 조건 |
|---|---|---|
| 기준 | 현재 판단 기준으로 사용 가능 | 해당 단계에서 먼저 읽는다 |
| 현재작업 | 지금 작업의 목표와 금지 범위 | 세션 이어갈 때 읽는다 |
| 참고 | 배경 이해용 | 직접 기준으로 삼지 않는다 |
| 산출물 | 특정 작업 결과 | 게이트 통과 후 다음 단계 입력 가능 |
| 폐기 | 더 이상 사용하지 않음 | 읽거나 인용하지 않는다 |
| 보류 | 정확성 미확정 | 사용자 확인 전 사용하지 않는다 |

## 6. AI 에이전트 로드 맵

에이전트는 문서를 한꺼번에 전부 열지 않는다. 아래 순서로 필요한 문서만 선택하고, 선택한 지시 문서는 끝까지 읽는다.

| 단계 | 판단 질문 | 읽을 문서 |
|---:|---|---|
| 1 | 시작 커널과 문서 라우터는 무엇인가 | `PROJECT_BOOTSTRAP.md`, `docs/INDEX.md` |
| 2 | 이어지는 현재 작업이나 상태 확인인가 | `SESSION_HANDOFF.md`, `CURRENT_TASK.md` |
| 3 | 전체 규칙 트리거 조건이 있는가 | `PROJECT_RULES.md` |
| 4 | 전체 단계 판단이 필요한가 | `01_유튜브_제작_워크플로우.md` |
| 5 | 특정 단계 작업인가 | 해당 단계 기준 문서 또는 `skills/*/SKILL.md` |
| 6 | 도구 실행이 필요한가 | `tools/README.md`, 해당 도구 도움말 |
| 7 | 프로젝트 구조나 문서 체계를 바꾸는가 | `PROJECT_RULES.md`, `docs/AGENT_MAINTENANCE.md` |
| 8 | 배경 판단이 필요한가 | 상태가 `참고`인 문서 |
| 9 | 과거 이력 확인이 필요한가 | Git 이력. 폐기 문서는 현재 기준으로 읽지 않음 |

로드 최적화 원칙:

- 기본 로드 문서는 짧아야 한다. 길어지면 기준 문서와 참고 문서로 분리한다.
- 전체 규칙 문서는 항상 주입하지 않는다. 부트스트랩 트리거 조건이 있을 때만 연다.
- `기준` 문서는 판단 기준이고, `참고` 문서는 배경 설명이다.
- `현재작업` 문서는 지금 할 일과 하지 않을 일만 담는다.
- `폐기` 문서는 존재하더라도 현재 작업 입력으로 쓰지 않는다.
- 긴 리서치 보고서는 기본 로드하지 않고, 필요한 단계에서만 연다.
- 문서 안에 다른 문서의 절차를 복사하지 않는다. 경로와 읽는 조건만 연결한다.

## 9. 새 문서 생성 게이트

새 문서는 아래 질문에 모두 통과할 때만 만든다.

1. 기존 현재 기준 문서에 추가하면 안 되는가?
2. 기존 참고 문서의 섹션 추가로 충분하지 않은가?
3. 다음 세션에서 다시 찾을 만큼 비자명한 결정·근거·함정인가?
4. 새 문서가 대체할 기존 문서가 있는가?
5. 만들자마자 이 인덱스에 상태, 읽는 조건, 대체 관계를 등록할 수 있는가?

하나라도 아니면 새 문서를 만들지 않는다.

## 11. 작업 종료 전 자가 검증 로드

작업 완료 직전에는 아래 문서를 다시 확인한다.

| 확인 대상 | 목적 |
|---|---|
| 최신 사용자 요청 | 실제 결과가 요청과 맞는지 확인 |
| `PROJECT_BOOTSTRAP.md` | 최소 시작 로드 정책이 맞는지 확인 |
| `CURRENT_TASK.md` | 이번 작업의 금지 범위와 검증 기준 확인 |
| 수정한 기준 문서 | 새 상태 문구가 충돌하지 않는지 확인 |
| `tools\run_doccheck.bat` | 문서 상태, 폐기 참조, 과거 경로, 스킬 필수 섹션 검사 |
| `git status --short` | 남은 변경 파일 확인 |
| `git diff --check` | 공백 오류 확인 |
| `rg` 상태 검색 | 오래된 참조, 동적 상태 문구, 폐기 문서 재참조 확인 |

최종 답변에는 수행한 검증과 수행하지 못한 검증을 구분해서 적는다.
