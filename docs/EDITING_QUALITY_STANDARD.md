# 편집 품질 일관성 기준

## 목적

전체 영상의 앞·중간·뒤가 같은 품질로 편집되도록 7단계의 판단 과정과 승격 조건을 고정한다.
여기서 같은 품질은 모든 컷 길이와 밀도가 같다는 뜻이 아니다. 같은 수준의 근거, microbeat 분해,
예외 설명, 검증을 거쳤다는 뜻이다.

이 문서는 `PROJECT_RULES.md`의 안전 규칙을 반복하지 않는다. 7단계 편집 품질에만 적용한다.

## 핵심 원칙

1. 후보범위는 실제 컷이 아니다. 후보범위 안을 정보·행동·리액션·상태 변화로 다시 나눈다.
2. `문장 보존`은 후보범위 전체 보존이 아니다. 핵심 문장의 의미와 순서만 보존하고 문장 사이의
   저정보 대기·반복은 별도로 판단한다.
3. 긴 컷은 실패가 아니다. 사건 화면, 연결 문장, 감정 누적, UI 변화처럼 길이를 설명할 근거가
   있으면 유지한다.
4. 컷 수를 늘리는 것 자체를 품질 개선으로 간주하지 않는다. 제거한 시간과 남긴 정보의 관계를 본다.
5. 초반 캘리브레이션만으로 전체 확장을 승인하지 않는다. 초반·중간·후반에서 각각 표본을 검증한다.
6. 자동 감사는 편집 판단을 대신하지 않는다. 편차와 설명 누락을 검토 대상으로 올리는 장치다.

## 모드별 동일 판단 기준

| 모드 | 유지 | 압축 | 자동 감사 기본 경고선 |
|---|---|---|---|
| 압축 | 새 정보·새 행동·필수 설정 | 자기정정, 반복 설명, 저정보 멈춤 | 평균 6초 초과 또는 단일 12초 초과 |
| 라디오 | 의미가 연결된 문장·감정 변화 | 문장 사이 대기, 같은 뜻 반복, 화면 이동만 있는 구간 | 평균 10초 초과 또는 단일 18초 초과 |
| 호흡 | 사건→반응→결과, 공포 누적, 실제 화면 변화 | 사건 전후의 기능 없는 배회 | 평균 18초 초과 또는 단일 45초 초과 |
| 훅 | 문맥→피크→종료 신호 | 설명 과잉, 결말 노출 | 평균 15초 초과 또는 단일 30초 초과 |

경고선은 목표 컷 길이가 아니다. 넘으면 자르라는 뜻이 아니라, 긴 이유를 다시 확인하고 기록하라는 뜻이다.
프로젝트 캘리브레이션이 다른 값을 입증하면 프로필에서 예외 처리하되 근거를 쓴다.

## 훅 품질 규칙

훅은 아래 세 기능을 모두 가져야 한다.

1. 문맥: 무엇이 위협인지 최소한 이해할 수 있다.
2. 피크: 행동·감정·질문의 최고점이 있다.
3. 종료 신호: 대사 뒤 잔향, 반응 완료, 의도한 스매시컷 중 하나가 있다.

대사 마지막 프레임에서 곧바로 인트로로 넘어가면 기본 검토 대상이다. 자연 잔향은 보통 0.5~1.5초를
첫 검토값으로 쓰되, 화면·공간음·의도에 따라 달라질 수 있다. 의도한 스매시컷이면 이유를 기록한다.

## 비트별 필수 기록

각 비트는 전체 XML 전에 아래 내용을 가져야 한다.

- 이야기 기능과 편집 모드
- 원본 후보범위
- 유지할 microbeat
- 압축·제거할 microbeat
- 실제 컷 수와 선택 길이
- 최장 컷 ID와 길게 유지한 이유
- 화면·자막·오디오 경계 근거
- 사용자 피드백 또는 캘리브레이션과 다른 점

후보범위를 한 줄의 실제 컷으로 옮겼다면 `왜 내부 분해가 불필요한지`가 반드시 있어야 한다.

## 초반·중간·후반 표본

전체 확장 전 최소 세 위치를 비교한다.

| 위치 | 필수 확인 |
|---|---|
| 초반 | 셋업의 정보 압축과 훅→본편 연결 |
| 중간 | 대표 사건의 호흡과 반복 제거 |
| 후반 | 피로 누적으로 컷 판단이 느슨해지지 않았는지, 결론 문장 보존 |

세 위치의 컷 길이가 같을 필요는 없다. 각 위치에서 동일하게 microbeat 기록과 최장 컷 근거가 있어야 한다.

## 품질 승격 게이트

| 게이트 | 통과 조건 | 실패 시 |
|---|---|---|
| Q0 입력 | 기획 비트·후보지도·원본·자막이 연결됨 | 7A로 돌아감 |
| Q1 캘리브레이션 | 압축·라디오·호흡과 초·중·후반 표본 확인 | 대표 표본 추가 |
| Q2 microbeat | 모든 비트에 유지·압축·제거와 최장 컷 근거 존재 | 7B 보완 |
| Q3 자동 감사 | `REVIEW_REQUIRED`가 없거나 근거 있는 예외로 처리됨 | 해당 비트 재검토 |
| Q4 레드팀 | 훅 급절단, 후반 통구간, 거짓 인과, 반복 장면을 반대 관점에서 검사 | 컷리스트 새 버전 |
| Q5 구조 | XML 프레임·링크·시퀀스·NUL·검증 페이지 통과 | 생성기/입력 수정 |
| Q6 앱·사용자 | Premiere 전체 재생과 사용자 컷 흐름 확인 | App-validated 금지 |

Q0~Q4를 통과하기 전에 전체 XML을 최신 기준으로 승격하지 않는다. XML 생성 자체는 진단용으로 가능하지만
가이드와 핸드오프에 `quality_review_required`를 표시한다.

## 자동 감사 프로필

`tools/edit_quality_audit.py`는 콘텐츠 기준 단일 시퀀스 CSV와 프로필 CSV를 읽는다.
멀티시퀀스 CSV는 같은 컷이 중복되므로 입력으로 사용하지 않는다.

프로필 컬럼:

```text
section,mode,waive,justification
```

- `section`: `HOOK`, `B01` 같은 구간 ID
- `mode`: `hook`, `compress`, `radio`, `breath`
- `waive`: 근거를 확인한 경고 코드. 여러 개면 `|`로 구분
- `justification`: 화면·문장·사건을 근거로 한 예외 설명

감사 코드:

- `AVG_LONG`: 구간 평균 컷 길이가 모드 경고선을 넘음
- `MAX_LONG`: 가장 긴 컷이 모드 경고선을 넘음
- `SINGLE_BLOCK`: 압축/라디오 구간이 8초를 넘는 한 컷으로만 구성됨
- `LATE_DENSITY_CLIFF`: 후반의 컷당 평균 길이가 초반의 1.5배를 넘음
- `MISSING_PROFILE`: 컷 구간에 프로필이 없음
- `MISSING_CUTS`: 프로필에 정의한 구간의 실제 컷이 없음

예외는 경고를 삭제하지 않고 `WAIVED`로 남긴다. `waive`가 있는데 설명이 없으면 프로필 오류다.

## 실행 예시

```powershell
python tools/edit_quality_audit.py `
  outputs/07_edit_export/cutlist_full.csv `
  outputs/07_edit_export/edit_quality_profile.csv `
  --output outputs/07_edit_export/edit_quality_audit.md
```

보고서가 `REVIEW_REQUIRED`이면 해당 비트의 7B 기록을 다시 읽고 경계를 재설계하거나 예외 근거를 작성한다.

## 레드팀

- 자동 경고를 없애려고 근거 없는 예외를 추가하면 품질 게이트가 무력화된다.
- 컷을 촘촘하게 만드는 데만 집중하면 공포·감정·행동의 연속성이 깨질 수 있다.
- 후반 밀도만 맞추려 초반의 과도한 마이크로컷을 기준으로 삼으면 잘못된 기준을 전파한다.
- 한 번 통과한 프로필도 컷 경계나 이야기 기능이 바뀌면 다시 감사한다.

## 중단 규칙

같은 사용자 진행 요청 안에서 같은 품질 결함을 수정하고 감사했는데 3회 연속
`REVIEW_REQUIRED`의 원인이 동일하면 중단한다. 새 진행·계속·재개 요청마다 횟수는 0으로
초기화하며 과거 핸드오프 기록을 합산하지 않는다. 세부 범위는 `PROJECT_RULES.md`를 따른다.
마지막 확인 원인, 계속 수정할 위험, 다시 조사할 원본 구간과 기준을 보고하고 사용자 결정을 기다린다.
