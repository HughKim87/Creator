# 변경 제안 0001 — SDD 강제 체계

- 역할: 프레임워크 변경이 문서 기준으로만 진행되도록 강제하는 체계 도입.
- 읽는 시점: 이 제안이 적용·검증될 때까지. 적용 후에는 상태만 갱신한다.
- 상태: 검토 대기 (사용자 승인 후에만 적용)
- 근거 원칙: P2(신뢰 대신 검증 — 강제 사다리의 오른쪽 이동), P3(에이전트 교체 가능 — 벤더 중립 초크포인트)

## 문제

SDD(문서 기준 작업)가 규칙 문서로만 존재해 에이전트가 무시한 채 작업하는
경우가 잦다. 원인: 강제가 아닌 권고, 준수 비용이 우회 비용보다 큼,
비공식 긴급 우회의 반복, 위반의 비가시성.

## 변경 내용

1. `docs/changes/` — 변경 제안 문서 보관소. 프레임워크 변경은 여기의
   제안 문서에서 출발한다.
2. `tools/sdd_gate.py` — 3개 명령:
   - `check`: commit-msg 훅에서 실행. 프레임워크 파일이 스테이징된 커밋은
     제안 문서 동반, `[change: <id>]` 태그, 또는 `[waiver: <사유>]` 태그가
     있어야 통과.
   - `propose <id> <제목>`: 제안 문서 템플릿을 1초에 생성 (마찰 제거).
   - `audit`: 최근 프레임워크 커밋의 SDD 준수율 보고 (가시화).
3. `.githooks/commit-msg` — 모든 에이전트·모든 도구에 벤더 중립으로 적용
   되는 초크포인트.
4. waiver는 사용자 명시 승인 시에만 사용하고 커밋 메시지에 영구 기록된다.

## 영향 파일

- 신규: `docs/changes/`(이 문서), `tools/sdd_gate.py`,
  `.githooks/commit-msg`, `tests/test_sdd_gate.py`
- 수정: `docs/INDEX.md`(라우터), `tools/README.md`(사용법)

## 검증 계획

- 단위 테스트: 프레임워크 diff + 태그 없음 → 차단 / 제안 동반 → 통과 /
  waiver → 통과 / outputs·inputs만 변경 → 통과.
- doccheck 오류 0, 전체 pytest 통과.
- 이 제안의 적용 커밋 자체가 게이트를 통과해야 한다.

## 후속 (이 제안 범위 밖)

- Claude PreToolUse 훅에서 기준 문서 없는 프레임워크 편집 조기 차단.
- CI에 `sdd_gate.py audit` 리포트 추가.
