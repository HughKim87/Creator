# 프로젝트 사용 가이드

- 목적: 사용자가 현재 프로젝트 기반의 사용 방법, 문서 역할, 승인 단계와 아직 구현되지 않은 기능을 확인할 수 있게 한다.
- 사용 시점: 새 작업을 요청하거나 단계 결과를 승인하거나 프로젝트의 현재 능력을 확인할 때 사용한다.
- 작성·수정 주체: 에이전트가 현재 구현과 검증 결과에 맞춰 유지하고, 정책과 작업 범위는 사용자가 승인한다.
- 언어: 한국어.
- 저장 위치와 연결 관계: `docs/user/GUIDE.md`. [프로젝트 소개](../../README.md), [현재 인수인계](../../SESSION_HANDOFF.md), [문서 지도](../agent/DOCUMENT_MAP.md), [설계 보고서](../reports/2026-07-20_프로젝트_기반_및_지식_시스템_설계.md)와 연결한다.

## 현재 사용할 수 있는 기반

- 모든 세션에서 읽는 공통 프로젝트 규칙
- 작업별 문서를 선택하는 시작 라우터와 문서 지도
- 작업 범위 설정, 변경, 검증, 보고, 인수인계의 공통 절차
- 지식 데이터, 검색 컨텍스트, 오래된 지식 검토를 위한 구현 전 계약
- 다음 세션이 채팅 기억 없이 재개할 수 있는 단일 인수인계 문서

지식 레코드 writer, SQLite 검색, 자동 컨텍스트 패키지와 기존 영상 제작 도구는 아직 구현되지 않았다. 문서에 적힌 미래 동작은 현재 기능으로 간주하지 않는다.

## 작업 요청과 승인

1. 원하는 결과와 작업 범위를 지정한다.
2. 사용자 데이터가 필요하면 정확한 작업이나 산출물을 지정한다.
3. 단계형 작업에서는 에이전트가 현재 단계만 수행하고 한국어로 결과와 검증 수준을 보고한다.
4. 결과를 확인한 뒤 다음 단계 진행 여부를 명시한다.
5. 중요한 정책·기술 선택은 근거와 선택지를 기록한 뒤 승인한다.

“진행해”와 같은 승인은 직전 보고서에 명시된 바로 다음 단계에만 적용한다. 이후 단계까지 한꺼번에 승인한 것으로 해석하지 않는다.

## 데이터 안전 경계

- `backup/`은 역사 자료이며 수정하지 않는다.
- `inputs/`, `outputs/`는 사용자가 정확한 작업이나 산출물을 지정한 경우에만 필요한 범위를 읽는다.
- 검색 인덱스가 생기더라도 보호 데이터는 전역 색인에서 기본 제외한다.
- 비밀, 인증 정보, 개인 절대 경로와 모델의 숨은 추론은 프로젝트 지식으로 저장하지 않는다.
- 검색 결과와 자동 요약은 출처 정본을 대신하지 않는다.

## 이후 지식 시스템의 사용 모습

승인 후 다음 단계에서 작업 기록, 세션 요약, 검증 지식, 결정, 실패 사례, 관계를 서로 분리해 저장한다. 검색은 정확한 문서 경로와 ID를 먼저 사용하고, 필요한 경우에만 전문 검색과 관계 확장을 수행한다. 결과에는 원본 파일·작업 event·공식 URL까지 이어지는 출처가 포함된다.

벡터 검색, 전용 그래프 DB, Obsidian은 처음부터 필수로 설치하지 않는다. 최소 검색의 실제 평가에서 필요성이 확인될 때 별도로 제안한다.

## 현재 다음 단계

프로젝트 기본 기반 구축 결과를 사용자가 승인하면, 지식 시스템의 첫 구현 단계인 기록 유형·스키마·검증 기반을 구축한다. 승인 전에는 데이터베이스나 RAG를 만들지 않는다.
