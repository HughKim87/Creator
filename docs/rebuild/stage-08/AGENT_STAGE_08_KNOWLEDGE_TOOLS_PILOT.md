# 단계 08 작업 지시서: MkDocs 이후 Obsidian·Graphify 선택 파일럿

## 1. 단계 목적

Obsidian과 Graphify가 핵심 안정성 계층이 아니라는 전제 아래 실제 탐색 효율을 측정하고,
효과가 비용과 유지 부담보다 클 때만 제한적으로 유지한다. 두 도구는 서로 독립적으로
평가하며 하나의 성공이 다른 하나의 도입 근거가 되지 않는다.

## 2. 공통 시작 게이트

- 단계 07까지 핵심 워크플로, DB, 복구, 문서 빌드가 정상이다.
- 두 도구 없이도 전체 실행·검증·복구가 가능하다.
- 설치일 기준 버전, 라이선스, 네트워크 동작, 가격을 공식 자료로 재확인한다.
- 설치, 외부 모델 호출, Sync 결제는 각각 사용자 승인을 받는다.
- 파일럿 전 Git 상태와 공통 설정 파일을 기록한다.

공용 `.gitignore`, `pyproject.toml`, `uv.lock`, MCP 설정의 변경·복구는 조정 에이전트만
수행한다. Obsidian·Graphify 평가 에이전트는 격리 설정과 증거 경로만 쓴다.

## 3. 공통 금지 사항

- 도구를 워크플로 상태 정본으로 사용
- 단계 승인, 테스트 통과, 산출물 등록을 도구가 결정
- `backup/`, 외부 작업 공간, 원본·산출물 미디어 인덱싱
- 자동 훅·`AGENTS.md`·CLI 설정 변경 허용
- 파일럿 결과를 바로 Git에 커밋
- 민감 문서나 미디어를 승인 없이 원격 모델에 전송
- 하나의 파일럿에서 두 도구를 동시에 처음 도입

# A. Obsidian 파일럿

## A-1. 용도

Obsidian은 사람이 Markdown 문서를 탐색하고 링크 관계를 확인하는 선택적 뷰어다. 작업
상태, 승인, 실패 기록을 수동 입력하는 정본이 아니다.

## A-2. 시작 조건

- `docs/` 구조와 MkDocs 엄격 빌드가 통과했다.
- 중복 규칙과 낡은 문서가 정리됐다.
- 생성 문서와 수동 문서가 명확히 구분된다.

## A-3. 설정

- 기존 `docs/` Markdown을 그대로 vault로 연다.
- 별도 복제 vault를 만들지 않는다.
- Restricted Mode를 유지한다.
- 초기에는 커뮤니티 플러그인을 설치하지 않는다.
- Obsidian Sync를 즉시 구매하지 않는다.
- `.obsidian/workspace*.json` 등 개인 UI 상태를 Git에서 제외한다.
- 생성 상태 문서를 Obsidian에서 수동 편집하지 않는다.
- 그래프를 꾸미기 위한 의미 없는 링크를 추가하지 않는다.
- `docs/index.md`를 유일한 탐색 시작점으로 둔다.
- 실제 프로젝트 상태나 핸드오프를 framework `docs/` 안에 생성하지 않는다.
  `docs/index.md`에는 외부 작업 공간의 `generated/SESSION_HANDOFF.md`를 찾는 CLI와
  locator 규칙만 설명하며, 실제 상태 파일은 vault 밖에 둔다.

## A-4. 2주 평가 과제

Obsidian을 열기 전에 Markdown·MkDocs와 기존 검색만으로 난이도가 같은 과제 세트를
수행해 탐색 시간, 정답률, 잘못된 문서 선택, 클릭·검색 수 기준선을 기록한다.

- 신규 에이전트 시작 문서 찾기
- 상태 전이 규칙 찾기
- 장애 복구 절차 찾기
- 특정 ADR의 결정 이유 찾기
- 코드 기능과 관련 문서 연결 찾기
- 최신 외부 생성 핸드오프를 찾는 명령과 locator 규칙 찾기
- 오래되거나 중복된 문서 발견
- 깨진 링크 확인
- 작업 시작에 필요한 문서 수 측정
- 잘못 편집된 생성 문서 탐지

각 과제의 탐색 시간, 실패, 잘못된 문서 선택을 기록한다.

## A-5. 유지 기준

- 대표 문서 탐색 시간 평균 2분 이내
- 기준선보다 탐색 시간이 20% 이상 감소하거나, 수치 감소가 작을 때 사용자가 기록된
  정성 이득을 명시적으로 승인
- 별도 상태 정본 생성 0건
- 생성 문서 수동 편집 0건
- 오래된 복제 문서 증가 0건
- MkDocs와 충돌 0건
- 월 유지보수 예상 1시간 이하
- 사용자가 실제 탐색 효율 향상에 동의

기준을 충족하지 못하면 `.obsidian` 설정만 제거하고 Markdown·MkDocs는 그대로 둔다.

# B. Graphify 파일럿

## B-1. 용도

Graphify는 코드 호출 관계, 변경 영향 후보, 구현·테스트 연결 탐색을 보조한다. 상태,
승인, 테스트, 입력 무결성, 전환 결정을 맡기지 않는다.

## B-2. 시작 조건

- 신규 `src/`, `tests/` 구조가 안정화됐다. `docs/` 분석은 별도 2차 파일럿이다.
- 핵심 수직 흐름과 전환이 완료됐다.
- Graphify 없는 기준 탐색 측정을 먼저 수행했다.
- 설치 시점의 정확한 버전을 고정할 수 있다.
- 원격 모델을 쓸 경우 사용자 승인과 비용 상한이 있다.

작성 기준일 최신 Graphify가 빠르게 변경되는 pre-1.0 계열이라는 사실은 참고만 하고,
실행 에이전트가 당일 공식 PyPI·저장소에서 버전과 보안 동작을 재검증한다.

## B-3. 기준 질문

설치 전에 기존 검색만으로 다음 대표 질문 10개의 정답, 근거, 시간, 컨텍스트를 기록한다.

1. `source_id` 불변조건 구현 위치
2. 승인 없는 전이를 막는 코드
3. Premiere XML 진입점과 테스트
4. 산출물 스키마 변경 영향 범위
5. 종료 코드 전달 테스트
6. FFmpeg가 도메인 계층을 침범하는지
7. 입력 해시 변경 차단 지점
8. 사람 A/V 승인과 기술 검사 분리 위치
9. 실패 증거 보존 경로
10. 문서와 코드 계약 불일치

## B-4. 설치·실행 제한

- 정확한 버전을 격리 환경에 고정한다.
- 1차 code-only 대상은 `src/`, `tests/`만 허용한다.
- 최소 제외 목록:

```text
backup/
inputs/
outputs/
studio-work/
.git/
.env*
*.mp4
*.mkv
*.wav
*.mp3
```

- 자동 설치 명령으로 에이전트 규칙·훅을 수정하지 않는다.
- MCP는 파일럿 세션에서만 활성화한다.
- 그래프 결과는 초기에는 Git에 커밋하지 않는다.
- 생성 인덱스와 캐시는 저장소 밖의 승인된 임시 경로에 둔다.
- 예상하지 못한 네트워크 전송이 발견되면 중단한다.
- 문서·미디어 의미 분석에 외부 모델을 사용하지 않는 code-only 실험을 우선한다.
- `docs/` 의미 분석은 1차 결과와 별개로 사용자 승인을 받고, 로컬 모델 또는 명시적으로
  승인된 원격 모델·비용 상한으로만 수행한다.

## B-5. 비교 방법

설치 후 난이도가 같은 다른 질문 세트를 사용해 학습 효과를 분리한다.

측정:

- 정답률과 근거 라인 정확도
- 답을 찾는 시간
- 컨텍스트 또는 토큰
- 잘못된 연결 수
- 그래프 최신성
- 인덱싱 시간
- 설정·장애 대응 시간
- 외부 전송
- 월 유지보수 예상 시간

기준 질문과 실험 질문 모두 사전 채점표로 평가한다. 알려진 코드 한 곳을 변경한 격리
fixture에서 stale graph가 탐지되는지, 재색인 후 정답이 갱신되는지도 시험한다. 도입
검토표에는 초기 설치·인덱싱 비용, 월 API·저장 비용, 구축 시간, 월 유지시간,
무료·오픈소스 대안, 완전 제거 예상 시간을 따로 기록한다.

## B-6. 유지 기준

- 정답률이 기준보다 낮아지지 않음
- 탐색 시간 또는 컨텍스트 20% 이상 감소
- 잘못된 주요 영향 관계 0건
- 변경 후 그래프 최신성을 검증할 수 있음
- stale graph를 탐지하고 재색인한 뒤 기준 질문이 갱신됨
- 민감정보 외부 전송 0건
- 월 유지보수 예상 30분 이하
- API 비용이 사전 상한 이하

하나라도 실패하면 MCP 설정 비활성화, 고정 패키지와 생성 인덱스 제거, 파일럿 전후
Git diff 확인, Graphify 없이 핵심 테스트 재실행 순서로 롤백한다.

## 4. 대안 재평가 조건

- GitNexus: 상업 라이선스 검토 전 금지
- DVC: 다중 PC에서 정확한 대용량 데이터 재현 요구가 생길 때
- Git LFS: 반복 생성 영상 저장에는 사용하지 않음
- Sourcegraph: 여러 저장소와 팀 검색이 실측 요구가 될 때
- PostgreSQL·분산 관측: SQLite 단일 writer 한계가 실제 지표로 확인될 때

## 5. 단계 완료 기준

- Obsidian·Graphify 없이 핵심 워크플로가 정상 작동
- 선택한 각 도구에 독립 전후 측정이 존재
- 도입 도구가 상태 정본·승인·검증을 침범하지 않음
- 비용과 유지 시간이 기록됨
- 기준 미달 도구는 완전히 롤백됨
- 기준 충족 도구만 사용자가 유지 승인함
- `backup/`과 원본 미디어 변경 0건

## 6. 중단 조건

- 자동 설치가 공용 에이전트 규칙이나 훅을 수정함
- 민감정보의 원격 전송이 발생함
- 도구 제거 시 핵심 실행·검증이 깨짐
- 파일럿 효과를 측정할 기준선이 없음
- 비용 상한이나 사용자 승인이 없음

## 7. 롤백

1. 평가 대상 도구의 실행과 네트워크 접근을 먼저 비활성화한다.
2. 파일럿 전 공용 설정 snapshot과 현재 diff를 비교한다.
3. Obsidian은 조정 에이전트가 승인된 `.obsidian` 설정만 제거하고 Markdown·MkDocs를
   보존한다.
4. Graphify는 MCP 등록, 고정 의존성, 저장소 밖 인덱스·캐시를 제거한다. 공용
   `pyproject.toml`, `uv.lock`, `.gitignore` 복구는 조정 에이전트만 수행한다.
5. 두 도구가 없는 상태에서 `workflow check --scope full`, MkDocs 엄격 빌드와 대표
   탐색 기준 질문을 다시 실행한다.
6. 제거 후 핵심 실행이 깨지면 Stage 08 변경을 완료로 처리하지 않고 Stage 07의
   `stabilized` 지점으로 복귀한다.
