## 1. 결과 요약

`F` 명령 3의 문서 기반을 구축했다. 활성 프로젝트에는 이제 다음 네 종류의 입구가 있다.

1. 에이전트가 매 세션 처음 읽는 시작 라우터와 상시 규칙
2. 사용자에게 현재 상태와 사용 방법을 설명하는 한국어 입구
3. 작업 절차·지식·검색·유지보수 책임을 분리한 영어 에이전트 문서
4. 채팅 기억 없이 다음 세션이 재개할 수 있는 단일 현재 인수인계

`F` `PROJECT_RULES.md`에는 모든 작업에 항상 적용되는 규칙만 넣었다. 작업 순서, 지식 데이터 모델, 검색 설계, 검토 절차와 현재 상태는 별도 문서가 소유한다.

`F` 명령 4의 데이터·검색 구현 경로는 만들지 않았다. 문서에서 미래 계약과 현재 구현 상태를 명시적으로 구분한다.

## 3. 상시 규칙의 범위

[`PROJECT_RULES.md`](../../PROJECT_RULES.md)에 포함한 상시 범주는 다음과 같다.

- 사용자 지시, 프로젝트 규칙, 승인 결정의 권위 순서
- 단계 종료 보고와 다음 단계 승인 대기
- `backup/` 읽기 전용과 활성 런타임 의존 금지
- 사용자가 정확히 지정하지 않은 `inputs/`, `outputs/`의 열거·검색·색인 금지
- 한국어 사용자 문서와 영어 에이전트 문서의 언어 경계
- 사실·역사 주장·추론·제안·승인 결정과 출처의 구분
- 직접 문서 라우팅 우선과 파생 인덱스의 비정본 원칙
- 실제 검증 수준의 명시와 사용자 승인 상태의 과장 금지
- 외부 게시·커밋·푸시는 명시적 요청이 있을 때만 수행

다음 내용은 `PROJECT_RULES.md`에서 분리했다.

- 세부 작업 절차: `WORKFLOW.md`
- 문서 역할과 권위: `DOCUMENT_MAP.md`

- 검색·컨텍스트 조립: `CONTEXT_RETRIEVAL.md`

## 5. 인수인계 구성

`handoff-manager` 작업 계약을 적용해 [`SESSION_HANDOFF.md`](../../SESSION_HANDOFF.md)를 다음 원칙으로 만들었다.

- 현재 상태의 단일 정본만 유지
- 완료 범위와 명령 4 미구현 범위 분리
- 검증 수준과 Git 상태 명시
- 실패 원인·해결·연속 횟수·다음 조건을 표로 보존
- 활성 차단 조건과 첫 미착수 작업 명시
- 일반 규칙은 복사하지 않고 권위 문서에 연결
- 다음 세션 시작 프롬프트에 승인 확인과 단계 경계를 포함

기존 `SESSION_HANDOFF.md`가 없었고 `backup/`은 수정 금지이며 상시 규칙이 임시 중복 백업을 금지하므로 별도 `.bak` 파일은 만들지 않았다.

이 추론은 문서 구조에 대한 판단이며 실제 장기 운영 효율을 측정한 결과는 아니다.

## 7. 검증 결과

최종 검증은 이 보고서와 인수인계를 포함한 모든 활성 기반 문서를 다시 읽어 수행했다. 확인 항목은 다음과 같다.

- UTF-8 엄격 디코딩과 NUL 문자 부재
- 후행 공백과 Markdown fenced block 짝
- 문서별 필수 메타데이터
- 한국어 사용자 문서의 언어 경계
- 모든 로컬 Markdown 링크의 실제 경로
- 기존 보고서의 승인 상태
- 명령 4 전용 경로의 미생성
- Git 상태와 `backup/` 무변경

검증 결과:

- 활성 기반 문서 13개, 140,991바이트를 검사했다.
- UTF-8, NUL, 후행 공백, fenced block, 필수 메타데이터, 언어 선언, 필수 규칙·인수인계 절, 보고서 승인 상태 검사에서 문제 0건이었다.
- Markdown 링크 148개를 확인했다. 로컬 링크 128개는 모두 실제 경로로 해석됐고 끊어진 링크가 없었다. 외부 링크 20개는 직접 URL 형식과 집계만 확인했으며 이번 단계에서 네트워크 재검증하지 않았다.
- 명령 4 전용 경로와 중복 현재 상태 문서가 존재하지 않음을 확인했다.
- Git 상태에서 새 활성 기반 파일은 미추적 상태이며, 커밋·게시하지 않았다.
- `git status --short -- backup` 결과가 비어 있어 `backup/` 무변경을 확인했다.

검증 수준은 **구조 검증**이다. 실제 지식 기록·검색 애플리케이션은 아직 없으므로 자동 기능 테스트, 애플리케이션 검증, 사용자 내용 승인을 통과했다고 주장하지 않는다.

다음은 설계 계약만 존재하며 현재 기능이 아니다.

- 작업별 context request·package
- 결과 write-back과 stale review 자동화
- Obsidian, 임베딩, vector store, Neo4j

## 9. 다음 승인 단계

이 보고서가 승인되면 명령 4 전체를 한 번에 만들지 않고 **Stage 4-A: 기록 유형·스키마·검증 기반**만 구현한다.
