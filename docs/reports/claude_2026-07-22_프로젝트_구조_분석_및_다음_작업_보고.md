# 프로젝트 구조 분석 및 다음 작업 보고

- 목적: 현재 프로젝트의 문서·구조·상태를 분석해 다음에 수행해야 할 작업과 그 승인 경계를 사용자에게 보고한다.
- 사용 시점: 새 세션에서 "이제 무슨 작업을 해야 하는가"를 판단하거나, 다음 단계 승인을 결정할 때 사용한다.
- 작성·수정 주체: Claude 세션이 작성한 시점 증거. 정책 권위는 없다.
- 언어: 한국어.
- 저장 위치와 연결 관계: `docs/reports/`. [PROJECT_RULES.md](../../PROJECT_RULES.md), [SESSION_HANDOFF.md](../../SESSION_HANDOFF.md), [DOCUMENT_MAP.md](../agent/DOCUMENT_MAP.md)를 근거로 한다.

## 1. 결론 먼저

**다음 작업은 L0~L8 영상 제작 로드맵의 복귀점(resume gate) 재확정이다.** 구현 작업이 아니라 감사(audit) 작업이다.

R 지식·컨텍스트 시스템은 완료됐고(86.8/100), F-1~F-4 운영 하드닝도 완료됐다. 지금 남은 유일한 미해결 게이트는 "L 로드맵의 어디까지 끝났고 어디부터 시작해야 하는지"가 현재 checkpoint에 복원되지 않았다는 점이다. 이 감사를 건너뛰고 L5를 구현하면 선행 조건(L2/L4)을 누락할 위험이 있다.

## 2. 분석 방법과 경계

- 읽은 문서: `PROJECT_RULES.md`, `AGENTS.md`, `README.md`, `SESSION_HANDOFF.md`, `docs/agent/DOCUMENT_MAP.md`, `docs/reports/` 21개 보고서 목록과 L 관련 본문.
- 구조 조사: 활성 루트의 디렉터리·파일 집계, Git 로그 20건, 작업 트리 상태.
- 준수한 경계: `backup/`은 열거만 하고 내용을 활성 분석에 사용하지 않았다. `inputs/`, `outputs/`는 접근하지 않았다(현재 활성 루트에 존재하지 않음). 커밋·푸시·외부 변경 없음.

### 3.2 아키텍처 요약

3계층 구조다.

1. **거버넌스 계층** — `PROJECT_RULES.md`(항상) → `AGENTS.md`(라우터) → `DOCUMENT_MAP.md`(권위 등록부) → `rules/`(조건부, resolver 선택). 컨텍스트를 예산으로 다루며 작업별 최소 문서만 로드하는 설계다.
2. **지식·컨텍스트 계층** — `schemas/`가 계약을 정의하고, `knowledge/`가 JSONL 저장소, `catalog/`가 색인, `tools/context/context_system.py`가 resolver/writer/validator를 모두 담당한다.
3. **검증 계층** — `tests/`의 35개 회귀 테스트, `evaluation/`의 고정 평가셋(R-4 8/8, R-5 9/9), 통합 validator(`ok=true`, 오류 0, 고아 0).

### 3.3 강점

- 문서마다 목적·사용 시점·소유자·언어·위치가 일관되게 기재돼 있어 권위 판단이 명확하다.
- 실패 원장(failure ledger)이 실제로 유지되고 있고, 재발 방지가 규칙·회귀로 연결된다.
- 보호 경로·백업 불변성이 규칙과 코드 양쪽에서 강제된다.

## 4. 현재 상태

- **완료**: R0~R-5 지식·컨텍스트 시스템, F-1~F-4 운영 하드닝 3회 반복.
- **검증**: 35/35 테스트 통과(Windows, Python 3.12.13), 통합 validator `ok=true`, 활성 파일 205, 단위 3,724.
- **점수**: R 단계 86.8/100(±2). Codex 87.2와 Claude 84.7을 조정한 값.
- **미완료**: L0~L8 영상 제작 로드맵. 백업 문서는 L0~L4와 L3.1~L3.3 완료를 주장하지만, 해당 구현은 모두 `backup/`으로 이동해 활성 기능이 아니다.
- **Git**: 최신 커밋 `b35cacc`. 작업 트리 clean.

## 5. 다음 작업 (권고)

### 5.1 1순위 — L 복귀점 재확정 감사

목표: 다음 네 가지를 하나의 현재 checkpoint로 복원한다.

1. 승인된 L0~L8 로드맵의 각 layer 정의
2. 실제로 완료된 layer와 그 증거
3. 첫 미착수 layer
4. 그 layer가 요구하는 선행 산출물(특히 L5의 L2/L4 의존성)이 현재 R 재구축에서 소실됐는지

**주의점**: 백업 문서의 "L0~L4 완료" 주장은 근거로 쓸 수 없다. 활성 루트 기준으로 모든 상태는 `not implemented`에서 시작해야 한다는 것이 기존 분석의 결론이다. 따라서 이 감사는 "무엇이 완료됐나"가 아니라 **"승인된 로드맵이 무엇이었나, 그리고 현재 활성 기반에서 무엇을 다시 만들어야 하나"**를 확정하는 작업이다.

산출물: 감사 보고서 1건 + `SESSION_HANDOFF.md` 갱신. 구현은 없음.

### 5.2 2순위 — gap이 확인된 뒤에만

선행 계약이 소실됐다면, 다음 layer 기능을 앞당기지 말고 필요한 선행 계약만 현재 구조에 맞춰 복구한 뒤 L5 시작 게이트를 제시한다. **별도 승인 필요.**

### 5.3 보류 항목 (현재 착수 금지)

- L5 및 임의 L layer 구현
- `context_system.py` 모듈 분리
- R-4 평가셋 확대, FTS/벡터/그래프/Obsidian 도입
- 커밋·푸시·배포·게시·외부 시스템 변경
- 보호 데이터 접근
