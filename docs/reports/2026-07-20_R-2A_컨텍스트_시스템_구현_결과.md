# R-2A 컨텍스트 시스템 구현 결과

- 작성일: 2026-07-20
- 목적: 승인된 R-2A 범위에서 기존 규칙과 모든 project-governed file을 task-scoped read/write 폐루프에 편입한 구현·검증 결과를 보존한다.
- 사용 시점: R-2A 산출물과 완료 게이트를 감사하거나 R-2B 승인 여부를 판단할 때 읽는다.
- 작성·수정 주체: 프로젝트 에이전트가 실제 catalog, fixture, test, event 증거로 작성하며 다음 단계 착수는 사용자가 승인한다.
- 언어: 한국어.
- 저장 위치: `docs/reports/2026-07-20_R-2A_컨텍스트_시스템_구현_결과.md`.
- 연결 관계: [프로젝트 규칙](../../PROJECT_RULES.md), [작업 절차](../agent/WORKFLOW.md), [문서 지도](../agent/DOCUMENT_MAP.md), [승인된 R-1.1 설계](2026-07-20_R-1.1_지식_시스템_설계_보정.md), [현재 핸드오프](../../SESSION_HANDOFF.md)에 연결된다.
- 권위·보존 상태: R-2A의 시점 증거이며 정책 권위가 아니다. `retained-evidence`로 정확한 단계 감사 때만 읽는다.

## 1. 결과

R-2A thin slice를 완료했다. 기존 29개 규칙은 검증된 `8개 boot kernel + 7개 Markdown pack의 21개 conditional rule`로 이동했고, 모든 활성 파일은 universal catalog와 결정적 artifact unit에 등록된다. exact target와 predicate 기반 resolver, before-hash를 요구하는 Markdown writer, append-only event chain이 실제 프로젝트 데이터로 동작한다.

검증 수준은 `structural + automated`다. 응용 프로그램 검증이나 사용자 내용 승인을 의미하지 않는다.

| 구성 | 구현 결과 | 정본 또는 상태 |
|---|---|---|
| 규칙 | 커널 8개, 조건부 규칙 21개, pack 7개 | `PROJECT_RULES.md`, `rules/*.md` |
| 파일 등록 | 활성 파일 48개, planned 0개, orphan 0개 | `catalog/files.jsonl` |

초기 tool/catalog 생성은 `event.manual-bootstrap.0001`로 수동 bootstrap 경계를 기록했다. 이 보고서와 핸드오프 쓰기는 생성된 work context와 write contract를 사용했다.

## 3. 실제 fixture

### 3.1 read-only fixture

`context/requests/r2a_read.json`을 resolver에 넣어 `WORKFLOW.md`의 `5. Validate` heading unit 하나를 exact target으로 선택했다. 결과 context는 kernel 8개와 predicate가 일치한 retrieval 규칙 4개만 포함하고, 전체 R-1.1 보고서와 무관한 파일·규칙은 제외 이유와 함께 배제했다.

### 3.2 contract 거부 fixture

write contract가 없는 read-only context로 writer를 호출했을 때 `write rejected: work context has no write contract`로 종료됐고 대상 변경은 없었다. 같은 동작을 자동 테스트에서도 임시 target의 hash와 내용 불변으로 확인했다.

### 3.3 live write fixture

`context/requests/r2a_write.json`에서 생성한 write contract가 이 보고서 생성, 문서 지도 활성화, `SESSION_HANDOFF.md` 갱신을 정확한 target과 before hash로 허용했다. writer는 세 Markdown 변경 뒤 file catalog, unit projection, event evidence를 갱신했다.

## 4. 검증 결과

- 사전 매핑: baseline 19개 파일 일치, source 29개·stable rule ID 29개 모두 유일, `8 + 21 = 29` 일치.
- 자동 테스트: parser, protected pre-filter, exact read context, contract 거부, 통합 구조 검증을 포함한 6개 테스트 통과.
- 통합 구조 검증: 활성 파일 48개, planned 0개, orphan 0개, kernel 8개, conditional 21개, hash·event chain·local link·unit 재생성 일치.
- 보호 경계: `backup/`, `inputs/`, `outputs/`, `.git/`, `.agents/`, `.codex/`는 탐색 전에 차단되며 global catalog에 내부 항목이 없다.
- 저장소 검사: UTF-8·NUL·JSON/JSONL·Markdown link·`git diff --check`를 최종 통합 단계에서 검사했다.
- 과장 방지: application-validated 및 user-approved 상태는 아니다.
