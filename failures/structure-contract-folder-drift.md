# 구현 폴더와 정보 구조 계약의 드리프트

- 상태: 해결·회귀 검증 완료
- 최초 확인: 2026-07-23 Stage 03 최종 문서 일관성 검토
- 마지막 검증: 2026-07-23 문서 기반 데이터 규칙 보정
- 적용 범위: 새 최상위·하위 구현 폴더, README 구조 표, 정보 구조 정본, 단계 종료 문서·코드 검증

## 증상

Stage 02~03에서 `schemas/`, `src/`, `tests/`가 실제로 생기고 `data/`가 승인 저장 루트가 됐지만, 사용자 README에는 일부만 추가되고 정보·문서 책임 정본의 위치 표에는 네 책임이 모두 빠져 있었다.

## 확인된 원인

새 파일 링크와 구현 계약은 갱신했지만 최상위 위치의 책임·배치 금지를 소유하는 `INFORMATION_ARCHITECTURE.md`를 단계 종료 체크리스트에 함께 대조하지 않았다. Stage 08 maintenance verify도 당시 유일한 구현 패키지였던 `src/file_data/*.py`만 AST 대상으로 고정해 이후 별도 도메인 패키지가 생길 수 있는 구조 계약을 반영하지 못했다.

## 실패·해결 이력

| 시점·문맥 | 시도·결과 | 최고 연속 횟수 | 해결·검증 |
|---|---|---:|---|
| Stage 03 최종 일관성 검토 | 구현 폴더 3개와 예정 데이터 루트 1개의 정본 책임 누락 | 1 | 정보 구조 정본과 README에 네 위치의 책임·금지 경계를 추가하고 전체 문서 지도·링크 재검증 |
| Stage 09 도메인 adapter 자체 검토 | 새 `src/youtube_domain`은 정보 구조에 연결했지만 `maintenance-verify`가 `src/file_data`만 AST 검사해 도메인 Python을 검증 대상에서 누락 | 별도 게이트 1 | AST 대상과 지표를 `src/**/*.py`로 일반화하고 별도 도메인 패키지의 실제 문법 오류를 탐지하는 회귀 추가 |
| 문서 기반 데이터 규칙 보정 | `rules/document-work.md` 제목과 책임을 변경한 뒤 생성 inventory를 먼저 갱신하지 않아 verify가 11 bytes 불일치를 보고 | 1 | 문서 정본을 먼저 확정하고 `maintenance-inventory --write`로 파생 inventory를 재생성한 뒤 verify 오류 0 확인 |

## 해결과 검증

- `schemas/`, `src/`, `tests/`, `data/`의 각 소유 책임과 배치 금지를 정보 구조 정본에 기록했다.
- README 기본 구조에도 승인 데이터 루트와 CLI 초기화 전 미생성 조건을 표시했다.
- 기존 `inputs/`, `outputs/` 보호 데이터와 프레임워크 `data/`를 명확히 구분했다.
- `maintenance-verify`가 공통 구현과 승인된 도메인 adapter의 모든 Python 파일을 같은 AST 기준으로 검사하도록 보정했다.
- 문서 제목·책임을 바꾼 뒤 생성 inventory를 문서 정본에서 다시 만들고 bytes 일치와 전체 verify 성공을 확인했다.

## 재사용 규칙

- 새 최상위 폴더를 처음 만들거나 계약할 때 README만이 아니라 정보 구조 위치 표도 함께 검토한다.
- 폴더 존재뿐 아니라 소유 책임과 배치 금지를 둘 다 기록한다.
- 단계 종료 문서 검증에서 실제 최상위 활성 경로와 정보 구조 정본 표를 대조한다.
- 구현 검증은 현재 존재하는 패키지명 목록을 고정하지 말고 승인 구현 루트 전체를 검사하되 보호·역사 경계는 먼저 제외한다.
- 문서 제목·경로·책임을 변경하면 문서 정본을 먼저 확정하고 생성 inventory를 재생성한 뒤 전체 verify를 실행한다.
