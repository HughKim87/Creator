# 오래된 핸드오프 상태와 죽은 경로

- 상태: 해결·방지 조건 적용
- 최초 확인: Stage 00 정리에서 재확인
- 마지막 검증: 2026-07-23
- 적용 범위: 세션 재개, 현재 상태, 다음 행동, 문서 링크

## 증상

핸드오프에 이미 끝난 행동, 오래된 동적 Git 상태, 존재하지 않는 경로가 남아 새 세션이 잘못된 지점에서 재개할 위험이 생겼다.

## 확인된 원인

현재 상태와 역사 서사를 한 문서에 계속 누적했고, 다른 문서에도 상태를 복제해 어느 값이 최신인지 판단하기 어려웠다.

## 실패·해결 이력

| 시점·문맥 | 시도·결과 | 최고 연속 횟수 | 해결·검증 |
|---|---|---:|---|
| Stage 00 핸드오프 정리 | 오래된 행동과 죽은 경로가 활성 재개 정보에 잔존 | 미상 | 핸드오프를 현재 상태 정본 하나로 축약하고 동적 Git 값은 실행 시 조회 |

## 해결과 검증

- `SESSION_HANDOFF.md`가 현재 단계, 차단, 첫 다음 행동의 유일한 소유자가 됐다.
- README와 마스터 계획은 현재 값을 복제하지 않고 핸드오프를 연결한다.
- 활성 Markdown 링크와 참조 경로 검사를 수행했다.

## 재사용 규칙

- 중요한 상태가 바뀌면 같은 변경에서 핸드오프와 첫 다음 행동을 갱신한다.
- Git 브랜치·ahead 수처럼 다시 조회할 수 있는 값은 장기 상태로 저장하지 않는다.
- 해결된 실패의 장문 역사는 핸드오프에 누적하지 않고 `failures/`로 이동한다.
