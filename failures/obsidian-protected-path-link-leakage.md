# Obsidian 보호 경로 링크 노출

- 상태: 해결·회귀 검증 완료
- 최초 확인: 2026-07-23 Stage 01.5 보호 경계 검증
- 마지막 검증: 2026-07-23
- 적용 범위: Obsidian 볼트, 활성 Markdown, `backup/`·`inputs/`·`outputs/` 보호 경계

## 증상

Obsidian 제외 필터는 보호 폴더를 색인하지 않도록 설정됐지만, 활성 시점 보고서에 `backup/` 내부 파일로 향하는 클릭 가능한 Markdown 링크 26개가 남아 있었다.

## 확인된 원인

폴더 제외 설정과 문서 연결 그래프를 별개로 검증하지 않았다. 제외 폴더의 파일 본문은 읽히지 않더라도 활성 문서의 링크가 보호 경로 이름과 노드를 검토 화면에 노출할 수 있었다.

## 실패·해결 이력

| 시점·문맥 | 시도·결과 | 최고 연속 횟수 | 해결·검증 |
|---|---|---:|---|
| Stage 01.5 전체 구조 게이트 재개 | 기존 역추론 보고서의 첫 `backup/` 링크에서 보호 대상 검사 중단 | 1 | 활성 Markdown 전체에서 보호 경로 링크 26개를 찾아 비링크 코드 출처 표기로 변경 |

## 해결과 검증

- 보고서의 역사 출처명과 프로젝트 상대 경로는 보존했다.
- 클릭 가능한 링크만 코드 경로 표기로 바꿔 보고서의 시점 증거 내용은 유지했다.
- 활성 Markdown 전체의 링크를 다시 해석해 `backup/`, `inputs/`, `outputs/`로 향하는 링크가 0개임을 확인했다.
- `.obsidian/app.json`의 다섯 제외 필터와 문서 링크 검사를 서로 다른 단언으로 유지했다.

## 재사용 규칙

- 보호 경계 검증은 앱 제외 설정, 활성 문서 링크, 전체 지도 수록 여부를 각각 확인한다.
- 역사 출처를 남겨야 하면 보호 파일을 클릭 가능한 링크로 만들지 말고 비링크 코드 경로로 표시한다.
- 보호 폴더의 내용을 읽지 않고도 활성 문서가 그 경로를 연결하는지는 검사할 수 있다.
